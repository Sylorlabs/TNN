# TNN Next Run Plan — Entity Mystery, Innate System Fluency, and Substrate Tournament

**Status:** Proposed next execution generation. Not executed yet.
**Implementation authority:** Native Zag v2 only for promotable TNN mechanisms. External evaluators may generate data, score, package, and audit but cannot supply cognition.
**Canonical parent:** Verified R27 accepted brain remains untouched until a native candidate passes promotion gates.

## Scientific thesis

The next run must stop treating "training" and "architecture" as one blended knob. It will isolate at least four independent axes:

1. **Training/curriculum** — amount, diversity, ordering, contrasts, teacher policy, withdrawal.
2. **Computational substrate / architecture** — graph, non-graph, hybrid, entity/world representation, routing.
3. **Innate system fluency** — whether TNN is born knowing how to invoke its own generic functions.
4. **Memory/search policy** — what it stores, retrieves, explores, mutates, and reuses from prior experiments.

The run is centered on the unresolved persistent-entity problem because identity continuity is upstream of naming, affordance, sibling teaching, and integrated world understanding.

# Phase 1 — Factorial experimental framework: training != architecture

Create a preregistered experiment matrix that changes one axis at a time and also tests selected interactions.

## 1A. Training axis

For each candidate substrate, test:
- passive random experience;
- balanced diverse experience;
- hardcoded adaptive Master teaching;
- learned TNN teacher where available;
- contrastive/minimal-pair curriculum;
- active self-selected observations;
- teacher withdrawal and independent exploration.

Dose checkpoints should extend as needed rather than stop at a small fixed schedule, e.g.:
`1,2,4,8,16,32,64,128,256,512,1024,...`

Record marginal gain per additional exposure. A training curve still improving is not an architecture plateau.

## 1B. Architecture axis

Hold the same training stream fixed across architectures. No candidate receives easier examples or more teacher help.

## 1C. Innate-fluency axis

Compare:
- `NO_INNATE_FLUENCY`: TNN must learn how to invoke its generic internal functions from consequences.
- `MASTER_TAUGHT_FLUENCY`: Master explicitly teaches how to invoke generic functions, then withdraws.
- `INNATE_SYSTEM_FLUENCY`: birth-level generic knowledge of how to call/compose TNN's own facilities.

Innate fluency may encode operation semantics and schemas only. It cannot encode task-specific choices or answers.

## 1D. Memory/search axis

Compare the same architecture with:
- learned memory/search policy;
- simple fixed controls;
- random exploration control;
- population/evolutionary search;
- learned predictive search.

Use factorial analysis to detect interactions rather than attributing everything to architecture.

# Phase 2 — Innate System Fluency experiment

Implement a protected core `SYSTEM_FUNCTION_INTERFACE` in native Zag.

TNN may be born knowing generic operations such as:
- create/clone/mutate/delete a non-core PAM;
- launch/terminate/allocate a fiber;
- read causal traces;
- allocate/retrieve/promote/archive/evict memory;
- create a shadow candidate;
- run internal development tests;
- compare candidates;
- request an additional observation;
- query another sibling/Master;
- serialize/reload state;
- rollback a non-core candidate.

The interface provides **how to operate the machine**, analogous to an instruction set, not what to think.

### Key tests

Measure whether innate fluency improves:
- time-to-first-useful-PAM;
- architecture-search regret;
- successful rollback rate;
- memory allocation utility;
- number of wasted function invocations;
- debugging/failure attribution;
- entity-learning speed;
- transfer to a new hidden problem that uses the same generic facilities differently.

### Falsifier

If innate fluency makes TNN rigid, causes premature PAM creation, overuses fibers/memory, or hurts hidden transfer, it is not automatically retained. Compare against teacher-taught and learned-from-scratch arms.

# Phase 3 — Solve the persistent-entity mystery scientifically

Do not jump to a new entity architecture until the failure chain is mapped.

## 3A. Fair known-entity protocol

Every target entity must be genuinely known before test. Hold out only transformations/contexts, never the entity identity itself for a changed-view claim.

Training experience includes several views of each entity. Hidden tests include:
- unseen viewpoint/rotation;
- translation and scale;
- illumination;
- partial occlusion;
- full temporary disappearance;
- reappearance after long distractor sequences;
- near-identical distractors;
- true identity switches;
- two objects crossing;
- background substitution;
- compound corruption;
- active reinspection opportunities.

Evaluator IDs never enter learner state.

## 3B. Stepwise training diagnosis

For each entity condition, log curves after every dose checkpoint.

Classify each residual failure as:
- representation destroyed at core;
- non-core PAM failed to normalize;
- entity binding failed;
- retrieval/memory failed;
- persistence too weak;
- persistence too sticky;
- ambiguity not represented;
- active observation chosen poorly;
- teacher curriculum insufficient;
- search/self-revision failed.

## 3C. Information microscope

At each processing boundary measure same-entity versus different-entity separability and trace exact failure ancestry:

`raw sensor -> protected core -> non-core PAMs -> route -> candidate identity hypotheses -> memory retrieval -> temporal continuity -> active observation -> final entity belief`

The aim is not merely to improve score but to explain every persistent failure family.

# Phase 4 — Entity architecture tournament: graph vs non-graph

Use identical training streams and hidden worlds.

Candidate families:

## G — Graph object-file system
Persistent entities as nodes plus typed/evidence-weighted relations.

## S — Slot/object-file state machine
A bounded/unbounded pool of persistent entity records with split/merge/reassignment, without requiring a general graph.

## H — Hypothesis population / particle-like entity memory
Maintain multiple competing identity hypotheses with weights; update by evidence and temporal continuity; split/merge only when warranted.

## F — Continuous entity field
Distributed recurrent field where identity is an attractor/dynamical state rather than a node/slot.

## A — Associative episodic set
Identity emerges from retrieval over multiple exact/structured memories, with no persistent graph object as primary representation.

## P — Program/executable-state representation
TNN-generated small executable state processes predict how an entity should transform/reappear.

## B — Blackboard/workspace system
Independent sensory/memory/affordance processes post evidence into a shared workspace; persistent identity emerges by competition/consensus.

## HYBRID
Permit TNN to combine the strongest mechanisms rather than forcing a single representational ideology.

### Promotion criterion

Do not select on entity accuracy alone. Score downstream:
- changed-view identity;
- occlusion/permanence;
- true-switch detection;
- naming;
- affordance prediction;
- delayed memory;
- sibling reference transfer;
- compute/storage;
- traceability;
- historical regressions.

The winner can be non-graph or hybrid.

# Phase 5 — Training quality tournament on the same entity substrate

Once a candidate substrate exists, freeze it and push training seriously before modifying it again.

Compare:
1. more random exposure;
2. diverse stratified exposure;
3. Master-selected high-information examples;
4. counterexamples/near-neighbor contrasts;
5. active self-selected reinspection;
6. replay/retrieval selected by TNN;
7. sibling-supplied evidence;
8. curriculum mixtures.

For every plateau, determine whether it is a real plateau or merely teacher/search failure.

A candidate architecture should not be rejected because it was trained badly.

# Phase 6 — Replace "learned PAM search" with a real learning problem

Random search stays as a control, never the intended endpoint.

The prior whole-graph evolutionary search beat random sampling, which proves that population-level structure matters. The next task is to make the architecture-search learner actually learn from its history.

## 6A. Architecture experiment memory

Store each experiment as:
- telemetry before proposal;
- generated architecture/program;
- training history;
- hidden-development outcomes;
- ablations;
- resource cost;
- regressions;
- failure reasons;
- what changed from parent;
- eventual promotion/deletion.

## 6B. Compare search learners

Against random and plain evolution:
- novelty/quality-diversity population search;
- contextual bandit over structural motifs;
- learned surrogate model predicting capability gains;
- program induction over executable PAM structures;
- mutation policy learned from prior successful deltas;
- compositional building-block transfer;
- hybrid evolution + learned proposal model.

## 6C. Critical rule

If a learned method loses to random, diagnose the learner. Do not conclude randomness is intrinsically better until multiple competent learning formulations fail.

# Phase 7 — Beyond PAM graphs: self-designed executable cognition

Generalize the Foundry into an `Architecture Foundry`, where TNN can create non-core computational structures from generic protected primitives.

Candidate structure types may include:
- graphs;
- local recurrent arrays;
- state machines;
- event-driven processes;
- associative banks;
- temporal programs;
- workspace agents/processes without separate identities;
- cellular fields;
- hybrid compositions.

TNN should be able to instantiate, shadow-test, mutate, compose, route, suspend, and delete these structures itself.

The protected core supplies primitives, resource isolation, trace integrity, and safe execution—not intelligence-specific topology.

---

# Phase 8 — Reintegrate world modeling after identity improves

Only after identity/permanence is strong enough:

1. bind entity records to observed actions;
2. learn `entity + action + context -> consequence`;
3. discover recurring affordance structure;
4. bind arbitrary spoken/text names into the same entity representation;
5. test references after delay/occlusion/noise;
6. teach independent siblings using the same grounded entity model.

Do not let naming or category classifiers mask weak identity.

---

# Phase 9 — Master as adaptive bootstrap, not permanent crutch

Use the prior dose-curve result explicitly:
- adaptive Master is strongest early;
- later diverse experience can match/overtake permanent Master control.

Therefore test a learned withdrawal schedule driven by competence/uncertainty rather than hardcoded age.

Master can teach:
- system-function use;
- diagnostic experimentation;
- grounded concepts;
- how to seek contrasts;
- teach-back and verification.

Master knowledge is still not learner knowledge.

---

# Phase 10 — Hard evaluation and near-perfect qualification

Use development, validation, confirmation, and sealed qualification generations.

Report:
- numerator/denominator;
- per-seed distribution;
- error taxonomy;
- learning curve;
- post-100 or post-99 challenge results;
- confidence intervals where useful.

Status vocabulary:
- `PARTIAL`
- `STRONG`
- `ROBUST_NEAR_SOLVED` (e.g. near-perfect on large hostile batteries with a small interpretable residual)
- `SOLVED_BOUNDED` (100% on sealed bounded battery plus successful harder follow-up)

Do not weaken a battery to change `ROBUST_NEAR_SOLVED` into `SOLVED_BOUNDED`.

# Phase 11 — Integrated continuous-life qualification

Run one uninterrupted brain lifetime containing:
- raw sensory learning;
- learner-chosen memory;
- known entities across views;
- temporary disappearance;
- true switches/distractors;
- one-shot names;
- action/consequence learning;
- long unrelated memory pressure;
- independent sibling teaching;
- misleading testimony with provenance;
- teacher withdrawal;
- TNN-generated non-core architecture changes;
- fresh-process save/reload;
- historical regressions.

Measure both component metrics and all-or-nothing scenario success.

A 99% component score can be excellent while the one integrated failure is still investigated honestly.

## Expected decision value

This run should tell us, with much less ambiguity:

- whether persistent identity is mostly a training failure, representation failure, or temporal architecture failure;
- whether TNN should be born fluent in its own generic machinery;
- whether learned architecture search can decisively outperform random/evolution once credit is represented correctly;
- whether graph structure is useful, limiting, or merely one component of a better hybrid;
- and which architecture produces the highest genuine integrated capability rather than the highest narrow benchmark score.
