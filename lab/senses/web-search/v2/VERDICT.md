## Verdict (prereg §6 as amended by A1)

**Evidence favors READ-AND-EDITABLE as safe AND useful, with R-CORR as the
required install rule.** R-CORR installed every true claim (M7–M8), withheld
every single-source falsehood (M1–M4), held the 1v1 line (M9–M10), respected
installed belief (M11), and the only false installs are the pre-registered
unanimous-spoof residual (M5–M6) that no corroboration rule without trust
tiers can defeat. READ-ONLY remains available for trainers who want zero
install risk (KB-MODE-RO: 0 install ops, mechanically enforced).
**R-CONTRA is confirmed unsafe as a deployment rule** — it installs
single-source falsehoods and first-seen 1v1 claims. It stays a negative
control, never a deployment option.

The trainer's forced choice stands regardless: no silent default either way.

## Documented substitutions (prereg §2 allows; not hidden)

1. **MTN re-recorded with 20 results.** 6 results could not supply the 2v1 /
   dissent structure; 20 gave a natural 5×Everest / 3×Mauna-Kea / 1×Denali
   split. Same query, more live data — no manufacturing.
2. **B-leg "single fake"** (prereg §2 situation 1) cannot be honestly derived
   from live results — the live web does not serve a clean single fake for
   these queries, and inventing one as "live" would be dishonest. B1/B5 use
   single TRUE claims (NEEDS_CORROBORATION, disp 2) instead. Single-source
   falsehoods are covered adversarially in the M/R battery (M1–M4, constructed
   sources, explicitly allowed).
3. **mtn_answer check order** (Mauna Kea > Denali > Everest, first match wins)
   documented in `gen_v2.py`; geology.com's snippet names both Everest and
   Mauna Kea and classifies as Mauna Kea.
4. **Single-letter answers** (U2 "K", U4 "N"): the mechanical substring rule
   matches broadly. Provisional answers were correct in all cases; the
   looseness is a transport-labeling limitation, not a sense-mechanism flaw.

## Residuals

- **Unanimous two-source spoof** (M5–M6): both rules install. Honest
  sensor-deceivable residual — "truthful but sensor-deceivable" stands.
- **Single volunteer-run instance** (lumy.live): the sense works, but
  production needs instance redundancy; the searx.space fleet is largely
  429/hostile to this VM's IP.
- **DDG fallbacks are intermittent** (~50–70%); fine as fallbacks, not primaries.

## Implementation notes (build fixes during scoring)

- `ws_install` now refuses on `tamper!=0` (corrupted-result hash can never
  install — closes a safety gap found during review).
- `ws_domains2` now records only domains whose stated answer equals the
  installed candidate (provenance accuracy for the ledger).
- `gen_v2.py` uses the v1 true-answer table for unknown facts (same role as
  v1's fixture labels); expected dispositions count distinct domains per the
  frozen corroboration rule.
