# TNN Master Architecture Plan — R27 Completion / Native Zag v2 Capability Program

**Status:** FINAL PLAN FOR USER REVIEW — NOT EXECUTED YET  
**Base checkpoint:** verified R27 accepted state, development step 60,423, zero newborn restarts.  
**Implementation rule:** promotable cognition, PAMs, learning, memory management, routing, self-revision, and integration are native Zag v2. Python may only be external analysis/evaluation glue and never counts as TNN capability.  
**Primary objective:** build one continuous TNN architecture that learns, remembers, reasons across persistent entities/events, creates its own non-core PAMs, manages its own memory hierarchy, learns from a strong Master and siblings, and survives strict integrated qualification without evaluator leakage or benchmark gaming.

---

## 0. Non-negotiable scientific rules

1. **Continue the same brain.** No newborn restart. Every accepted revision derives from the exact prior accepted state or a deterministic, verified native migration of it.
2. **Training first, architecture when justified.** Weak scores trigger detailed dose/teacher/memory/routing diagnostics before structural changes.
3. **Architecture is allowed to change aggressively when evidence demands it.** Core PAMs are protected from TNN self-mutation, not sacred.
4. **TNN-created non-core PAMs require zero researcher implementation.** TNN generates executable PAM structures through a generic protected Foundry.
5. **Memory is TNN-controlled.** There is no human developmental schedule that phases exact memory away. TNN chooses short/working/long-term/episodic/semantic/procedural/archive placement and revises those policies from consequence and regret.
6. **Hardcoded Master is permitted as teacher, not learner.** Teacher knowledge cannot be counted as TNN competence and must be withdrawn before qualification.
7. **No evaluator leakage.** Object IDs, category names, human relation names, transcript labels, final answers, hidden-set composition, and score keys stay outside mutable cognition.
8. **100% is a skeptical bounded qualification target.** Never make the test easier to obtain it. A perfect score must survive sealed hidden tests and then harder challenge batteries.
9. **Every result has authorship and provenance.** Separate TNN-generated mechanisms, protected core mechanisms, Master curriculum, researcher implementation, and evaluator-only scoring.
10. **Negative results remain first-class artifacts.** Failed PAMs, bad memory policies, teacher failures, and regressions are retained with causal history.

# PHASE A — Establish one authoritative native Zag v2 brain

## A1. Reconcile developmental state and native runtime

The project currently contains a developmental R25-R27 lineage and earlier verified native Zag v2 machinery. The next run must stop treating those as parallel worlds.

Build a one-time **State Continuity Bridge** that maps the accepted developmental state into native Zag v2 representations without adding knowledge. The bridge is external engineering, not cognition.

Required parity before any new training:

- state digest lineage references preserved;
- zero newborn restarts;
- strict Zag v2 compilation;
- checked/release execution parity;
- deterministic save/reload;
- exact archive/provenance integrity;
- retained R25-R27 English/reasoning/sibling/memory/sensory probes reproduced within predefined tolerance;
- no capability credited to Python surrogate code.

If exact structural migration is impossible, create a deterministic behavioral migration and separately mark which old internal structures could not be represented. Do not silently claim internal identity when only behavioral parity exists.

## A2. Freeze the root verifier and final hidden sets

Before architecture tuning:

- pre-generate sealed hidden seeds;
- hash them;
- separate development, validation, confirmation, and final qualification worlds;
- prevent TNN and Master from accessing hidden scorer labels;
- keep final hidden-set details unavailable to training logic.

Development results may change curriculum or architecture. Final qualification results may not be used for another attempt without declaring a new experimental generation and creating a fresh sealed set.

# PHASE B — Audit whether the previous 0% failures were real

The previous integrated result showed 93.33% spoken-name resolution and 100% different-entity rejection but 0% same-entity changed-view identity and 0% sibling teaching. That pattern must be investigated before redesigning the brain.

## B1. Fairness / sabotage audit

For every integrated item verify:

- target entity actually appeared during training;
- only the viewpoint/background/noise is novel, not the identity itself;
- positive same-entity pairs share the same real source entity;
- negative distractors are truly different entities;
- the entity was inserted into persistent identity memory before testing;
- teacher withdrawal begins only after the declared exposure budget;
- clean/noisy pairs differ only in intended corruption;
- sibling sender/receiver are independent;
- no accidental state reset occurs between naming, identity, affordance, and sibling phases;
- evaluation does not bypass the normal TNN route.

Then rerun the accepted architecture unchanged.

## B2. Step-by-step learning curves

For every major capability, collect curves at exposure counts such as:

`1, 2, 4, 8, 16, 32, 64, 128, ...`

Continue until one of these is demonstrated:

- strong continuing improvement;
- clear plateau across multiple increments;
- interference/regression;
- compute/resource saturation;
- ceiling on development but failure on hidden transfer.

Do not assume the same exposure schedule across identity, affordance, language, speech, and sibling teaching.

At each step log:

- current accuracy and confidence;
- exact failure examples;
- active PAM route;
- memory location of relevant evidence;
- retrieval success/failure;
- Master intervention selected;
- whether TNN requested help or reinspection;
- whether new evidence changed the hypothesis;
- later delayed outcome.

This is the core diagnostic dataset for architecture decisions.

# PHASE E — Autonomous PAM Foundry

This is a major architectural milestone.

## E1. Protected generic Foundry substrate

Implement a native Zag v2 **PAM Foundry VM** as protected core infrastructure. It supplies generic executable primitives, not task-specific candidate architectures.

Primitive classes may include:

- state cells;
- weighted local connections;
- recurrence;
- delay lines;
- local receptive mappings;
- gates;
- normalization;
- nonlinear transforms;
- temporal pooling;
- prediction/error channels;
- routing switches;
- plastic weights;
- sparse competition;
- memory read/write ports.

## E2. TNN-generated executable PAMs

TNN itself must generate graph/data structures that define a candidate PAM. It autonomously controls:

- topology;
- node count;
- receptive field;
- recurrence;
- update rates;
- plasticity;
- input/output ports;
- compute budget;
- training budget;
- routing conditions;
- cloning;
- specialization;
- merging;
- pruning;
- deletion.

A researcher does **not** translate “try a wider PAM” into code.

## E3. Endogenous proposal process

TNN uses its failure telemetry and causal history to decide:

1. Is more training still yielding value?
2. Is the failure correlated with a specific sensory/context cluster?
3. Is the current route underutilizing existing evidence?
4. Would a new PAM likely add information, memory, or temporal integration?
5. What candidate structures should be generated?
6. How much resource should each receive?
7. What shadow tests discriminate them?
8. Which candidates should be promoted, retained contextually, or deleted?

The proposal grammar must permit combinatorial novelty, not a short menu of human-named architectures.

## E4. Self-revision safeguards

- core PAMs and root verifier inaccessible to TNN writes;
- non-core PAM candidates sandboxed/shadow-routed initially;
- resource ceilings enforced by protected substrate;
- accepted-state rollback always available;
- provenance records exact parent PAMs and failure evidence;
- a PAM cannot validate itself without external root-verifier confirmation.

# PHASE F — TNN-controlled memory architecture

Memory autonomy is a core capability, not a cleanup pass.

## F1. Memory substrate versus memory policy

Protected substrate provides:

- addressable storage;
- integrity checks;
- provenance;
- timestamps/order;
- access-cost accounting;
- resource accounting;
- save/reload;
- rollback.

TNN controls policy.

There is **no rule** such as “young TNN stores exact episodes; mature TNN slowly stops.”

## F2. Coexisting memory forms

Support at least:

- sensory trace memory;
- active/working memory;
- short-term episodic memory;
- exact long-term episodic archive;
- structured event/entity memory;
- semantic relational memory;
- procedural/fiber memory;
- PAM-specific local memory;
- source/provenance memory;
- counterfactual/quarantined memory.

These are storage/operation capabilities, not human developmental phases.

## F3. TNN memory decisions

TNN can decide to:

- keep exact;
- retain only a compressed representation;
- keep exact + compressed;
- index for fast retrieval;
- move between hot/cold storage;
- rehearse;
- consolidate;
- link episodes;
- preserve anomalies;
- duplicate high-value evidence for resilience;
- de-prioritize redundant evidence;
- evict when justified;
- restore future policy after regret.

Policy features may include:

- uncertainty;
- novelty;
- future prediction error;
- recurrence;
- causal usefulness;
- downstream task value;
- source reliability;
- contradiction;
- retrieval frequency;
- resource cost;
- regret from prior compression/eviction.

## F4. Memory regret experiments

Give ordinary-looking details unpredictable future relevance. Measure whether TNN learns:

- what to protect;
- when compression is unsafe;
- when exact archive is worth cost;
- how to revise future retention after regret.

Compare against fixed human policies such as FIFO, LRU, phase-based reduction, keep-all, and fixed compression.

The goal is not minimum memory. The goal is **maximum long-horizon capability per available resource, under learner control**.

# PHASE G — Persistent entity architecture

The 0% changed-view result makes this central.

## G1. Entity identity is not a single classifier output

Build persistent identity from converging evidence:

- temporal continuity;
- multi-view visual evidence;
- transformations between views;
- action continuity;
- object permanence through disappearance;
- provenance-linked episodic evidence;
- contradiction from similar distractors;
- learned active reinspection.

Maintain multiple hypotheses when ambiguous.

## G2. Entity split/merge

TNN should autonomously propose:

- merge two traces believed to be one entity;
- split one entity that accumulated contradictory evidence;
- preserve unresolved alternatives;
- request more evidence before committing.

A merge cannot be decided by evaluator object ID.

## G3. Identity challenge ladder

Train and evaluate in increasing difficulty:

1. same view;
2. small viewpoint change;
3. rotation;
4. scale/background change;
5. partial occlusion;
6. disappearance/reappearance;
7. visually similar distractor;
8. heavy corruption;
9. long delay;
10. changed context and action;
11. cross-session save/reload.

At each rung, continue training until the curve is understood before moving to the next.

# PHASE H — Active perception and information-seeking

TNN should not passively accept ambiguous perception.

Expose generic actions such as:

- inspect another view;
- observe motion;
- inspect an earlier exact episode;
- perform/observe a discriminating action;
- ask the Master;
- ask a sibling;
- wait for more evidence;
- abstain.

TNN learns expected downstream value and cost of each action from consequences. Do not hardcode “if confidence < X, ask for another view.”

Final tests should include cases where:

- extra view helps;
- extra view is irrelevant;
- exact replay helps;
- sibling testimony is wrong;
- Master is unavailable;
- abstention is better than guessing.

# PHASE I — Unified entity/action/effect world model

Affordance must stop being an arbitrary category-to-action table.

Represent experience around persistent entity hypotheses:

`entity state + action + context -> observed consequence`

The learner should discover reusable action/consequence structure across entities while preserving exceptions.

Training progression:

1. repeated action on same entity;
2. different actions on same entity;
3. same action on different entities;
4. several entities with related consequences;
5. superficially similar entities with different behavior;
6. different-looking entities with similar behavior;
7. unseen entity generalization;
8. counterexample revision;
9. delayed recall;
10. corrupted perception.

Category-like abstractions should emerge only when useful for prediction and action, not because the evaluator supplies category IDs.

Maintain a causal architecture ledger:

# PHASE N — Stepwise capability-maximization protocol

For every target metric, use the following escalation loop:

### N1. Baseline
Freeze architecture and measure hidden performance.

### N2. Training dose
Increase exposure while logging the curve.

### N3. Better teaching
Replace repetition with targeted examples, contrasts, counterexamples, changed contexts, teach-back, and active observation.

### N4. Memory diagnosis
Check whether evidence was learned but forgotten, misplaced, compressed, or not retrieved.

### N5. Route diagnosis
Check whether the right PAM/entity/world-model route was selected.

### N6. Representation diagnosis
Check whether the relevant information exists in internal representations.

### N7. Autonomous non-core architecture search
If plateaued, let TNN Foundry create and test candidates.

### N8. Core redesign
Only if lower layers demonstrably destroy information or universally constrain downstream learning.

### N9. Confirmation
Require fresh multi-seed confirmation and all regressions.

This loop repeats until improvement is exhausted or the bounded target is solved.

# PHASE O — Skeptical evaluation and the 100% target

## O1. Development/hidden separation

Use at least:

- 5 development seeds;
- 5 validation/confirmation seeds;
- 5 sealed final qualification seeds;
- additional adversarial challenge seeds after any nominal 100% result.

Larger sample counts should be used when per-seed item counts are small.

## O2. Headline integrated targets

Target 100% on the preregistered bounded qualification set for:

- spoken name resolved clean;
- spoken name resolved late-noise;
- same entity changed view clean;
- same entity changed view late-noise;
- similar/different rejection;
- affordance clean;
- affordance late-noise;
- sibling successfully taught;
- fully integrated success.

But a 100% score is accepted only when:

- every hidden item passes;
- test size is reported;
- no hidden example influenced training;
- no evaluator label is exposed;
- teacher is withdrawn where required;
- save/reload works;
- historical regressions pass;
- multiple corruption/view/delay families are present;
- exact near-neighbor challenges are present.

## O3. Post-100 challenge battery

A perfect bounded score automatically triggers a harder test:

- more severe viewpoint shifts;
- previously unseen combinations of corruption;
- longer delays;
- stronger distractors;
- novel speakers;
- unseen entities/categories/affordances;
- misleading sibling testimony;
- ambiguous cases requiring abstention;
- memory pressure;
- longer continuous interaction.

If the harder battery drops, report both numbers and narrow the capability claim.

## O4. Statistical discipline

Report:

- numerator/denominator, not percentage alone;
- per-seed values;
- mean/median where appropriate;
- confidence intervals when informative;
- failure examples;
- development vs final hidden distinction;
- exact regression deltas.

No 100% from three duplicated or effectively identical seeds is treated as strong confirmation.

# PHASE P — Integrated qualification scenario

The final bounded scenario should require all major mechanisms in one uninterrupted brain lifetime:

1. TNN encounters several unfamiliar physical entities from raw video/audio.
2. It chooses what sensory evidence to retain and how.
3. It builds persistent entity hypotheses across multiple views.
4. The Master teaches one arbitrary spoken/name association once.
5. TNN observes actions and consequences.
6. Long unrelated experience occurs and memory resources are pressured.
7. The target entity disappears and later returns under changed viewpoint/noise.
8. Similar distractors appear.
9. TNN identifies the same entity and rejects the distractor.
10. It resolves the learned name.
11. It selects or predicts an appropriate affordance from learned consequences.
12. A sibling that never saw the entity receives a learned description/demonstration.
13. The sibling asks a useful discriminating question.
14. The receiver identifies the entity among distractors.
15. A sibling supplies one misleading claim; provenance prevents echo amplification.
16. The Master is fully removed.
17. The system is saved and reloaded in a fresh process.
18. The entity appears again under compound corruption.
19. TNN retains identity, name, affordance, source history, and correction.
20. The root verifier reruns all old regression suites.

The integrated score is all-or-nothing per scenario as well as component-scored. A system that gets 19/20 does not receive 100% full integration.

# PHASE Q — Promotion hierarchy

### Non-core PAM promotion
May promote if broad hidden gain is material, repeated across fresh seeds, and regressions are acceptable—even before the total integrated system reaches 100%.

### Memory-policy promotion
Must improve future utility/retention under resource pressure without unacceptable loss of exact future-relevant detail.

### Entity/world-model promotion
Must improve changed-view identity, permanence, and downstream naming/affordance—not just a standalone classifier metric.

### Core PAM replacement
Requires the strongest gate: sensory information gain, downstream integrated gain, multi-seed replication, regression parity, native deterministic continuity, and no leakage.

### Master-policy change
Can be promoted as a teaching policy if it improves learning after withdrawal. It never counts as runtime learner competence itself.

### Production/general capability
Remains locked until dedicated gates pass. Bounded 100% is not adult English, unrestricted camera intelligence, AHI, human superiority, or production readiness.

# Success definition

The goal is not to produce a table full of 100s. The goal is to build an architecture capable enough that **a hostile, correctly isolated evaluator is forced to report 100% on the bounded task because the learner actually solved every item**.

If the score is 63%, report 63% and show the training curve. If more training takes it to 88%, continue. If it plateaus at 88% while the core representation still contains the needed information, investigate memory/routing/entity architecture. If the core destroys the information, redesign the core. If a TNN-generated PAM takes it to 97%, promote that PAM if it passes broad gates but keep the final problem open. If it reaches 100%, attack it with a harder sealed challenge before calling the capability robust.

That is the intended path to maximum genuine capability rather than benchmark-shaped success.
