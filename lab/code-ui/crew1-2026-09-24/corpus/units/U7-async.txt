# U7 — ASYNC / PROMISES (manual excerpts; sources: MDN async_function, handbook/2/everyday-types.html)

## async functions
- async function getFavoriteNumber(): Promise<number> { return 26; }
- An async function ALWAYS returns a Promise. A non-promise return value is
  implicitly wrapped: return 26  ~  Promise.resolve(26).
- Annotate the return as Promise<T>, not T.
- await is ONLY valid inside an async function body (SyntaxError otherwise).
- await suspends until the promise settles; the resolved value is the await
  expression's value: const result = await resolveAfter2Seconds();

## Error handling
- try/catch works around awaited code:
  async function getProcessedData(url: string) {
    let v: string;
    try { v = await downloadData(url); }
    catch (e) { v = await downloadFallbackData(url); }
    return processDataInWorker(v);
  }

## Concurrency
- const slow = startSlow(); const fast = startFast();
  const a = await slow; const b = await fast;   // concurrent start, serial wait
- await Promise.all([p1, p2]) — wait for all, fail-fast, single chain.
- Sequential awaits of independent promises is SLOWER than Promise.all.

## Promise basics
- new Promise<string>((resolve) => setTimeout(() => resolve("done"), 10));
- resolve/reject are the executor's parameters; types flow from Promise<T>.

## Common errors
- TS1308 'await' expressions only allowed within async functions.
- TS1068/TS2461: returning T where Promise<T> declared is FINE (auto-wrap);
  returning Promise<T> where T declared is an ERROR — annotate Promise<T>.
- Forgetting await: const p: Promise<string> = fetchName(); p.toUpperCase()
  // TS2339 — p is a Promise, not a string.
