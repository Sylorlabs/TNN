# W1 PREREG — Real training-data stress test (frozen pre-build, 2026-09-20)

Branch: `tnn-native-lab`. Workstream 1 of the post-wave-11 program:
**REAL TRAINING DATA for TNN**.

This file is committed BEFORE any W1 harness source is written. Any change
after this commit is a dated amendment, flagged for retroactive review.
Standing laws apply: pure Zag for harness/runner/checker, zero RNG
(static-grepped), byte-identical reruns, append-only audit, no binaries /
`.zagd` / `.zag-cache` committed.

## 1. Claim under test

The native five-organ deliberate-memory machinery (the `st_memory_core`
substrate as integrated in INT-1) can ingest **real byte material** —
natural-language prose and production source code — as episodes, and run its
deliberate learning lifecycle over it at a 6,144-episode scale:

- **O1 acquire:** one deliberate memory per 64-byte chunk, holding a
  deterministic integer signature of the chunk's bytes (add path, audited).
- **O1 re-evidence / O3 consolidate:** on re-observation with an unchanged
  signature, record corroborating evidence and promote the memory
  (SHORT→LONG tier).
- **O2 eliminative refutation:** on re-observation with a changed signature,
  refute the "chunk is stable" hypothesis with logged justification and
  deliberately kill the memory (arm-B deliberate kill, audited).
- **O4 recall:** byte-exact recall — re-read sampled chunks from the corpus
  and verify the stored signature still describes them.
- **O5 govern / audit:** the append-only audit replays to exact state
  (`st_replay_check` == 0).

**What this does NOT claim.** This is a stress test of the learning
machinery against real-world material, not a product demo. It does NOT
claim TNN is a language model, learns language, or does next-token
prediction. There is no tokenizer, no vocabulary, no embedding table, no
gradient descent, no text generation anywhere in this workstream. TNN is not
an LLM; W1 measures whether its deliberate-memory learning loop functions
correctly, deterministically, and at scale on real bytes instead of
synthetic integers.

## 2. Why full LLM scale is infeasible (stated honestly, pre-build)

1. **Representation.** Memories are i32 scalars in slots (in INT-1, "the
   value IS the episode id"; here, the value is a 32-bit chunk signature).
   There is no float type in the learning path, no vocabulary, no embedding
   table, and no matmul — a 33k×256 embedding alone would be ~33 MB of
   integer arithmetic the substrate has no operator for.
2. **No sequence objective exists.** O2 does eliminative hypothesis logic
   over committed hypotheses; there is no prediction head, no loss
   function, no optimizer. Nothing in the organism predicts the next byte.
3. **Capacity.** Store slots are budgeted in tens–hundreds at current legs;
   the audit ledger costs 16 words (64 bytes) per op; znc forbids indexing
   any single slice larger than 2^25 bytes (33,554,432).
4. **Throughput.** `st_add` scans linearly for a free slot — O(cap) per add
   when near-full, i.e. O(n²) at 100k+ memories. This harness stays two
   orders of magnitude below that knee and reports the measured cost.

## 4. Mechanism (committed, deterministic, zero RNG)

- **Chunking.** Concatenated order: D1 chunks 0..4095, D2 chunks 4096..6143.
  N = 6144 episodes. Chunk size 64 bytes.
- **Signature.** `h = 0`; per byte `b`:
  `h = (((h & 0xFFFF) << 5) + (h & 0xFFFF) + b) & 0x7fffffff`.
  Every intermediate is < 2^21, so the result is well-defined regardless of
  the backend's i32 overflow semantics. Deterministic; a 1-byte flip
  changes the signature with certainty for these slices. The signature is NOT
  collision-free on these slices: 28 collisions exist among the 6144 chunk
  signatures (6116 unique, verified pre-build on the committed slices).
  Collisions are benign for this harness because every comparison is
  per-chunk (pass-2 signature of chunk i vs the stored value of chunk i's
  own memory) — the fault probe needs only that every injected 1-byte flip
  changes its own chunk's signature, which holds for all 64 injected
  faults (verified pre-build). The checker asserts per-chunk consistency,
  not global uniqueness.
- **Store.** `st_init(cap=16384, audit_cap=65536, org=71)`. Region USER,
  declared judgment strength 50 (recorded openly; arm-B kill ignores
  strength, per INT-1's frozen arm-B kill law).
- **Pass 1 (stage ADD):** for i in 0..6143: `sig = w1_sig(chunk i)`;
  `st_add(sig, USER, 50, &slot)`; record slot in slotmap[i].
  Expected: `adds_ok = 6144`, zero refusals.
- **Fault injection (the O2 probe).** Before pass 2, copy both slice
  buffers to a working copy and flip byte 0 of every chunk with
  `i % 97 == 0` (`^= 0xFF`). Fault indices: 0, 97, 194, …, 6097 —
  exactly **64** faults. The committed corpus buffers are untouched.
- **Pass 2 (stage FULL):** for i in 0..6143: `sig2 = w1_sig(working chunk
  i)`; if `sig2 == stored value` → `st_evidence(slot, ST_J_CORROBORATED,
  cite_ep=i)` then `st_promote(slot)`; else → `st_justify(slot,
  ST_J_CONTRADICTED)` then `st_kill(slot)` (arm-B deliberate kill).
  Expected: `evidence_ok = 6080`, `promotes = 6080`, `kills = 64`,
  `justify_ok = 64`. Every kill's target must satisfy `i % 97 == 0`
  (checker-verified from the transcript's kill list).
- **O4 recall sample.** The first 100 indices `i` in [1, 6144) with
  `i % 97 != 0`: re-read chunk `i` from the **pristine** buffer, recompute
  the signature, compare to the stored memory. Expected: `recall_ok = 100`.
- **O5 / audit.** `st_replay_check` must return 0. Transcript prints
  `audit_n` as a measurement.
- **Transcript.** Machine-checkable `CHECK,<name>,<actual>,<expected>`
  lines; exit code = number of failed checks.

## 5. Kill bars (binding — if one fires, stop and report honestly)

- **K1 determinism:** the run script executes the binary twice; the two
  full transcripts must be byte-identical (`sha256sum` equal). Any diff =
  FAIL, stop.
- **K2 zero RNG:** static grep over `impl/*.zag` for
  `rand|srand|random|urandom|getentropy|rdtsc|clock_gettime|gettimeofday`
  (case-insensitive) must return empty. Any hit = FAIL, stop.
  (The harness never reads a clock: no wall-time inside the binary.)
- **K3 fault-detection exactness:** `kills` must equal exactly 64, and the
  killed set must equal exactly `{i : i % 97 == 0}`. Any other count or any
  kill outside the injected set = FAIL.
- **K4 recall:** `recall_ok` must equal 100. Any mismatch = FAIL.
- **K5 ingress honesty:** the in-harness sha256 of each slice buffer must
  equal the §3 hashes. Any mismatch = FAIL (wrong data, not a TNN result).
- **K6 repo hygiene:** no binaries, `.zagd*`, or `.zag-cache/` committed;
  corpora are never committed. Checked at commit time.

## 6. Measurements (not bars — reported as findings)

`audit_n` at end of run; peak live slots; op counts per op type; wall time
(measured by the run script around the binary, not inside it); binary size.

## 7. Verdict rule

**W1 PASS** iff K1–K5 all pass on the committed slice. A PASS means: the
deliberate-memory learning machinery ingests real prose and real code as
episodes, acquires true signature-beliefs, re-evidences and consolidates
the stable ones, refutes and kills exactly the corrupted ones, recalls
byte-exactly, and does all of it deterministically with zero randomness.
It does **not** mean TNN learned language. Any bar failure is reported as
an honest FAIL with the failing bar named — never bent, never re-scoped
without a dated amendment.
