## Root-cause taxonomy (verified against dlb_json.zag source + item bytes)

1. E_PARSE_11 "no hypotheses" (dlb_json.zag:398: if(it.*.nh<1){return -11;}):
   ZERO of 877 items carry input.hypotheses. The harness requires >=1
   hypothesis per item; the battery/red-team crews shipped raw task payloads
   (gate trials, attack descriptions, logic propositions, surface/deep
   evidence texts) with no hypothesis enumeration at all.
   Affected: 248 admit + 108 revoke + 104 trap + 109 cost = 569 items
   (the remainder fail earlier on causes 2/3 below).

2. E_PARSE_1 "JSON syntax" (jp_eat/jp_string/jp_int failures):
   (a) logic battery (264/264): input.evidence is an array of STRINGS
       (e.g. "CAUSE(LESS_DENSE(ice,than_water),FLOATS(ice,on_water))");
       dj_parse_evidence (dlb_json.zag:234) requires each element to be an
       object {id, supports{}, attacks{}} -> jp_eat('{') fails -> -1.
   (b) trap (18) + cost (16): bare JSON floats outside strings
       (e.g. trap ground_truth_basis "Bayes posterior=0.0242<0.5:
       (0.99*0.00050)/..." contains the bare numbers 0.99, 0.00050, 0.02).
       The harness JSON subset is objects/arrays/strings/signed-int32 only;
       jp_int stops at '.', the parser then chokes -> -1.

3. E_PARSE_8 "bad id characters" (dlb_id_ok: [0-9A-Za-z_.-]{1,64}):
   ground_truth values outside the id charset:
   - trap C6 (5 items): ground_truth "P and not-Q" (spaces).
   - revoke R2 cells (5 items): ground_truth "KILL/SURVIVE" (slash).

## Structural summary
The four Phase-1 crews never integrated: the harness (Crew 2) consumes
weighted eliminative-judgment items {input.hypotheses[], input.evidence[]
of {id,supports{},attacks{}}}, while the battery crew (Crew 3) and red-team
crew (Crew 4) produced raw task-material JSON (rich JSON with floats,
booleans, free text; logic evidence as bare proposition strings). The
harness's own honest-scope notes (HARNESS.md s2, ITEM_FORMAT.md) assumed
"the battery crew pre-encodes premises/observations as weighted evidence
links" — that encoding was never produced. No translation layer exists in
any frozen commit. The REDTEAM_PLAN.md "harness-integration notes" proposed
feeding surface_evidence at depth 1 / deep_evidence at depth>=2 and
evidence_rounds[k] at depth k — the frozen harness implements none of this
(it consumes input.evidence in payload order, one item per round).
