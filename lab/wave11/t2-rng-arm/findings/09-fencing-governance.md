# Slice 09: Fencing and governance — Arm B containment spec

## 1. Slice
Fencing and governance: the build tags, attestation, fail-closed rule, artifact audit, and
amendment-governance that guarantee Arm B's RNG can NEVER leak into canonical paths.

## 2. Falsifiable claim
If the fenced RNG arm is properly contained, then (a) no artifact in any canonical path can
be produced by an Arm B build (attestation audit: 0 canonical artifacts carry an Arm-B
attestation), (b) any attempt to compile a canonical build containing RNG-linked code fails
before producing an artifact (100% of injected-probe builds fail-closed), and (c) revoking
the amendment stops all Arm B work immediately (no Arm B binary can run, build, or be
attested within 24h of revocation). A single canonical artifact traceable to an Arm B build
kills Arm B permanently — this is the containment kill bar, independent of any trial result.

## 3. Design
**Build tags.** Two build profiles, selected at compile time by a single flag, never by
runtime config:
- `--profile=canonical` (default; zero flags = canonical): the znc build defines
  `TNN_CANONICAL` and omits the `src/rng/` unit entirely from the compile graph.
- `--profile=arm-b`: defines `TNN_ARM_B` and includes `src/rng/`. Arm B code lives ONLY
  under `src/rng/`; a canonical compile fails if any RNG-linked unit appears in its graph.

**Attestation.** Every built binary embeds, at link time, a 64-byte attestation header:
`[profile: canonical|arm-b][rng_points: bitmask of active prereg-enumerated injection
points][seed_scheme: "deterministic-fixed" | "logged-prereg"][amendment: "AMENDMENT_2026-09-20_RNG_ARM_B"][build_epoch: n]`.
Attestation is generated by the build driver (not by Zag code, not settable at runtime),
hashed into the binary's audit record, and every run logs it first. An Arm B binary with a
zero rng_points bitmask is legal (arm measured without RNG); a canonical binary with a
nonzero bitmask cannot exist — its build fails.

**Fail-closed rule (three layers).**
1. Compile gate: canonical builds compile `src/rng/` OUT. Any `import` or call into an
   RNG unit from canonical code is a hard compile error ("unknown unit"), not a warning.
2. Sentinel function: `rng_draw(slot)` exists ONLY under `TNN_ARM_B`. A canonical stub
   with the same name does not exist — so calling it in canonical code is a compile error,
   never a silent no-op. Additionally, at runtime each canonical entrypoint asserts
   `attestation.profile == canonical && attestation.rng_points == 0` before the first
   decision; mismatch = immediate abort, logged to the audit ledger.
3. Ledger gate: ledger/audit writes verify the attested profile; an Arm B-attested binary
   CANNOT write to a canonical ledger file (write rejected, binary aborts). This is the
   last line: even a corrupted binary cannot contaminate canonical history.

```zag
// src/rng/gate.zag — compiled ONLY under TNN_ARM_B
pub fn rng_draw(slot: i64) -> i64 {
    // slot: prereg-enumerated injection point id (tie-break, phrasing, exploration)
    // seed: fixed per prereg; every draw logged to arm-b audit with (slot, counter, value)
    let v = xorshift64(SEED ^ (slot << 32) ^ draw_counter);
    audit_log_b("RNG_DRAW", slot, draw_counter, v);  // arm-b ledger only
    draw_counter += 1;
    return v;
}
// Canonical compile: rng_draw does not exist. Any reference = compile failure.
```

**Artifact audit.** Weekly (and pre-release), a checker walks all canonical artifacts
(binaries, ledgers, checkpoints) and verifies: (i) each binary's attestation says
canonical with zero rng_points, (ii) no canonical ledger contains an Arm-B attestation
record, (iii) the canonical source graph contains no path into `src/rng/`. Output is a
signed audit report: PASS/FAIL with the attestation hash of every artifact checked.
Injected-probe test: periodically compile a canonical build with a deliberate RNG call
inserted — it MUST fail at the compile gate. A probe that builds, or an audit that finds
an Arm B attestation in a canonical artifact, fires the containment kill bar.

## 4. Kill bar
Containment kills Arm B (permanent, non-appealable, independent of trial outcome) if ANY of:
- one canonical artifact is found carrying an Arm B attestation or an RNG draw record;
- one injected-probe canonical build containing an RNG call compiles successfully;
- one Arm B binary is found able to write to a canonical ledger (ledger gate bypassed).
Trial-level (Arm B loses on merit): if Arm B loses on adaptivity, judgment stability,
integrity-trap performance, or reproducibility-from-logged-state, it retires per the
amendment's falsification posture. Governance kill: amendment revocation → zero Arm B
binaries buildable, runnable, or attestable; any Arm B run logged after revocation = audit FAIL.

## 5. Honesty notes
The compile gate assumes the build driver is honest — a compromised driver could forge a
canonical attestation onto an Arm B binary. Mitigation: attestation hash chain is verified
against the committed build config in git (branch tnn-native-lab); any binary whose
attestation doesn't match the config that built it is rejected at startup. I am NOT
claiming RNG is safe — this slice only claims it is fenced. The `src/rng/` directory
itself is a permanent attack-surface smell: periodic audits (not just weekly checkers)
are the price. Reproducibility-from-logged-state for Arm B is weaker than canonical by
construction: it reproduces only if the seed log is intact; losing the seed log = trial
data loss, not a canonical integrity event.

## 6. Next build step
Build the attestation header + the three fail-closed layers FIRST, before any RNG
injection point is implemented: a builder compiles `--profile=canonical` with a probe
RNG call and confirms hard compile failure, compiles `--profile=arm-b`, and confirms the
ledger gate rejects its write to a canonical ledger. Only when all three fail-closed
probes pass does RNG-point implementation begin.
