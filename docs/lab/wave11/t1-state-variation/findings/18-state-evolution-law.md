# Slice 18: The state-evolution law

## 1. Slice

State-evolution law: specify the exact deterministic transition function S' = T(S, E) that maps the
full internal state S plus one external input/event E to the next state S' between episodes, so that
state-dependent variation (Track 1) is lawful and replayable.

## 2. Falsifiable claim

If the transition function T is specified as a pure function over an enumerated, fully-logged state
vector with canonical event ordering, then any two runs starting from the same logged full state and
fed the same input sequence produce byte-identical full state trajectories (and therefore
byte-identical outputs), while any *legitimate* output variation across runs is traceable to a
logged difference in full state — never to unlogged nondeterminism. This is killed if a builder
implements T per this spec and any of the kill-bar conditions fire (see §4).

## 3. Design

**State vector (enumerated, all logged).** S = (M, H, C, B, D, K), where:
- M: memory store — slots indexed 0..N-1, each slot = (content hash, status ∈ {live,killed,pinned},
  strength grade, last-op episode id, cite pointer).
- H: hypothesis ledger — hypotheses indexed by creation id (monotonic u64, never reused),
  each = (status ∈ {live,refuted,suspended}, evidence ids, verdict episode).
- C: context id (current partition), the context-activation stack (ordered ids).
- B: deliberation budget counters per active context = (remaining steps, cap, consumed-this-episode).
- D: discrepancy/pending queue — ordered list of unresolved contradiction holds (trust-tier wave9).
- K: clock = monotonic episode counter (int64, incremented once per episode; NOT wall-clock).

**Events.** The only events are: `Observe(x)` (external input), `Deliberate(step)` (internal),
`Verdict(v)` (verdict reached), `MemOp(op, slot)` (deliberate memory op: add/kill/pin/promote/
demote/strengthen/weaken), `SwitchContext(c)`, `GateEvent(g)` (gate transitions, petitions).

**Transition rules (formulas, applied atomically per event).**
1. `Observe(x)`: K' = K+1; H' = H ∪ {new hypotheses generated by eliminative logic, id = next-id()};
   D' = D with each existing hold re-scored: score' = score + contra(x, hold) (contra is a
   deterministic hash-based mismatch count, no float rounding ambiguity); M unchanged. x is
   appended to the input log byte-exactly.
2. `Deliberate(step)`: B' = B with remaining = remaining − 1 for the active context; if
   remaining would go negative, the step is REFUSED and B' = B (budget exhaustion is a hard
   stop, not a skip). No other variable mutates. Exhaustion episode is logged.
3. `Verdict(v)`: H' = H with v.target.status = refuted if v = eliminate, live otherwise, and
   v.episode = K; D' = D minus any holds resolved by v (removal, not mutation — holds are
   append-only before resolution, then tombstoned with episode id).
4. `MemOp(op, slot)`: M' = M with slot updated per op's semantics; every MemOp appends one
   audit entry (op, slot, K, prev-status, new-status) to the append-only ledger (MA1:
   docs/lab/wave5/... audit replay to exact state). Killed slots keep content + tombstone
   episode (no reuse of killed slot ids within a run — ids are monotonic).
5. `SwitchContext(c)`: C' = c; activation stack push(c) (pop on return; stack is explicit,
   no recursion-derived order); B' resets consumed-this-episode = 0 for c only.
6. `GateEvent(g)`: C' gate transitions per the gate table (wave5/6 gates); gate state is a
   logged enum, never inferred.

**Simultaneous events ordering rule.** Within one episode, events are serialized in the fixed
canonical order: `GateEvent → SwitchContext → Observe → Deliberate* → Verdict → MemOp*`.
Multiple events of the same type apply in arrival order (single-threaded intake queue; intake
appends monotonically). No event ever interleaves with another: T is applied to one event at a
time. This is the only ordering rule and it is total — there are no ties.

**No hidden nondeterminism.** Canonical iteration: all scans (memory, hypotheses, holds) iterate
by id ascending; tie-breaks use smaller id, never pointer address. No wall-clock anywhere —
the only clock is K. No uninitialized reads: state is zero-constructed at init and every field
is written before any read (builder must prove by construction: all reads guarded by a
written-flag bitset checked at compile time in Zag). No concurrency: single intake thread.

**"Lawful" for outside-world variables.** External inputs x are *data*, not randomness: T is a
pure function T(S, E) where E includes the input bytes. The law governs the transition, not the
world — the same prior state plus the same input bytes always yields the same posterior state.
Unpredictable world ⇒ unpredictable-but-lawful state, exactly as a human differs by experience.

## 4. Kill bar

This design is dead (do not build on it) if ANY of the following fire in a trial implementing
the spec above, each run at ≥10x episodes with two seeds differing only in input order:
- KB1: replay from a logged full state + input log yields ANY byte difference in the final
  state vector or output (≠ 0 differences across 100% of reruns).
- KB2: any state variable mutated by an event NOT listed in §3 for that event (≥ 1 occurrence).
- KB3: any tie-break or iteration order not reducible to "smaller id first" observed in a
  trace (≥ 1 occurrence), or any wall-clock / uninitialized read detected by the build audit.
- KB4: two events in one episode applied in an order violating the canonical serialization
  (≥ 1 occurrence), or a Deliberate step applied when remaining = 0 (budget violated, ≥ 1).
- KB5: an output variation between two runs that cannot be attributed to a logged full-state
  difference (i.e. same S and same inputs → different output, ≥ 1 occurrence).

## 5. Honesty notes

Weakest points: (a) the canonical ordering rule is a *choice*, not a theorem — a different
ordering would give different lawful behavior, and nothing in this slice justifies this order
over another; it must be preregistered and then held fixed. (b) "every read guarded by a
written-flag" is a compile-time claim that must be enforced by the Zag builder, not assumed —
uninitialized reads are the classic hidden-nondeterminism source and this design's assurance
is procedural, not structural. (c) I am NOT claiming the listed state vector is complete:
slices 1–17 enumerate state variables; if any slice adds a variable, T must be extended and
re-frozen — this law is only as good as the prereg's variable list. (d) The budget-exhaustion
refusal (B' = B) creates a failure mode where a stuck agent burns episodes silently; the trial
must log exhaustion episodes and a builder-side watchdog should flag >N consecutive
exhaustions. (e) This slice does not address sensor-deceivable inputs (known accepted hole,
wave9): lawful evolution on spoofed data is still wrong — the law guarantees determinism, not
truth.

## 6. Next build step

Build the minimal native Zag harness: the state vector S as logged structs, the intake queue,
and the six transition rules as pure functions — then run the 10x-episode replay test (KB1)
with a fuzzer that permutes *only input arrival order* (inputs are data, not RNG) across 100
runs from the same logged state. If zero byte-differences in trajectory, the law holds and
slices 19+ can safely attribute all legitimate variation to logged state differences.
