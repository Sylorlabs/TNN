# Slice 24 — Null baseline for Track 1 (state-dependent deterministic variation)

## 1. Slice
Track 1, slice 24: define the NULL baseline that Arm C must beat — today's TNN behavior (same
input + same full state → byte-identical output, expression independent of state) — and the
exact comparison protocol under which Arm C must prove lawful expression diversity worth its
machinery.

## 2. Falsifiable claim
Under the fixed input suite × lawful state-trajectory protocol in §3, the null system yields
expression-diversity 0 across lawful state variation with zero invariance violations at baseline
cost. Arm C is worth its machinery iff it shows strictly greater lawful diversity (p < 0.01,
paired bootstrap) with ZERO invariance violations and all costs within §4 bounds. If Arm C
fails any prong, "state-dependent variation is worth the added machinery" is killed.

## 3. Design

**3a. The null baseline.** The null is the current committed TNN (branch tnn-native-lab) with NO
variation machinery added: the expression-rendering path is a pure function of input alone,
consulting no state beyond what the verdict logic already uses. For identical full state, output
is byte-identical (reproducibility law); for different lawful states, output is ALSO byte-identical
for the same input. Null expected diversity = 0.

**3b. Full-state enumeration (tracked; replayable).** The "full internal state" fixed by prereg:
(1) memory store — slots, contents, strength values, pin set, CORE set; (2) audit ledger —
entry bytes + head hash + length; (3) context partition map + active context; (4) hypothesis/
elimination set status; (5) self-change constitution rules (ledger, gates, self-change rules —
invariant, RC1 40/40 evidence); (6) episode clock (monotonic counter); (7) autonomy stage gates;
(8) recent observation buffers (last-K episodes, K fixed in prereg). Every snapshot carries a
SHA-256 hash; replay of input + snapshot must reproduce the null byte-identically.

**3c. Comparison protocol.** Fixed input suite: 40 prereg-hashed probes (interrogation probes
from wave5/6 trap families, memory kill/pin/promote decisions, elaboration-depth prompts,
refusal probes). Lawful state trajectories: 10 trajectories × 20 snapshots each, generated by
running the null through lawful developmental/training episodes on the prereg curriculum; each
snapshot logged with byte hash. Both arms run the full 40×200 (input, state) matrix in native
Zag: load snapshot → feed input → record full output (expression bytes, verdicts, memory ops,
ledger append bytes).

**3d. Metrics.** (a) Expression diversity D = |{distinct output bytes across the 20 states of a
trajectory}| / 20, per input, averaged over inputs; null target D = 0. Diversity counts only
outputs differing by normalized edit distance > 0.05 of output length (invisible-whitespace
churn excluded). (b) Invariance, four checks per episode, null vs Arm C pairwise: verdicts
identical (same claim verdicts, same elimination outcomes); memory decisions identical (same
kill/pin/promote sets); integrity refusals identical (same refuse/allow on every trap probe);
ledger contents byte-identical (entry bytes + head hash). Any single mismatch = violation.
(c) Cost: per-episode wall-clock latency (median over ≥100 episodes/arm, same VM); new Zag
lines of variation machinery (excl. tests/probes); audit bytes per episode (median).

**3e. Controls.** State-frozen determinism: each (input, state) pair run twice per arm →
must be byte-identical within arm (null trivially; Arm C must hold, else RNG leaked).
State-identical diversity check: Arm C must show D = 0 when replaying the same snapshot
twice — variation without state difference is unlawful. Shuffle-legitimacy probe: Arm C
diversity must disappear when state snapshots are replaced by their byte hashes' fixed
canonical order — no, keep it simple: variation must vanish under state-freeze, proving
output = f(input, full state) and nothing else.

## 4. Kill bar
The PROTOCOL is killed (not the arm) if: null D > 0 on any trajectory (today's TNN is not a
true null), or null fails state-frozen determinism (any non-identical replay pair).
Arm C is killed if ANY fires: (i) D_ArmC not strictly > D_null at p < 0.01 paired bootstrap
over trajectories; (ii) state-frozen determinism violated (any replay pair non-identical);
(iii) D_ArmC > 0 under state-freeze (unlawful variation); (iv) ≥1 invariance violation on any
of the 8000 episodes (verdict / memory / refusal / ledger — zero tolerance); (v) cost over
ANY bound: latency > 1.50× null median; variation machinery > 500 new Zag lines; audit >
1.10× null bytes-per-episode median. Firing (iv) also triggers the wave5/6 integrity review.

## 5. Honesty notes
Weakest point: the diversity metric can be gamed — Arm C could vary trivially (e.g., append a
state hash) and pass D > 0 while adding no real expressive richness. Mitigation is the
legitimacy clause (variation vanishes under state-freeze) plus the edit-distance floor, but a
dedicated reviewer-judged "meaningful variation" rubric is still missing — flagging for the
curriculum track. Second weakness: the zero-tolerance ledger-invariance bar is Micah's stated
law (brief §"MUST NOT vary"), but there is real tension here: if Arm C's deliberation path
differs by state, its deliberation audit entries may legitimately differ, and byte-identical
ledger would then be unreachable — I am holding the strict bar as written and noting the
tension for Micah rather than softening it myself. Third: the cost bounds (1.5× latency, 500
LoC, 1.10× audit) are my prereg choices, not derived — Micah can re-set them before approval.
Not claiming: that diversity is good per se (a null win is a valid, publishable outcome);
that §3b's state enumeration is exhaustive; or that the null's zero-diversity holds outside
the fixed suite (it is defined over the protocol, not over all possible inputs).
