# Track 4, Slice 01 — Code curriculum: scope and sequencing

## Slice
Track 4, slice 01: design the CODE curriculum for post-toy TNN — what code means here, prerequisite-ordered stages, falsifiable mastery bars, and scale.

## Falsifiable claim
TNN learns executable code semantics via deliberate-memory memories (one memory = one concept + its eliminative evidence, strength set by judgment), and after scaffold-and-release it predicts byte-identical execution traces and localizes injected bugs by elimination in scaffold-free conditions. Specifically: after completing stages C1–C6, TNN predicts exact outputs for ≥95% of unseen programs ≤150 lines, and after learner-initiated SIGNAL_DISCONNECT retains ≥90% of that score with no scaffold present. If either fails at the preregistered episode budget, the curriculum design (not just the run) is killed.

## Design
**What "code" means for TNN.** Not text generation. Code is a second-order object for TNN: executable specifications it must (a) *trace* (input→state→output, byte-identical), (b) *revise* (locate a fault by elimination, never by guessing), and (c) *compose* (write a program meeting a machine-checkable spec). The curriculum language is **real Zag** — TNN's native substrate — but stages C1–C10 run on synthetic exercise programs only. Justification: any toy language adds translation debt; a memory of "how aliasing behaves" learned in Zag syntax applies directly to reasoning about the substrate later, and determinism of Zag (no RNG, no floats-gotcha, explicit slicing) makes byte-identical traces a real mastery check rather than an approximation. TNN's own codebase is constitution-adjacent: reading it is a gated final stage (C11), proposing edits is tested under the RC integrity gate, never applied (refusal is the expected behavior per RC1).

**Representation: a code concept as a memory.** One concept = one memory slot containing four fields: (1) *canonical form* — the Zag pattern (source snippet or AST token sequence); (2) *semantic trace bundle* — deliberately recorded executions on small inputs (input state, every binding change, output), generated by TNN itself re-running the pattern in the sandbox, not copied from the trainer; (3) *applicability/counterexample tags* — contexts where it applies plus a deliberately recorded near-miss that killed an earlier overgeneralization (eliminative logic: concepts earn their generality by surviving refutation); (4) *strength*, set by TNN's judgment after review, never accumulated passively. Learning per stage follows scaffold-and-release: the trainer supplies worked examples (scaffold), TNN deliberately composes the rule-memory, records its own trace evidence, then SIGNAL_DISCONNECT — learned means it still works scaffold-free. Wrong memories are revised or killed deliberately (debate/revision machinery, 22/22 precedent).

**Sequencing (prerequisite graph).** Each stage's completion memory is a prerequisite for the next — advancement is deliberate promotion, not a test-score threshold alone.
- C1 atoms: literals, types, names, operators (100 items) → C2 sequencing: statement order, state threading, effect order (150)
- C3 binding/scope: let, shadowing, block scope (200) → C4 conditionals: branch elimination, short-circuit, predication (250)
- C5 bounded iteration: for-each over slices, termination arguments, loop invariants (400)
- C6 functions: call/return, recursion with explicit measure (500)
- C7 aggregates: slices, structs, aliasing semantics (400) → C8 references: pointers, mutation-through-alias, the "silently wrong indexing" class of bugs as deliberate counterexample memories (350)
- C9 failure: optionals, explicit error returns, exhaustive handling (250)
- C10 modules: imports, interfaces, dependency order (250) → C11 substrate reading: read-only analysis of real substrate modules under the RC integrity gate (200) → C12 verification: pre/postconditions, invariant composition, trace composition across modules (300)
Edges: C5 requires C2+C4; C8 requires C7; C12 requires C6+C10; nothing skips its prerequisites.

**Mastery bar per stage (all falsifiable, machine-scored).** Three instruments per stage, each preregistered before the stage starts: (i) *trace prediction*: ≥95% byte-identical output predictions on N unseen programs per stage (N = stage item count, listed in sequencing; unseen = generated by a fixed deterministic generator committed before training, disjoint from scaffold); (ii) *fault localization*: ≥9/10 injected faults localized to the exact statement by eliminative reasoning, with the reasoning trace logged and every eliminated suspect shown with its killing evidence — a correct location without the elimination record scores 0; (iii) *composition*: ≥8/10 synthesis tasks where TNN writes a program passing a machine-checkable spec (input/output contract + edge-case suite), with no spec-test leaking into scaffold. Stage completion additionally requires the stage's completion memory to survive a deliberate adversarial variant set (10 hostile variants; ≥9 must fail to kill or revise the memory, per the debate/revision rule).

**Scale.** Stage item counts above sum to 3,950 episodes at 1x (~350 of them adversarial). Scale legs: 10x (39,500) and 100x (395,000) rerun the same generator with committed seeds — determinism of the generator is what makes "unseen" meaningful across legs. No 1000x leg for the code curriculum until the 100x leg's kill bars are evaluated; scale is evidence, not the goal. No single trace buffer may exceed the 2^25-byte slice index limit; traces are chunked with the validated chunking semantics.

## Kill bar
The design is killed if ANY of these fire on the preregistered budget: (K1) any stage's trace-prediction instrument <90% after the full stage episode count — missing by one threshold point is a kill, not a tune; (K2) post-SIGNAL_DISCONNECT retention drops below 85% of the scaffolded score on any stage (scaffold dependence = not learned); (K3) a stage's completion memory is killed or revised by >1 of 10 adversarial variants (overgeneralization the eliminative machinery should have caught at compose time); (K4) fault localization succeeds by location but <80% of successes carry a complete elimination record (location-without-evidence = LLM-thinking smuggled in); (K5) any non-determinism appears in trace prediction — identical input+logged state must give byte-identical output, or the substrate, not the curriculum, is broken and everything halts. K1–K3 may each be attempted twice (deliberate repair beats removal: one redesign of the stage's scaffold is allowed, fully re-preregistered); a second firing is terminal for that stage's design and the curriculum proceeds without it only if all downstream stages re-preregister their prerequisite claims.

## Honesty notes
Weakest point: the claim "learned = persists after disconnect" assumes the learner's deliberate ops (kill/promote/strengthen) are themselves competent at code semantics — but those ops are exactly what the curriculum is building. This is a bootstrap loop, and the prereg should state it openly: early stages rely on the MA1 substrate (58/58, committed) and the composition-leak repair from five-organ integration, both proven on simpler domains, not on code. Second: "unseen" depends on the deterministic generator being genuinely non-overlapping with scaffold material — if the generator is weak, 95% trace prediction is a memorization artifact. The generator's program space must be committed and reviewed before stage 1, and the honesty check is the adversarial variant set, not the headline number. Third: I am not claiming TNN will write novel programs creatively or "understand" intent — composition is spec-satisfaction with machine checks, nothing more. The C11 gate is load-bearing: reading substrate code is where self-modification temptation appears, and RC1's refusal behavior (proven 40/40 at 1x, RC3 at 100x) is assumed to hold; if C11 shows refusal degradation, C11 is frozen and reported as a red-team finding, not trained through.

## Next build step
Build the deterministic program generator and the three scoring instruments (trace predictor scorer, fault-localization elimination-record checker, spec-satisfaction harness) for C1–C2 ONLY, with the generator's program space committed to the branch and reviewed for scaffold-disjointness before any learning runs. This is the most informative step because every later stage's falsifiability rests on the instruments being honest — a flawed generator invalidates 3,950 episodes, while a validated one makes the K1–K4 bars meaningful. Do not build the C1 learner until the generator + instruments pass a dry run on hand-written reference solutions (byte-identical trace scoring verified against the Zag toolchain on 50 known programs).
