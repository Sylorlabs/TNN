**1. HONESTY HOLES**

The saliency definition (motion + texture, u64 integer per pixel) is programmer-provided and explicitly "crude" per open risk 1; it has no object concepts and can latch onto legs/ground instead of heads. This is smuggled choice dressed as generic perception — the mechanism never "sees" the pig's snout or bunny's ears, only busy patches. Test: extract the 9 cell densities from the trace for this exact run; if both memories' max cells are in non-subject areas, the focus rule is already failing its own rubric's recognizability criterion.

The thirds grid (3×3, density = cell_mass/total_mass / cell_area/frame_area, exact integer ×10000) is fixed programmer code with no justification for 3 vs 4 vs 5 vs n. Focus = argmax-density cell (tiebreak lowest index) is likewise hardcoded; the tiebreak alone can make corner ADJOIN deterministic in one direction regardless of content. Legitimate? No — these are not generic standards; they are baked-in heuristics chosen once. Test: run the same two memories with saliency swapped to gradient-only or motion-only; if winner changes only because of the thirds rule, it's steering.

Verb_fit rubric numbers (MERGE: OVERLAY 100 / PIP 85 / SPLIT 60 / XFADE 45 / INTERLEAVE 40; SIDE: SPLIT 100 etc.) are explicitly "programmer-authored rubric" with no derivation, no ablation, and no validation beyond "not for winner-picking." These are the single biggest leak — they hardcode the exact preference ordering for this test pair. Criterion weights (35·verb_fit + 30·presence + 20·balance + 10·recognizability + 5·parsimony) are likewise authored once and never stress-tested for discriminativeness across varied pairs. Presence formula (10000·donor_retained·recipient_retained, with SPLIT mass fractions) rewards raw mass retention but can be gamed by making one subject tiny. ADJOIN corner rule (minimizing recipient-saliency overlap) is a programmer heuristic with no proof it finds "best" corner. Candidate set of exactly 18 (OVERLAY 4, PIP 8, SPLIT 4, INTERLEAVE 1, XFADE 1) excludes any plan involving object correspondence, semantic blending, or part swaps. Refusal fallbacks (unknown verb or unmatched noun → rc=1) are too brittle for "imagination" but are the honest guardrail.

Every one of these is either explicitly programmer-provided or a fixed heuristic chosen without evidence it generalizes beyond this test. The "no specific pair" claim does not survive contact with the numbers and rules.

**2. DEGENERACY CHECKS**

Yes, the rubric produces near-identical scores: prototype 64.2 vs 64.11 (0.09 margin) for MERGE winner. Because arithmetic is "exact integer fixed-point (×10000)" with no floats, the 0.09 difference must come from the integer components of the 35/30/20/10/5 weights and the 0..10000 scores. But the doc never states whether the final total is integer or scaled; a 0.09-point difference in prototype Python is meaningless noise in Zag's integer domain. Winner winning on a criterion that doesn't track reality: presence rewards retention but penalizes SPLIT only by mass fractions while XFADE gets a flat 2500; if saliency is concentrated in one cell, OVERLAY can win on presence while balance and recognizability are mediocre. Parsimony tiebreak is always 10000 but "documented" — that documentation can be whatever the builder writes. The 0.09 margin is exactly the kind of noise-laundering that makes the mechanism look deliberative while being driven by tiny integer differences in programmer-chosen weights. Trust it only if the full trace shows the top loser losing on recognizability (3000 penalty) or verb_fit gap, not on a 9-point difference in a 10000-scale presence term.

**3. THE IMAGINATION QUESTION**

This is a parameterized compositing menu with a scoring function, not imagination. The mechanism is given a fixed list of 18 plans, a fixed saliency metric, a fixed rubric, and fixed pixel operators; it picks the max-score one after measuring content. No generation of new plans, no reasoning about alternatives, no notion of "what would a real imagination do." Strongest steelman that it IS genuine (crude) imagination: the trace ships every candidate's five scores + total + templated reasons; selection is argmax over content-derived measurements, not hardcoded for pig/bunny; XFADE is deliberately included as rejectable control; instruction sensitivity is required to prove choice is mechanism-owned. Strongest attack that it ISN'T: this is exactly what a deterministic rule engine does with a scoring layer. It has zero agency, zero creativity, zero abstraction. Single architectural addition that would most move it toward genuine imagination: a plan generator that emits new plan families (e.g., "match facial landmarks then blend") instead of the enumerated 18.

**4. MISSING MECHANISMS**

No object/part correspondence whatsoever. The head-swap example REQUIRES knowing which region of the pig corresponds to which region of the bunny. The design has only focus rects (argmax cell) and saliency mass fractions; it grafts arbitrary rectangles or splits frames without any feature matching, optical flow, or part segmentation. It fakes correspondence by always grafting the donor focus rect centered on recipient focus cell — which may be the pig's leg on the bunny's head if saliency is wrong. No temporal structure beyond INTERLEAVE/XFADE/SPLIT; no story-level planning for "THEN". No abstract concept binding ("merge the two subjects while preserving identity"). No way to represent or reason about "replace head" vs "adjoin in corner". The design achieves none of these and fakes the rest with rect_copy and scale_nn.

**5. FAILURE MODES**

- Focus cell lands on pig leg instead of head → OVERLAY grafts wrong region; trace will show high saliency but rubric's "recognizability" (3000) doesn't catch it because it's not about correctness, only about scale and blend.
- ADJOIN always picks the same corner due to tiebreak or saliency calculation order → deterministic programmer bias hidden as "best corner."
- XFADE wins because recognizability penalty (3000) + verb_fit (45) is insufficient against other plans when scores are close (see degeneracy above).
- Still-image ingest uses PPM only (PNG out of scope); if the pig/bunny clips were PNGs, the mechanism literally cannot ingest them without ffmpeg pre-conversion that the Zag binary never sees.
- Refusal falls back to rc=1 on any verb not in the exact scan list; this is programmer veto, not mechanism imagination.
- Trace records "why top losers lost" but builder can ignore any row that doesn't support the desired winner.

**6. THE SECOND-INSTRUCTION TEST**

"Different verb → different winner" is weak evidence at best. It can be gamed by making the machinery prefer SPLIT for SIDE and anything else for MERGE while the actual choice logic never depends on the parsed verb — only on the fixed candidate set and saliency. Stronger test the builder should run: (a) ablate one rubric component (e.g., remove recognizability penalty) and confirm winner changes for the same instruction; (b) run identical instruction on four different memory pairs and confirm winner changes when content changes (not just label); (c) swap the thirds grid to quarters and confirm argmax cell (hence plan parameters) actually moves; (d) add a third instruction "merge then side by side" and verify the mechanism does not simply concatenate the two prior winners.

**7. VERDICT**

Fundamental flaw requiring rethink. The architecture is not imagination; it is a deterministic scoring engine over a programmer-supplied menu of 18 plans, with programmer-supplied numbers, grid, focus rule, and saliency. Every honesty hole listed in 1 is a leak of steering. The head-swap example cannot be achieved without object correspondence that the design explicitly lacks. Build this only if every programmer-provided number, grid, and rule is first replaced by a mechanism that discovers them from data — otherwise it is exactly the "programmer writing the blend" the load-bearing honesty rule forbids.
