## What this proves — and what it does not

**Proves:** the deliberate-memory learning machinery ingests real prose
and real code as episodes (file ingress via native capability IO works),
acquires per-chunk signature-beliefs, re-evidences and consolidates the
stable ones, refutes and kills exactly the corrupted ones with logged
justification, recalls byte-exactly, keeps a replay-clean audit — all
deterministically, with zero randomness, on real byte material instead of
synthetic integers.

**Does NOT prove:** language learning. There is no tokenizer, no
vocabulary, no embedding table, no next-token objective, no gradient
descent, no text generation. TNN is not a language model; W1 is a stress
test of the learning machinery, exactly as preregistered.

## Item 2 findings — can the native system ingest text/code? (recorded)

1. **Ingress — was missing, now exists in the harness.** Before W1 the
   organism had no corpus ingress: episodes were generated in-process by a
   synthetic curriculum. Native capability IO (`nio_open_root` /
   `nio_open_child` / `nio_read_exact`) reads real files fine; W1's reader
   is 30 lines of Zag. Blocker status: resolved by this workstream for
   byte-stream ingress.
2. **Representation — still the hard blocker for any language claim.**
   Memories are i32 scalars; text has no representation in the store beyond
   integer signatures. No float path, no vocabulary, no embedding table, no
   matmul. A sequence-modeling objective cannot be expressed in the current
   organs (O2 does eliminative hypothesis logic, not prediction).
3. **Capacity — measured, with a hard wall found (see probes).** Current
   legs budget slots in tens–hundreds; W1 ran 16,384 slots cleanly. The
   audit ledger (16 words/op) and znc's 2^25 single-slice indexing limit
   are the binding constraints.

## Post-hoc scale probes (exploratory — outside the prereg verdict)

- **10x probe** (`evidence/probe_10x.txt`): 61,440 chunks (3.75 MB),
  65,536 slots, 184,322 audit entries — **PASS, 0 failed checks, 13.4 s.**
  Per-add cost grew ~3.7x vs 1x (59 µs → 218 µs): `st_add`'s linear
  free-slot scan is O(n²) and is the first soft knee.
- **~38x wall probe** (`evidence/probe_wall.txt`): 233,407 chunks
  (full Shakespeare + full sqlite3.c, 14.9 MB), 700,223 audit entries =
  45.4 MB audit buffer — **panics at store init**:
  `panic: slice index out of bounds`. The audit ledger exceeds znc's 2^25
  (33,554,432-byte) single-slice indexing limit. Ingress, K5, and fault
  injection all succeeded before the panic; the mechanism was correct up
  to the wall. **This is what breaks first: the append-only audit ledger
  hits the compiler's slice limit at ~500k ops.** Any future scale-up of
  this substrate must chunk the ledger (cf. AGENTS.md znc-limit lesson) or
  bound audit growth.
