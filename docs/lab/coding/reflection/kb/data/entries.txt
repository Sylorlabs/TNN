@L-TYPES
T:LANG
K:type,i64,u64,u8,slice,integer,void
Zag value types the learner has seen compile: i64 (signed 64-bit integer),
u64 (unsigned 64-bit), u8 (byte), i32/u32/u16 (see L-CAST-I32 before using),
[]u8 and []i64 (slices), *u8 and *T (pointers), void (no return value).
String literals like "abc" have type []u8. There is no bool type; use i64
with 1=true and 0=false. Integer literals are i64 by default; write
(108 as u8) or (n as i64) to convert. Arithmetic is two's complement
mod 2^64; there is no overflow trap.
@end
@L-SLICE
T:LANG
K:slice,index,len,subslice,element
A slice []u8 is a (pointer,length) pair. a[i] reads/writes element i,
valid for 0<=i<a.len; out-of-bounds behavior is undefined, so always
guard with explicit length checks. a[lo..hi] makes a sub-slice sharing
the same memory (no copy). a.len is the element count. Slices alias:
let b=a; b[0]=x also changes a[0]. A fresh empty slice is written "".
@end
@L-SLICE-EQ
T:LANG
K:slice,equal,compare,==,identity
== on two slices is NOT content comparison (only a==a on the same value
is true). To compare contents, loop over bytes and compare each element,
returning 0 on the first mismatch (see idiom I-S-EQ). Never use == to
choose between buffers or to test string equality.
@end
@L-SLICE-LIMIT
T:LANG
K:slice,limit,large,chunk,33554432
No single slice larger than 2^25 bytes (33,554,432) may be indexed; even
a[0] panics above that size in this znc build. Any buffer that can grow
with input (ledgers, file contents, arenas) must be chunked into pieces
each under 32MB, or the size must be capped before indexing. This is a
build limit, not a language rule; design around it.
@end
@L-STRING
T:LANG
K:string,literal,escape,newline
String literals are []u8 byte sequences. "\n" is newline, "\\" is a
backslash, "\"" is a quote. A literal may not span source lines.
_zag_arg(n) returns the program's command-line arguments as []u8
slices; _zag_arg(1) is the first user argument.
@end
@L-STRUCT
T:LANG
K:struct,field,nested,value
struct T { x:i64, b:[]u8 } declares an aggregate; T{...} builds one and
f.x reads/writes a field. Keep structs small (about 8 fields or fewer):
large structs miscompile on copy and on free. Never nest large structs
by value; decompose into parallel arrays or small structs instead.
Never free through a nested value field (see L-STRUCT-CAST).
@end
@L-STRUCT-SLICE16
T:LANG
K:struct,slice,field,16,bytes,size
A slice-typed struct field ([]u8, []i64) occupies 16 bytes (pointer plus
length), not 8. When sizing _zag_malloc for a struct, budget 16 bytes
per slice field and 8 per scalar/pointer field, with headroom. Undersizing
silently corrupts the heap and crashes far from the cause.
@end
@L-LOCAL-ALIAS
T:LANG
K:local,alias,pointer,slice,field,ZNC-004
Do not alias a slice field off a LOCAL struct value:
let p:[]u8=s.field (s a local) fails the build. Route through a pointer:
let ps:*T=&s; let p:[]u8=ps.*.field; — that form compiles and runs.
Scalar field access on a local (s.n) is fine.
@end
@L-PTR-CHAIN
T:LANG
K:chain,field,pointer,subfield,ZNC-012
Never chain field access through a pointer stored in a struct field:
w.p.n (where w.p holds &v) miscompiles and reads garbage. Always copy
to a local first: let p:*T=w.p; then use p.*.n. The store itself and the
single-load form both work; only the chained form is broken.
@end
@L-PTR-HELPER
T:LANG
K:helper,pointer,local,field,ZNC-010
.*. slice-field access through a pointer derived from &local fails the
type check with a misleading message, even though the identical access
through a *T function parameter works. Workaround: pass &local into a
helper fn that takes *T and do the field access inside the helper.
@end
@L-CAST-I32
T:LANG
K:cast,i32,u32,u16,alias,miscompile,ZNC-007
as []i32, as []u32 and as []u16 MISCOMPILE when two or more same-size
casts are allocated back-to-back (the 2nd array's first slots alias the
1st array's later slots). Never use these casts for indexed tables.
Use []u8 arenas with explicit little-endian get/put accessors instead
(see idiom I-ARENA-U8). A single as []i64 cast is not affected, but the
[]u8 form is preferred for uniformity.
@end
@L-SLICE-AS-PTR
T:LANG
K:cast,pointer,slice,data,ZNC-002
slice as *u8 does NOT yield the data pointer in this znc build; reads
return heap garbage. To get a usable pointer, allocate with
let p:*u8=_zag_malloc(n) as *u8 and build the slice view as p[0..n].
To pass a buffer to a syscall, keep the *u8 and write p as i64.
@end
@L-RETURN
T:LANG
K:return,void,semicolon
A bare return in a void fn fails to parse; always write return; with the
semicolon. Every fn declares its return type (i64, []u8, void, ...).
@end
@L-SEMICOLON
T:LANG
K:semicolon,brace,};
Never write }; — a stray semicolon after a closing brace fails the
native build with a misattributed "unknown identifier" error. Close
blocks with } alone; the following statement carries its own semicolon.
@end
@L-ARGC
T:LANG
K:argc,argv,arg,absent
The runtime passes argc=0 to main regardless of the real argument count.
Never gate _zag_arg(n) reads on argc; read unconditionally and treat ""
(empty slice) as absent. Presence test: _zag_arg(k).len>0.
@end
@L-ZARG-OWN
T:LANG
K:arg,free,owned,non-owned,memory
_zag_arg(n) returns a NON-OWNED pointer. Never free it; freeing corrupts
the allocator and crashes the next large allocation. Only free what
_zag_malloc (or _zag_i64_to_str) returned.
@end
@L-STRCMP
T:LANG
K:strcmp,equal,compare,string
_zag_strcmp(a,b) returns 1 on equality, not 0. (Reversed from the C
convention; do not port C idioms blindly.)
@end
@L-SHIFT-EXPR
T:LANG
K:shift,expression,mask,bit,ZNC-008
Do not nest (1 as i64)<<k inside a &-test expression; the build fails
with a misattributed "unknown identifier" error. Hoist the shift into a
local first: let bit:i64=(1 as i64)<<k; then test (mask&bit)!=0.
@end
@L-ELSE-NEST
T:LANG
K:else,nest,flatten,conditional,ZNC-013
Five-deep if/else nesting miscompiles in this znc build. Keep
conditional nesting shallow: flatten with early returns, helper
functions, or restructured conditions. Three levels is safe.
@end
@L-MUL-POW2
T:LANG
K:multiply,shift,power,two,ZNC-015
Avoid power-of-two multiplies (x*512, x*1024) inside large functions;
one build miscompiled (x as i64)*512 as *1024. Hoist the multiply out
of hot loops or use a non-power constant. Small test programs are not
affected, but the kb's emitters avoid the pattern everywhere.
@end
@L-IMPORT
T:LANG
K:import,path,cwd,module
"@import" must be a BARE directive (not //-commented) to take
effect; commented ones are silently ignored and cause "unknown type"
errors. Import paths resolve relative to the CURRENT WORKING DIRECTORY,
not the source file, so build scripts must run znc from the directory
the import paths are written against.
@end
@L-INIT-HEAP
T:LANG
K:heap,init,zero,sentinel,uninitialized
Uninitialized heap arrays are NOT reliably zeroed. Any array with a
sentinel convention (free slot = -1, empty = 0) must be explicitly
initialized after allocation; code that "works" on allocator luck will
break under different heap states.
@end
@L-ZALLOC-NAME
T:LANG
K:zalloc,name,collision,builtin
Never name a user function zalloc; callers get a type-mismatch error
from a suspected builtin collision. Use z_alloc / z_free / z_cstr
(underscore style) for allocation helpers.
@end
@L-SYSCALL7
T:LANG
K:syscall,args,seven,raw
_zag_raw_syscall takes EXACTLY 7 arguments: (num, a1, a2, a3, a4, a5, a6).
An 8th argument fails the build. Unused trailing arguments are 0.
@end
@L-SYSCALL-NUMS
T:LANG
K:syscall,number,read,write,open,close,flags,O_CREAT,O_TRUNC,fd
Linux x86-64 syscall numbers and open(2) flags used by kb emitters.
Paths passed to open(2) must be NUL-terminated (see idiom I-CSTR).
read=0
write=1
open=2
close=3
O_RDONLY=0
O_WRONLY=1
O_CREAT=64
O_TRUNC=512
O_WCT=577
MODE644=420
@end
@L-OPEN-EXCL
T:LANG
K:open,excl,flags,trunc,create,silent
open(2) with O_CREAT|O_EXCL fails SILENTLY on existing files (fd<0,
old content kept). When rerun output does not change, suspect the flags
first. For overwrite semantics use O_WRONLY|O_CREAT|O_TRUNC (=577).
@end
@L-GET32
T:LANG
K:get32,unsigned,sign,reader,extend
f3_get32-style readers return UNSIGNED values (0..2^32-1) with no sign
extension. Never use them where the sign matters; accumulation mod 2^32
is fine unsigned, but sign-interpreting reads need a sign-extending
variant. (Historical defect: unsigned peak reads half-wave-rectified
rendered audio.)
@end
@L-STRUCT-CAST
T:LANG
K:struct,cast,malloc,aggregate,ZNC-005
_zag_malloc(N) as *Struct fails the build for large structs ("aggregate
let needs an aggregate initializer"). Workaround: avoid the cast — use
global arrays indexed by session/test id, or split the allocation into
small structs linked by handles.
@end
@L-E0204
T:LANG
K:global,mutable,state,Cx,E0204
File-scope mutable globals are rejected by this znc build (E0204).
Thread mutable state through an explicit context pointer parameter
(*Cx); see idiom I-CX for the buffer pattern. Pure functions of their
inputs stay deterministic and testable.
@end
@L-FN-FORM
T:LANG
K:fn,main,signature,program
Every program needs fn main()void { ... }. Helper fns are top-level:
fn name(a:i64, b:[]u8)i64 { ... }. There are no nested fns, no methods,
no closures. Builtins seen in use: _zag_print([]u8), _zag_i64_to_str(i64),
_zag_arg(i64), _zag_malloc(i64), _zag_raw_syscall(...7 args...).
@end
@A-ARRAY
T:ALGO
K:array,index,loop,sequential
An array is a contiguous run of elements with O(1) indexing. The
universal traversal is i=0; while(i<n){ visit a[i]; i=i+1; }.
All kb emitters that walk argv or buffers use this form. n comes from
.len or from counting present arguments; never from a guess.
@end
@A-STACK
T:ALGO
K:stack,push,pop,lifo
A stack is last-in-first-out: push appends at top, pop removes from top.
Implement with an array plus a top index, or a linked list. Use for
undo histories, depth-first search frontiers, and nested-structure
matching (open/close pairing).
@end
@A-QUEUE
T:ALGO
K:queue,fifo,enqueue,dequeue
A queue is first-in-first-out: enqueue at the tail, dequeue from the
head. Implement with an array plus head/tail indices (circular) or two
stacks. Use for breadth-first search frontiers and work lists.
@end
@A-HASHMAP
T:ALGO
K:hash,map,table,open,addressing,lookup
A hash map gives average O(1) key lookup: hash the key to a slot, probe
on collision (open addressing: try slot+1, slot+2, ...). Initialize
every slot to a sentinel (see L-INIT-HEAP); never leave slots
uninitialized. Keys must hash deterministically — no RNG anywhere.
@end
@A-HEAP
T:ALGO
K:heap,priority,sift,top
A binary heap keeps the extreme element at index 0: sift-up on insert,
sift-down on remove-top, both O(log n). Array-represented: children of
i are 2*i+1 and 2*i+2. Use for priority scheduling and top-k selection.
@end
@A-TREE
T:ALGO
K:tree,binary,array,node
A binary tree can live in an array: node i has children 2*i+1, 2*i+2.
For pointer-scarce targets prefer this over node structs. Traversals are
iterative with an explicit stack (see A-STACK); recursion depth is
bounded by tree height only if the tree is balanced.
@end
@A-GRAPH
T:ALGO
K:graph,adjacency,edge,vertex,neighbor
Represent a graph as adjacency lists: per-vertex list of neighbor ids.
Store as one flat array plus per-vertex (start,length) pairs to avoid
nested structures (see L-STRUCT). DFS/BFS over this form need only an
explicit stack/queue and a visited bitmap.
@end
@A-SORT-INSERT
T:ALGO
K:sort,insertion,order,ascending
Insertion sort: for i=1..n-1, take a[i] and shift larger predecessors
right until its slot is found. O(n^2) worst case, O(n) on sorted input,
stable, in-place, and simple enough to verify by eye — the kb's default
sort for small n (see emitter E-SORT). For large n prefer a O(n log n)
sort; do not ship O(n^2) on unbounded input.
@end
@A-SEARCH-BINARY
T:ALGO
K:search,binary,sorted,midpoint
Binary search on a sorted array: lo=0, hi=n; while(lo<hi){ mid=(lo+hi)/2;
if(a[mid]<x){lo=mid+1;} else {hi=mid;} } then check a[lo]==x. O(log n).
Precondition: the array IS sorted — verify, do not assume.
@end
@A-DFS
T:ALGO
K:dfs,traversal,stack,graph,depth
Iterative depth-first search: push the start vertex on an explicit
stack; pop, mark visited, push unvisited neighbors. Visits every
reachable vertex exactly once. O(V+E). Use the explicit stack, not
recursion, when depth is unbounded.
@end
@A-BFS
T:ALGO
K:bfs,traversal,queue,graph,breadth
Iterative breadth-first search: enqueue the start vertex; dequeue, mark
visited, enqueue unvisited neighbors. Visits vertices in increasing
distance order, so the first visit gives shortest-path distance in
unweighted graphs. O(V+E).
@end
@A-DP
T:ALGO
K:dp,memo,dynamic,table,bottom-up
Dynamic programming: solve small subproblems first, store answers in a
table, build up. Bottom-up iteration beats top-down memoization here
(no recursion-depth worries, no hash map needed). Table dimensions come
from the input size; initialize the base row explicitly (L-INIT-HEAP).
@end
@A-FNV
T:ALGO
K:fnv,hash,64,digest,fowler
FNV-1a 64-bit: h=14695981039346656037; for each byte b:
h = (h XOR b) * 1099511628211, all mod 2^64. Deterministic,
order-sensitive, good enough for digests and hash-table keys. The empty
input hashes to the offset basis itself. See emitter E-HASH.
@end
@A-TWO-POINTER
T:ALGO
K:two,pointer,reverse,palindrome,in-place
Two-pointer technique: i at the start, j at the end, move toward each
other. Reverses an array in place with O(1) extra space (see emitter
E-STRREV); tests palindromes; partitions around a pivot. Loop while
i<j and keep the invariant explicit.
@end
@S-MEM
T:SYS
K:memory,stack,heap,layout,allocation
Stack holds call frames and locals (freed on return); heap holds
_zag_malloc results (live until freed). Zag slices may point at either.
Do not return a slice of a local buffer and use it after return. Heap
buffers shared across fns travel as []u8 with an explicit length.
@end
@S-FD
T:SYS
K:fd,file,descriptor,stdin,stdout,stderr
Unix processes talk to files via small integer descriptors: 0=stdin,
1=stdout, 2=stderr. open(2) returns a new fd >= 0, or a negative value
on failure — always check fd<0 before use. fds are per-process and must
be closed; leaking them exhausts the table on long runs.
@end
@S-FILE-LIFECYCLE
T:SYS
K:file,open,read,write,close,lifecycle
File I/O lifecycle: open path (NUL-terminated, flags from L-SYSCALL-NUMS)
-> check fd>=0 -> read/write in a loop (short counts happen; loop until
0 or target) -> close. See emitters E-FILEWRITE and E-FILEREAD for the
complete verified pattern. Never assume one read returns everything.
@end
@S-ENDIAN
T:SYS
K:endian,little,byte,word,order
x86-64 is little-endian: the least significant byte lives at the lowest
address. u8_put64 writes bytes low-to-high with (v>>(8*i))&255;
u8_get64 rebuilds low-to-high. Multi-byte values crossing slice
boundaries must use these accessors, never ad-hoc shifts.
@end
@S-DETERMINISM
T:SYS
K:deterministic,byte-identical,rerun,state
Same state in -> byte-identical out. No RNG in any decision path, no
uninitialized reads (L-INIT-HEAP), no wall-clock or address-dependent
choices. Determinism is TESTED: rerun and compare digests; a mismatch
is a defect, not noise. The kb install and every recall generation
must satisfy this.
@end
@S-RC
T:SYS
K:return,code,error,fd,negative,convention
Syscall return convention: negative means failure (see the fd from
open, the count from read/write). Check rc<0 immediately at the call
site and handle it (print a diagnostic, return;) — do not let a bad fd
flow into later syscalls. Success counts are >=0.
@end
@I-CX
T:IDIOM
K:buffer,emit,Cx,accumulate,builder
Mined from coding/src/learner.zag. The Cx pattern: struct Cx { b:[]u8,
n:i64 } with e_raw(cx,s) copying bytes into b at n. All emission goes
through one Cx, so output assembly is a pure function of calls. State
is threaded as *Cx because file-scope mutable globals are rejected
(see L-E0204).
@end
@I-S-EQ
T:IDIOM
K:compare,equal,byte,loop,s_eq
Mined from coding/src/learner.zag. s_eq(a,b): if lengths differ return
0; loop i over a.len, return 0 on first a[i]!=b[i]; return 1. The lawful
content comparison (see L-SLICE-EQ). Used for mode dispatch, id lookup,
and every equality test on []u8.
@end
@I-S-FIND
T:IDIOM
K:find,substring,search,s_find,needle
Mined from coding/src/learner.zag. s_find(hay,needle,from): scan i
from..hay.len-needle.len, inner loop over needle bytes; return first
match index or -1. O(n*m), fine at kb scale. Basis for keyword scoring
and spec parsing.
@end
@I-SPEC-KV
T:IDIOM
K:spec,kv,parse,key,value,pipe
Mined from coding/src/learner.zag. Specs are key=value pairs separated
by |. spec_kv(spec,"name=") finds the key, then reads until the next |
or end of input. The description text sits before the first |. Slot
filling reads emitter parameters from here.
@end
@I-SPLIT
T:IDIOM
K:split,parse,field,separator,token
Mined from coding/src/learner.zag. split_parse(s,arena,maxf,sep): one
pass recording (start,length) pairs into an offset table; returns the
field count. The offset-table-in-a-flat-array form avoids nested
structures (see L-STRUCT).
@end
@I-CSTR
T:IDIOM
K:cstr,nul,terminate,path,zero
NUL-termination helper: p=_zag_malloc(s.len+1) as *u8; copy s[i] into
p[i]; p[s.len]=0. Keep the *u8 (do NOT cast the slice back; see
L-SLICE-AS-PTR) and pass p as i64 to open(2). Required by every
emitter that opens a path.
@end
@I-ARGV-LOOP
T:IDIOM
K:argv,loop,arg,iterate,command
Mined from coding/src/learner.zag. k=1; while(1==1){ a=_zag_arg(k);
if(a.len==0){break;} ...; k=k+1; } — iterates all user arguments
without argc (see L-ARGC). break exits the loop; every emitted main
that takes inputs uses this form.
@end
@I-PRINT-I64
T:IDIOM
K:print,i64,str,convert,decimal
Print an integer: let t:[]u8=_zag_i64_to_str(v); _zag_print(t);
_zag_print("\n");. Bind the conversion to a let (a bare nested call
trips analyzer warning L0012). Values that may exceed i64 range are
printed as hex by hand instead (see E-HASH).
@end
@I-EMIT-MAIN
T:IDIOM
K:emit,main,program,skeleton,fn
Every emitted program has the shape: helper fns first (top-level,
see L-FN-FORM), then fn main()void { ... }. Helpers used by kb
emitters: parse_i64, u8_put64/u8_get64, hex printing. main reads inputs
via _zag_arg (see I-ARGV-LOOP), computes, prints, ends with return;.
@end
@I-ARENA-U8
T:IDIOM
K:arena,u8,offset,table,get64,put64
Offset/word tables live in []u8 arenas with explicit accessors, never
as []i32 casts (see L-CAST-I32). u8_put64(b,o,v): 8 bytes little-endian
(see S-ENDIAN). u8_get64(b,o): rebuild. One u64 per 8 bytes; table of
k entries needs 8*k bytes. The kb's own entry index uses this form.
@end

@E-ARRAYSUM

fn parse_i64(s:[]u8)i64 {
    let v:i64=0;
    let neg:i64=0;
    let i:i64=0;
    if(s.len>0){
        if(s[0]==45){neg=1;i=1;}
    }
    while(i<s.len){
        let d:i64=(s[i] as i64)-48;
        v=v*10+d;
        i=i+1;
    }
    if(neg==1){v=0-v;}
    return v;
}
fn main()void {
    let sum:i64=0;
    let k:i64=1;
    while(1==1){
        let a:[]u8=_zag_arg(k);
        if(a.len==0){break;}
        sum=sum+parse_i64(a);
        k=k+1;
    }
    let t:[]u8=_zag_i64_to_str(sum);
    _zag_print(t);
    _zag_print("\n");
    return;
}

fn u8_put64(b:[]u8, o:i64, v:i64)void {
    let i:i64=0;
    while(i<8){
        let sh:i64=i*8;
        b[o+i]=((v>>sh)&255) as u8;
        i=i+1;
    }
    return;
}
fn u8_get64(b:[]u8, o:i64)i64 {
    let v:i64=0;
