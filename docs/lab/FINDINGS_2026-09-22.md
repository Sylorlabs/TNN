## 1. Storage: the honest tradeoff (README, commit f3656c8a)

TNN is a storage eater, not a RAM or compute eater: ~220 bytes/fact
all-in (~92 fact slot + ~128 audit-ledger entry). Marginal cost is fixed:
one more fact = 220 bytes + ~6µs. Scale: 1K→220KB, 1M→220MB, 1B→220GB,
10B→2.2TB. A 70B LLM burns ~140GB of VRAM whether it knows ten facts or
ten billion; below ~150–600M facts TNN uses *less* storage than the
model's weights, above it more — but on disk at dollars a month, not in
VRAM. Caveats: the audit ledger is more than half the 220 bytes (the
price of integrity), and everything above was measured RAM-resident —
the past-RAM experiment (below) is measuring what happens past RAM.

## 3. Quality-buying — CEILING-CONFIRMED (synthesis 3314fc1f, prereg 39d4ccb6)

Does qualitatively deeper deliberation buy quality past the knee
(18/18 coding, 59/94 epistemic)? No. Five deeper forms (conflict-driven,
3-round critique, hypothesis competition, one-brain phases, combined):
zero quality gained anywhere. Lessons: the ledger is the binding
constraint, not the decision procedure — re-reading the same evidence
extracts nothing new. Critique without a justification bar is
DESTRUCTIVE: the 3-round critic flipped 47 correct items to wrong
(59→12/94). Deliberation is cheap; it just doesn't help. Standing
result: 2× deliberation + free-speed mechanisms is the whole game; new
quality needs new mechanisms or new knowledge, never more compute.

## 6. What should be tested next — Sol and Grok consulted

Micah asked Sol and Grok directly what more should be tested. Their

### Sol (gpt-5.6-sol) says:

The weakest links are likely the comparison baselines, benchmark saturation, and causal interpretation of the authority and critique results. I would run these five experiments.

### 1. End-to-end memory crossover

**Hypothesis:** TNN becomes cheaper than an LLM at roughly 150–600M facts when all operational memory is counted, not merely fact slots and audit entries.

**Exact test:**

- Implement three TNN storage modes:
  1. uncompressed,
  2. compressed,
  3. compressed with past-RAM paging.
- Count every byte required for:
  - fact slots,
  - audit ledger,
  - indexes,
  - hash tables,
  - allocator overhead,
  - loaded code/data,
  - retrieval caches,
  - page tables or external-storage metadata.
- Measure at logarithmically increasing fact counts from 10M through 2B.
- Compare against at least three LLM serving configurations:
  - weights only,
  - weights plus KV cache,
  - weights plus KV cache and retrieval/index memory.
- Measure both resident memory and latency at a fixed task-quality target.
- Repeat with the same query workload and report facts-per-second, p50/p95 latency, and total bytes.

**Kill bar:** The 150–600M crossover is killed if the fully operational TNN does not beat the smallest LLM configuration achieving the same predefined quality target by at least 2x in total memory at any point below 2B facts, or if paging makes p95 latency exceed the LLM by 10x.

This specifically tests whether the 220-byte figure is a storage figure rather than a system figure.

### 2. Authority independence and adversarial correlation

**Hypothesis:** T1 gating improves truth selection because it supplies genuinely independent authority evidence, rather than merely encoding a useful but correlated heuristic.

**Exact test:**

Construct a fact set with four source conditions:

1. one correct T1 source;
2. two independent correct sources;
3. two sources generated from the same underlying error;
4. one correct source and one confidently incorrect but higher-status source.

Randomness is prohibited, so generate the corpus from a fixed manifest and deterministic transformations. Include balanced disputes and concealed source-quality labels.

Run the system under:

- T1 only;
- T1 plus T2;
- T1 plus T2 with source independence metadata;
- T1 plus T2 where independence metadata is deliberately false.

Measure:

- accuracy,
- abstention rate,
- false-confidence rate,
- confidence calibration,
- dispute-resolution accuracy,
- performance on source-correlated errors.

Require confidence to be evaluated separately from correctness.

**Kill bar:** The authority hypothesis is killed if T1 gating fails to improve dispute accuracy by at least 10 percentage points over the ungated baseline, or if its false-confidence rate is not at least 50% lower. It is also killed if the gain disappears when source independence is controlled, or if correlated duplicate sources cause more than a 5-point increase in false confidence.

This tests whether “+78/180 disputes” and “100% to 0% false confidence” generalize beyond the current source mix.

### 3. Ceiling challenge for deliberation

**Hypothesis:** The 18/18 coding and 59/94 epistemic results represent a real quality ceiling, not a ceiling caused by benchmark saturation, leakage, or insufficiently difficult task structure.

**Exact test:**

Create a locked, previously unseen evaluation suite containing:

- multi-hop temporal facts;
- facts requiring contradiction resolution;
- facts with missing premises;
- source conflicts;
- compositional Zag programs;
- adversarially plausible but false claims;
- cases requiring explicit abstention;
- cases where a second deliberation pass can correct the first.

Freeze the corpus, scoring rules, and task ordering before running. Compare:

1. one deliberation pass;
2. two passes;
3. three passes;
4. T1-only;
5. T1 plus T2;
6. T1 plus T2 plus T3.

Use exact-match coding scores and an independently audited epistemic score. Report per-category results rather than only aggregate accuracy.

**Kill bar:** The ceiling claim is killed if any additional deliberation condition improves the locked challenge suite by at least 5 percentage points overall, or by at least 10 points in any preregistered category, without increasing false confidence or unsupported claims by more than 2 points.

A result that only improves easy cases but fails on contradiction, abstention, or temporal categories should not count as evidence of a true ceiling.

### 4. Cause of destructive critique

**Hypothesis:** Critique is destructive specifically because critique lacks a justification bar, rather than because the critique mechanism changes answer selection, introduces excessive abstention, or exposes a scoring artifact.

**Exact test:**

Use a fixed corpus and factorially vary:

- critique: off/on;
- justification requirement: off/on;
- answer revision: forbidden/allowed;
- abstention: allowed/forbidden;
- ledger evidence requirement: off/on.

Run all combinations deterministically. For each output, retain:

- original answer;
- critique;
- revised answer;
- cited ledger facts;
- justification;
- confidence;
- final score.

Score correctness, unsupported-claim rate, abstention quality, and confidence calibration. Have adjudicators classify each error as:

- critique-induced reversal;
- unsupported critique;
- failure to revise;
- unjustified abstention;
- ledger retrieval failure;
- scoring ambiguity.

**Kill bar:** The explanation is killed if adding the justification bar does not recover at least 75% of the lost quality, or if critique remains destructive even when revision is forbidden. It is also killed if the 59-to-12 degradation disappears when abstention is disabled or when the scoring rubric is corrected, indicating that the observed failure was procedural rather than epistemic.

This separates “critique is harmful” from “one particular critique-and-scoring protocol is harmful.”

### 5. Compression and deterministic replay integrity

**Hypothesis:** Compression and past-RAM storage can reduce the effective bytes-per-fact without changing answers, auditability, or byte-identical reruns.

**Exact test:**

Build a fixed corpus of at least 100M facts containing:

- repeated structures;
- near-duplicate facts;
- long audit histories;
- contradictory facts;
- rare exceptional records;
- malformed or boundary-case records.

For each compression configuration:

1. ingest the corpus;
2. serialize the complete memory;
3. replay a fixed query and update trace;
4. compare all outputs and resulting memory bytes against the uncompressed reference;
5. restart from every checkpoint and replay again;
6. corrupt one compressed block at a time and verify detection and containment.

Record:

- bytes per fact;
- compression and decompression time;
- query latency;
- update latency;
- hash equality;
- detected corruption rate;
- affected-query scope.

**Kill bar:** The compression hypothesis is killed if any valid input produces a different answer, audit record, or final byte hash from the reference; if any undetected corruption changes a result; or if compression reduces storage by less than 25% while increasing p95 query latency by more than 3x.

The byte-hash requirement matters here: semantic equivalence alone is insufficient under the standing determinism law.
