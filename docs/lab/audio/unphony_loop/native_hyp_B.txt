## 0. Definitions (so the debate has a clean seam)

The pipeline is plan-then-render. The SEAM is drawn here, and this is the
only seam the experiment in §3 is allowed to touch:

- PLAN = everything symbolic and event-level: the note/event sequence,
  pitches, onset times, durations, per-note dynamics parameters, phrase
  structure, rubato curves, articulation flags. If it can be written as a
  list of timed events with parameters, it is plan.
- RENDER = everything that turns the plan into samples: the physical
  source model (or lack of one), per-note waveform generation, attack
  envelopes, spectral evolution over a note's life, breath/string/room
  components, mixing. If it touches a sample value, it is render.

Consequence: a note with an instantaneous attack and zero release is a
RENDER defect if the renderer generates the waveform, but a PLAN defect if
the plan hardcodes attack=0/release=0 per event. The experiment must
therefore ship each plan with an explicit, frozen event schema (pitch,
onset, dur, vel, attack_ms, release_ms, vib_depth, vib_rate, brightness)
so blame cannot slide across the seam after the fact.

## PART 1 — plan-vs-render

### 1A. The strongest case that the PLAN is phony

TNN's imagination of the scene is acoustically wrong. The renderer's job is
only to realize the plan; it cannot fix a plan that describes a scene no
human performer would ever produce.

Mechanism 1 — event structure pathology. Real music is not a list of
isolated note objects. Real notes overlap: the decay of note N is still
audible under the attack of note N+1, string/body resonances persist
across phrase boundaries, and phrase-level energy has an arch (rise,
climax, release). If TNN's plan emits non-overlapping quantized note
events with hard on/off boundaries — the natural output of a
sequence-model imagination — then the rendered scene is a row of
disconnected acoustic objects. That sounds exactly like "phony": each
object is fine, the SCENE is fake. Killer: measure inter-onset interval
(IOI) distributions and note-overlap fraction in the plan vs. a
real-anchor-derived event plan (measurement-only). If TNN's plan has
overlap fraction < 0.05 while the real plan has > 0.35, the plan is
scene-deaf.

Mechanism 2 — dynamics pathology. TNN likely plans velocity as a
per-note scalar drawn from a narrow range (or constant), because its
training signal is note-identity, not expression. Real performances have
phrase-level dynamics with 6–12 dB of contrast between phrase peak and
trough, and brightness coupled to loudness. A flat-velocity plan renders
as emotionally dead even through a perfect physical renderer. Killer:
compare the plan's velocity histogram (mean, std, max-min range) against
real-anchor measured per-note RMS. If TNN's plan std < 3 dB while real
is > 8 dB, the plan cannot produce a living phrase.

Mechanism 3 — temporal statistics pathology. TNN's plan timing likely
comes from a metronomic grid (or the AR drift process: recurrence 0.74).
Real rubato is not noise on a grid — it is systematic: phrase-final
lengthening, agogic accents on structural beats, 30–80 ms of expressive
timing deviation correlated with dynamics. If the plan's IOI coefficient
of variation is either ~0 (grid) or uncorrelated noise (AR drift), the
timing will read as machine. Killer: correlate per-note timing deviation
with per-note dynamics in the plan; real music shows r > 0.3
(slower+louder at phrase peaks). If TNN's plan shows r ≈ 0, its timing
is decorative, not expressive.

Mechanism 4 — the strongest version of the plan case. The AR-vs-PAR
evidence does NOT exonerate the plan. Both renders were judged "same
horrible," and both plans came from the same generator family. If the
phoniness lives at the single-EVENT level of the plan (every note event
carries wrong attack_ms, zero release_ms, flat vel — i.e., the plan's
event schema is impoverished), then both AR and PAR plans are identically
defective at event granularity and recurrence drift is irrelevant.
"Same horrible" is exactly what you expect when two plans share an
impoverished event schema. Killer for this whole section: §3.

### 1B. The strongest case that the RENDER is phony

The plan could be musically perfect and the bytes would still sound
horrible, because the renderer has no physical source model. This is the
V11 mechanism, and it generalizes: ARTIC had correct F0 (385 Hz) but 0%
formant frames (real: 30%) and HNR 0.5 dB (real: 4.5 dB); PARADD was
additive sines with no vocal-tract model; SPECSTAT was filtered noise
with no glottal source. The common defect is renderer-side: pitch exists,
physics doesn't.

Mechanism 1 — static timbre stasis. A renderer that generates each note
as a fixed harmonic stack (or a single looping sample) produces notes
whose spectrum does not evolve: centroid pinned, no formant drift, no
brightness attack bloom. Real notes are spectrally alive: the attack is
noisier than the sustain (ZCR ratio > 1.5), the centroid tracks dynamics
(r > 0.5), formants move. A human ear reads static timbre as "synthesizer
demo" — i.e., phony — within one note, regardless of what the plan says.
Killer: these are all renderer-measurable on a SINGLE isolated note, with
no plan information at all. If one rendered note already fails the
discriminator (§4), the plan never gets a vote.

Mechanism 2 — missing excitation physics. Real instrumental tone =
excitation (breath, bow, hammer, pluck) × resonator (body, bore, string).
Current renders plausibly synthesize the resonator's steady state (the
harmonic stack) with no excitation component: no breath noise under a
flute note, no bow scratch at a string attack, no hammer thump. The ear
is an excitation detector — we hear the CAUSE, not the spectrum. Missing
excitation = "nobody is playing this" = phony. Killer: band-limited
noise energy in the 2–6 kHz region during the first 30 ms of each note
(real: present, 10–20 dB below the tonal peak; current renders:
absent or white).

Mechanism 3 — missing space. Real recordings have a room: early
reflections within 20–80 ms, exponential tail after note offsets. A
renderer that outputs dry notes with hard digital silence between them
produces a scene no physical room could contain. The ear reads this as
"rendered in a void" — phony. Killer: measure post-offset decay slope;
real shows −60 to −10 dB/s tails, renders show a cliff.

Mechanism 4 — why the render case survives the AR/PAR evidence better
than the plan case. The judges heard "same horrible" for recurrence 1.00
and 0.74. A plan-side timing defect predicts a DIFFERENT flavor of
horror when timing changes (grid-horror vs drift-horror). A renderer-side
timbre defect predicts EXACTLY what was heard: every note is the same
kind of phony, so the clip is the same kind of horrible regardless of
note order or timing. "1=same as 3, slightly different" is the signature
of identical broken timbre carrying different note sequences.

### 1C. The decisive experiment (2×2 factorial, one build, one run)

Build the four cells. No new hypotheses until this is read out.

PLAN dimension (frozen event schema: pitch, onset_ms, dur_ms, vel_dB,
attack_ms, release_ms, vib_depth_cents, vib_rate_hz, brightness_01):
- P_TNN: the plan from TNN's current motif generator, re-emitted into
  the frozen schema with its native parameters (the plan that produced
  the horrible clips, as faithfully as the schema allows).
- P_HUMAN: a human-composed deterministic plan for the same motif
  length and pitch content — same note sequence, but with authored
  phrase arch (vel ±6 dB across the phrase), rubato (phrase-final
  lengthening 1.15×, agogic accents), note overlap (legato overlap
  40–80 ms), per-note attack_ms 15–60, release_ms 80–200. Authored once,
  committed, byte-frozen. This is NOT derived from any anchor
  (measurement-only license stays clean); it is composed from musical
  first principles.

RENDER dimension:
- R_CUR: the current deterministic renderer, byte-identical to the one
  that produced the judged clips.
- R_PHYS: a new pure-Zag deterministic renderer implementing the
  minimal physical source model: per-note excitation (band-limited
  deterministic noise burst at attack, 20 ms, level tied to vel) +
  resonator (time-varying formant filter bank, 3 formants, formant
  frequencies gliding 5–10% over the note) + room (deterministic
  early-reflection comb, RT60 0.4 s exponential tail). Zero RNG:
  excitation noise from a hash stream (SHA-256 counter mode) seeded by
  note index — deterministic, byte-identical reruns. No real samples.

Four renders: A=(P_TNN,R_CUR) baseline, B=(P_HUMAN,R_CUR),
C=(P_TNN,R_PHYS), D=(P_HUMAN,R_PHYS). All 44.1 kHz mono 16-bit WAV,
same length ±0.5 s.

Measurement: the frozen discriminator from Part 2, scored per cell
(pass/fail on every bar), plus a blind ABX of each cell vs the
motif-class real anchor (judge must argue FOR real before rejecting,
per UNPHONY_BAR_V1 §4).

Decision rule (committed before the run):
- If B passes (bars + near-chance ABX) and C fails → PLAN dominates.
- If C passes and B fails → RENDER dominates.
- If only D passes → both are necessary; the debate's framing was
  incomplete and the loop tests plan-render co-design next.
- If D still fails every bar → both hypotheses are wrong about the
  mechanism; the phoniness is neither the event plan nor the
  source model (suspect: the motif CONTENT itself — TNN imagining
  melodies no human would write — or the discriminator is measuring
  the wrong thing). Report exhaustion honestly per bar §7(c).
- Partial-pass tiebreak: count bars passed. If B and C both partially
  pass, the one with strictly more bars passed names the dominant side;
  exact tie → both necessary.

Falsifiability: the experiment can kill both of my cases. If
(P_HUMAN,R_CUR) passes, my committed render-side position (§1D) is
dead and I concede the plan case.

Cost control: R_PHYS is the only new build. P_HUMAN is ~2 hours of
composition. R_CUR and P_TNN already exist. One experiment, four cells,
no loop iteration needed to read the answer.

### 1D. Commitment: RENDER dominates

I commit to the render side. Reasons, in order of force:

1. The V11 mechanism is renderer-side and mechanism-specific: pitch
   without a physical source model sounds phony (0% formant frames,
   HNR 0.5 dB, no glottal source). The motif renders come from the
   same generator lineage and the judges' description ("horrible"
   independent of recurrence) matches a per-note timbre pathology,
   not an event-structure pathology.
2. The single-note killer (§1B, Mechanism 1): if one isolated rendered
   note already fails the discriminator, no plan can save the clip.
   Plan defects need a sequence to manifest; timbre defects manifest
   in 200 ms. The judges needed no long listening to say "horrible."
3. "Same-but-slightly-different" (clip 3 vs 1) is the fingerprint of
   identical broken timbre + different note content. Plan-side timing
   horror should have changed flavor between recurrence 1.00 and 0.74;
   it did not.
4. Asymmetry of the fix: a physical source model (excitation ×
   resonator × room) is a bounded, well-understood build. A "correct
   imagination of musical scenes" is an open research problem. The
   loop should spend its budget where the mechanism is known.

What would change my mind: the §1C readout, specifically
(P_HUMAN,R_CUR) passing while (P_TNN,R_PHYS) fails. Also, if the
single-note discriminator test shows current renders' isolated notes
scoring INSIDE real variance — then timbre is exonerated and the plan
case wins by elimination.

## PART 2 — frozen discriminator design (motif/instrumental class)

### 2A. Design principles

- Every feature computable deterministically from 44.1 kHz mono
  16-bit WAV in pure Zag: integer/fixed-point FFT (radix-2, 32-bit
  fixed point, twiddle table precomputed deterministically),
  autocorrelation via direct sums, LPC via Levinson-Durbin in fixed
  point. No floats at the bar level; measurements reported as
  integer milli-units (milli-dB, milli-Hz) so bars are exact.
- Bars are RANGES within real-anchor variance, never thresholds tuned
  on renders. Each bar: [lo, hi] from the anchor + a same-class second
  real recording (variance floor). A fork passes a bar iff its value
  falls inside.
- The discriminator reports per-feature pass/fail AND a summary
  (bars passed / total). Prong 1 requires ALL bars passed.
- Determinism gate: running the instrument twice on the same file
  must produce byte-identical measurement vectors. Tested in CI
  before freezing.

### 2B. The feature list (8 features, exact recipes)

Notation: x[n] 16-bit samples, Fs=44100. All windows Hann (fixed-point
table). "Frame" = windowed segment; hop sizes below.

F1 — Median voiced HNR (harmonics-to-noise ratio).
  Recipe: 4096-sample frames, hop 1024. Per frame: normalized
  autocorrelation r[tau] for tau in [88, 882] (lags for 50–500 Hz).
  If max r < 0.30 → unvoiced, skip. Else HNR_frame =
  1000 * log10(r_max / (1 - r_max)) milli-dB (integer log10 via
  table). F1 = median of HNR_frame over voiced frames.
  Real anchor prediction: 5000–20000 milli-dB (5–20 dB), sustained
  pitched notes are harmonic but breathy/noisy.
  Current renders prediction: EITHER < 2000 (noisy renders like
  SPECSTAT-lineage: r_max ≈ 0.5 → HNR ≈ 0 dB) OR > 30000 (pure
  additive sines: r_max → 0.999+ → HNR > 30 dB). Both miss the band.
  Killer: a render that lands inside [5000,20000] by mixing noise
  into sines at the right ratio — caught by F2/F5 below. No single
  feature decides; the BAND decides.

F2 — Formant-frame fraction.
  Recipe: 2048-sample frames, hop 1024, only frames passing F1's
  voicing test. LPC order 12 via fixed-point Levinson-Durbin; find
  pole pairs with bandwidth < 400 Hz and center 200–3500 Hz
  (formant-like). Frame counts if ≥ 2 formant-like poles.
  F2 = 1000 * (formant frames) / (voiced frames) (per-mille).
  Real prediction: > 250 per-mille (resonant bodies/bores impose
  formants on most voiced frames).
  Current renders prediction: < 50 per-mille (V11 measured 0–3%).
  Killer: a renderer could fake this with a static 2-formant filter —
  caught by F5 (formant MOTION): real formants glide.

F3 — Spectral centroid mean and normalized dispersion.
  Recipe: 4096-sample frames, hop 2048, magnitude spectrum via
  fixed-point FFT. centroid_frame = sum(k * |X[k]|) / sum(|X[k]|),
  in Hz (k * Fs/4096). Over all frames with RMS above −40 dBFS:
  F3a = mean centroid (Hz, integer), F3b = 1000 * std / mean
  (per-mille normalized dispersion).
  Real prediction: F3a in 800–3500 Hz (instrument-dependent; frozen
  per anchor class), F3b > 150 per-mille (timbre breathes with
  phrasing — attacks brighter, releases darker).
  Current renders prediction: F3b < 40 per-mille (static harmonic
  stack; nothing ever changes). This is the "timbre stasis" bar.
  Killer: a render with fake brightness LFO would raise F3b — caught
  by F6 (brightness must CORRELATE with dynamics, not wobble freely).

F4 — Attack noise vs sustain tone contrast (ZCR ratio).
  Recipe: onset detection first (see F7). For each detected onset at
  sample n0: attack window = [n0, n0+1323] (30 ms), sustain window =
  [n0+22050, n0+30870] (500–700 ms post-onset, only if no new onset
  inside). ZCR = zero-crossing count per window, normalized per
  1000 samples. F4 = 1000 * median(attack ZCR) / median(sustain ZCR)
  (per-mille ratio).
  Real prediction: > 1500 (attacks are noisy: bow, breath, hammer).
  Current renders prediction: 900–1100 (attack is just the tone
  starting — same texture throughout).
  Killer: adding a click at every onset fakes high ZCR — caught by
  F5 (clicks have no formant structure) and F8 (click decay is
  instant, not exponential).

F5 — Formant glide (spectral motion within notes).
  Recipe: on voiced frames from F2, take the lowest formant-like pole
  center frequency f1_frame. For each note region (between onsets,
  ≥ 300 ms long): glide = 1000 * (max f1 − min f1) / mean f1
  (per-mille). F5 = median glide over note regions.
  Real prediction: > 60 per-mille (embouchure/bow/finger motion moves
  resonances continuously).
  Current renders prediction: < 15 per-mille (static filter or static
  additive stack).
  Killer: random formant jitter would pass — but jitter fails F1's
  voicing stability and sounds like vibrato-abuse to ears (Prong 2
  catches what the bars miss; ears outrank metrics).

F6 — Brightness–dynamics coupling.
  Recipe: 2048-sample frames, hop 1024. Per frame: centroid (as F3)
  and RMS_dB (20*log10 RMS, milli-dB). Over 2-second blocks with
  ≥ 6 dB RMS range: r = Pearson correlation (fixed-point) of
  centroid vs RMS_dB. F6 = 1000 * median r over blocks.
  Real prediction: > 400 (louder = brighter: harder bowing, more
  breath pressure excite more highs).
  Current renders prediction: −100 to +100 (static timbre
  independent of the plan's dynamics — or brightness INVERTED if a
  naive lowpass "expression" filter is used).
  Killer: a renderer could fake this with a dynamics-driven lowpass —
  but a static lowpass moves centroid WITHOUT moving formants,
  failing F2/F5; and ears hear filter-sweep as phony (Prong 2).

F7 — Inter-onset-interval regularity (plan-side feature — included
  deliberately: the discriminator must ALSO catch plan phoniness, or
  the §1C experiment's B cell could pass on timbre while sounding
  metronomic-dead).
  Recipe: onset detection via spectral flux: 1024-sample frames, hop
  256; flux = sum over k of max(0, |X_t[k]| − |X_{t−1}[k]|);
  onset where flux > 3× the 1-second trailing median AND
  high-frequency content (4–10 kHz energy) rises. IOI = gaps between
  onsets in ms; keep IOIs in [120, 4000] ms. F7 = 1000 * std/mean
  of IOIs (per-mille CV).
  Real prediction: 150–600 per-mille (human timing breathes; phrase
  structure spreads IOIs).
  Current renders prediction: EITHER < 50 (metronomic grid plan) OR
  uncorrelated with dynamics (AR-drift timing: CV may be high but
  random — see F7b).
  F7b (companion): 1000 * Pearson r between per-note timing
  deviation (IOI − local median IOI) and per-note peak RMS_dB.
  Real prediction: > 250 (agogic accents: structural notes are
  longer AND louder). Grid/drift plans: |r| < 100.
  Killer: a plan could fake F7 with random timing jitter — F7b
  requires the jitter to be MUSICALLY correlated, which random
  jitter cannot fake.

F8 — Post-offset decay slope (room/body resonance tail).
  Recipe: note offsets = onset positions advanced by the plan's
  dur_ms is NOT available to the instrument (it measures audio
  only) — so: detect offsets as frames where RMS drops > 12 dB
  within 100 ms and stays low ≥ 200 ms. Tail window = [offset,
  offset+22050] (500 ms). Fit log-RMS slope by least squares
  (fixed-point). F8 = fraction of offsets (per-mille) whose slope
  lies in [−60000, −10000] milli-dB/s (−60 to −10 dB/s:
  exponential physical decay).
  Real prediction: > 500 per-mille (rooms and bodies ring).
  Current renders prediction: < 100 per-mille (hard digital
  silence: slope ≈ −∞ or 0).
  Killer: a renderer could add a fixed exponential tail to every
  note — caught by F8b: TAIL VARIANCE. Real tails vary with pitch
  and dynamics (low notes ring longer); require std of decay time
  across offsets > 15% of the mean. Fixed tails have ~0 variance.

### 2D. Red-team calibration traps (the discriminator must earn its teeth)

Each trap is a WAV the discriminator scores BEFORE any fork is judged.
A trap failure (wrong side) blocks freezing — the instrument is not
frozen until all traps behave.

MUST-SCORE-REAL traps (prove it doesn't call everything phony):
- T1: two DIFFERENT real recordings of the motif class (anchor A and
  a second real performance B, different performer/piece, same
  class). Both must land inside EVERY bar. If B fails, the bars are
  overfit to anchor A — widen to real variance, never narrow to a
  recording.
- T2: anchor A with 1-LSB deterministic dither added (byte-level
  perturbation). Measurement vector must be BIT-IDENTICAL to anchor
  A's (proves determinism and noise-floor robustness, not
  hypersensitivity).
- T3: anchor A truncated to the first 50% vs the second 50%. Both
  halves must pass (proves the bars capture stationary class
  properties, not one lucky passage).

MUST-SCORE-PHONY traps (prove it catches known phonies):
- T4: additive-sine resynthesis of anchor A's measured F0 contour
  (correct pitch track, static harmonic stack, no formants, no
  excitation). Must FAIL F2, F4, F5 at minimum. This is the V11
  pathology in pure form — the single most important trap.
- T5: metronomic sine-note grid playing anchor A's note sequence
  (perfect timing, dead timbre). Must FAIL F2, F3b, F4, F6, F8.
  Catches "fix the plan, keep the broken renderer" forks.
- T6: white noise shaped to anchor A's long-term spectrum at
  anchor A's RMS. Must FAIL F1 (no voicing → no voiced frames →
  F1 undefined → scored as fail), F2, F7 (no onsets). Catches
  SPECSTAT-lineage renders.
- T7: anchor A's note sequence rendered with CORRECT timbre model
  but with every attack replaced by a 2 ms click and every tail
  hard-cut. Must FAIL F4 (click texture ≠ excitation noise:
  ZCR ratio goes the wrong way — clicks are TOO high-frequency)
  and F8. Catches naive "add transients" patches.
- T8: the CURRENT horrible TNN renders (ar_motif.wav etc.). Must
  fail a MAJORITY of bars. If the current clips pass, the
  discriminator is decorative and the loop must not use it.
  (Negative control — the most embarrassing trap to fail.)

ADVERSARIAL near-miss traps (prove resistance to feature gaming):
- T9: T4 + shaped noise mixed to land F1 inside the real band
  (HNR gaming). Must STILL fail via F2/F5 (noise has no formants).
  Proves no single feature is load-bearing.
- T10: T5 with a dynamics-driven lowpass filter (fake F6 coupling).
  Must STILL fail via F2/F5 (filter sweep moves centroid without
  moving formants) — and note for the record that filter-sweep
  phoniness is Prong 2's job.
- T11: concatenative Frankenstein — 200 ms grains of REAL anchor
  audio crossfaded into a sequence (internal red-team probe only;
  anchor material never ships in a fork). Must FAIL F8b (grain
  boundaries break natural tail variance) and F7b (grain order
  destroys timing–dynamics correlation). Proves the discriminator
  is not fooled by real timbre in a fake sequence. (License note:
  T11 uses anchor audio as an INTERNAL attack probe, never as
  render source; it is deleted after the trap run and its bytes
  never enter any fork.)

Trap verdict rule: all 11 traps must behave as specified before the
instrument freezes. Any trap misbehaving → fix the feature recipe,
re-run all traps, re-freeze. The frozen instrument ships with its
trap log.

### 2E. What the discriminator deliberately does NOT measure

- Absolute pitch accuracy / tuning: a detuned-but-real performance
  is real; phoniness is not wrong notes.
- Recurrence/drift: killed as a hypothesis by the AR/PAR evidence;
  measuring it would resurrect a dead hypothesis.
- Stereo image, loudness (LUFS), mastering: production choices, not
  reality signatures. A mono 16-bit anchor-derived band keeps the
  instrument honest.
- Genre/style: the bars are per anchor CLASS (motif/instrumental),
  frozen in the addendum per §2 of UNPHONY_BAR_V1.

### 2F. Freezing procedure (addendum, before first fork judged)

1. Select motif-class real anchors (anchor A + second real B).
2. Run instrument on A, B, A-halves → set each bar [lo,hi] to cover
   observed real variance with 20% margin, never narrower than the
   two-recording spread.
3. Run all 11 traps → all must behave.
4. Commit instrument source + measurements + trap log + bar values
   with Micah-visible version tag. Frozen. Amendments need his
   sign-off (V2).

## 3. Open questions for the debate (do not build until argued)

1. Is R_PHYS's hash-stream excitation "zero randomness"? Yes by the
   program's law: deterministic given state (note index seed),
   byte-identical reruns. But the debate should confirm no one
   reads "noise burst" as banned stochasticity — it is a
   deterministic signal, like a wavetable.
2. Should P_HUMAN be composed by a human or by TNN under a
   "compose expressively" instruction? If TNN composes it, the
   experiment tests TNN's planning ceiling, not the plan/render
   seam. For THIS experiment, human-composed: the question is
   whether ANY good plan saves R_CUR, not whether TNN can write one.
   TNN-composed expressive plans are a follow-up loop.
3. F7/F7b assume onset detection works on the renders. If R_CUR's
   onsets are undetectable mush, F7 scores "fail" for the wrong
   reason — log onset counts per file and require ≥ 60% of planned
   onsets detected, else mark F7 INCONCLUSIVE rather than fail.

## 4. Bottom line

The plan case is real and the §1C experiment can prove it — I am not
smuggling the conclusion. But the mechanism-specific evidence (V11:
pitch without source model; judges: identical horror across
recurrence 1.00 and 0.74; "same-but-slightly-different" as the
fingerprint of shared broken timbre) points at the RENDER. The
discriminator is built to catch exactly that: eight features, every
one a physical-model signature, every one with a named trap that
kills it if it goes soft.
