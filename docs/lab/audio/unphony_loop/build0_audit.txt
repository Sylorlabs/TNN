## VERDICT: NARROW-BUG (found, one line, in both forks)

The vibrato depth is computed 2*pi (6.28x) too large. Every motif note
(plan: 5.5 Hz, +/-15 cents) actually renders with a +/-95-cent pitch wobble
at 5.5 Hz — modulation index m = 4.37 rad — which nulls the carrier
(Bessel J0(4.37) ~= -0.33) and smears each partial into ~13 sidebands
spanning +/-36 Hz. The result is a seasick wobbling tone with no stable
pitch center: measured note "pitch" lands on the upper sideband lobe
(~+4% sharp), and autocorrelation-based HNR collapses because the
waveform never repeats cleanly. This single bug explains the measured
inharmonicity, the ~+4% sharp readings, and the horrible/phony percept.
The grand theories (missing physical source model etc.) are premature:
fix this line first, re-render, re-measure.

## 2. Render path summary (what it actually synthesizes)

- Plan parse: BED/EVENT/RESPOND lines; EVENT fields t0,dur,freq,amp(0-1000),
  timbre(harmonic count 1..13),glide,vib_hz,vib_cents. amp Q: (q16*65536)/1000
  bug and unnormalized harmonic stack were already fixed per FINDINGS.md
  (both WAV-invisible after peak normalization anyway).
- Voice: sum over h=1..timbre of (1/h)*sin(2*pi*h*phase), normalized by
  sum(1/h) so voice peak ~= plan amp. Sine via 1024-entry LUT from a
  Taylor fsin_q (error ~3e-6 — fine).
- Phase: PAR absolute per sample ph=((f0q*tr)/SR)*65536 (Q32 cycles);
  AR carried ph+=inc, inc=(fq*65536)/SR. Harmonic LUT index
  ((ph*h)/4194304)&1023 — exact integer harmonic ratios h*f0 (verified).
- Envelope: 40 ms raised-cosine attack / 150 ms release, capped at dur/2 —
  verified 0 -> full -> 0, no clicks.
- Vibrato: phase modulation, phase += vbeta*sin(vibrato_phase),
  vbeta = beta*2^32 with beta = df/vibhz, df = f0*(2^(vibc/1200)-1).
  AR additionally scales vbeta by the output-servo vibmul (0.5..1.5).
- Bed: 110 Hz, 3 harmonics, no vibrato, 25 ms edge fades.
- Mix: plain sum into i64 Q16 buffer. WAV writer: global peak normalize
  to 0.85 FS (v*27852/peak). No other mastering.

## 4. The bug (mechanism)

File/line (identical in both forks):
- fork_par/src/render_par.zag:207:  `if (vibhz > 0.001) { beta = df / vibhz; }`
- fork_ar/src/render_ar.zag:223:    `if (vibhz > 0.001) { beta = df / vibhz; }`
- (hybrid/src/render_hyb.zag:240 — same line, same bug)

The render implements vibrato as PHASE modulation in units of cycles:
  phase(t) = f0*t + beta*sin(2*pi*fv*t)      [cycles]
so the true peak frequency deviation is
  dF = beta * 2*pi * fv                      [Hz]
To obtain the planned deviation df (= f0*(2^(cents/1200)-1)), beta must be
df/(2*pi*fv). The code sets beta = df/fv — missing the 2*pi.

Consequences for the motif (fv=5.5 Hz, 15 cents, f0=440):
- intended: +/-3.83 Hz (+/-15 cents), modulation index m = 2*pi*beta = 0.70 rad
- actual:   +/-24.1 Hz (+/-95 cents), modulation index m = 4.37 rad
- m=4.37 rad nulls the carrier (J0(4.37) ~= -0.33); energy moves into
  ~13 Bessel sidebands at 5.5 Hz spacing spanning +/-36 Hz per partial.
- measured spectrum of the rendered 440 Hz note: broad two-lobed hump
  410-480 Hz with a DIP at the 440 Hz carrier; peak reads 455-458 Hz
  (the upper sideband lobe), i.e. ~+4% "sharp".
- AR's servo multiplies vbeta by vibmul (up to 1.5), deepening AR's
  vibrato further — consistent with AR measuring worse than PAR
  (HNR -2.0 vs -0.5 dB, centroid 2269 vs 1556 Hz).

  (1.032-1.041x); ar_motif.wav notes +3.9..+6.7% sharp — the sideband
  lobe, not the plan pitch. The bed (no vibrato) is exact at 110 Hz.

## 6. Minimal fix

One line per fork (diff in build0_fix.diff, NOT applied):
  beta = df / vibhz   ->   beta = df / (6.283185307179586 * vibhz)
i.e. convert the planned frequency deviation to a phase deviation in
cycles correctly. No other code changes: the PM application
`ph = ph + (vbeta * vs) / 32768` is correct once beta is.
