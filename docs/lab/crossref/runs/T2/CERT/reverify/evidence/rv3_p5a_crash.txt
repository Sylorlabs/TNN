## White-box root cause

thincert_orig.zag lines 763-765 declare the manifest tables as THREE CONSECUTIVE
SAME-SIZE `as []i32` casts (512 bytes = 128 i32 each):
  let mtier:[]i32=mtierr as []i32;
  let moff:[]i32=moffr as []i32;
  let mlen:[]i32=mlenr as []i32;
This is the exact ZNC-2026-09-21-007 trigger pattern. Minimal probe on the pinned
toolchain (alias_probe2.zag, buildable + runnable, in evidence):
  b[0..2] read as 1065,1066,1067 == a[65..67]; clobbering a[65..67] to 111,222,333
  makes b[0..2] read 111,222,333.
=> the 2nd/3rd cast's slots 0-2 alias the previous array's slots 65-67
   (OFFSET IS LAYOUT-DEPENDENT: the 2026-09-21 probe saw 9-11; this build sees 65-67).
Consequence for thincert_old: moff[0..2] read mtier[65..67], mlen[0..2] read moff[65..67].
At N<=65 those slots are uninitialized heap (historical verdicts survived by allocator
luck — zeroed pages); at N>=66 they hold live tier/offset values and the binary
deterministically corrupts its heap ("invalid or double free").
thincert_new's mechanical arena transform (t_put32/t_get32 over []u8) eliminates the
pattern structurally: immune at all sizes tested (128 entries PASS).

Same pattern also present in thincert_old's walk tables (foff/flen, lines 849-850)
and import tables (coff/clen, lines 652-653).

## Additional boundary notes (both instruments agree)

- Empty (0-byte) module attests PASS on thincert (vacuous pass), FAIL on rngscan
  (vendored_ok=false). Both instruments deterministic and agreeing.
- Module at exactly 4194304 bytes (4MB read cap): PASS both. At 4194305: R1 FAIL both.
- Binary at 33554431 bytes: R7 "binary unreadable" on BOTH (single 33MB read fails
  in the substrate); at 33554432: same. Agreement, not a pass — boundary semantics
  identical across instruments.
- Missing manifest -> both exit 2 (usage-IO error), no attestation. Missing module /
  missing evidence / truncated evidence / runs=7 / byte_identical=0 / malformed
  manifest line -> FAIL on both, byte-identical attestations.
