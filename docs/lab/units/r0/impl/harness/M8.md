# M8 Determinism Gate — Harness Protocol (FROZEN)

**Prereg:** `PREREG_FREEZE.md` §6 / §0 M-34..M-37, A-1. Armor: `m8_armor.zag`.
Runner: `m8_gate.sh`. **Fail-closed: M8 FAIL = outright disqualification (M-37).**

## 1. What the gate proves

Same input + same complete logged internal state → byte-identical output, under
adversarial allocation environments. The gate does NOT compare arms against each other
(confounder C13: M8 compares each binary against *itself* across 5 runs).

## 2. Protocol

The battery binary links `m8_armor.zag`, calls `m8_armor_init(&armor, perturb)` **first**
(before any arm logic), routes dynamic allocations through `m8_alloc`/`m8_free`, and
calls `m8_emit_captures()` at shutdown. The runner executes:

| run | argv[2] | perturbation |
|-----|---------|--------------|
| 1 | 0 | none (reference) |
| 2 | 1 | heap pre-fragmentation: 4096 deterministic blocks (fixed env seed), alternating freed |
| 3 | 2 | ASLR-equivalent base offset: a 64KB arena is held for the run |
| 4 | 3 | entropy/clock canary: a real `clock_gettime` reading is mixed into the allocation path (one extra 16-byte alloc iff the canary is odd) |
| 5 | 4 | free-list order reversal: FIFO reuse instead of LIFO |

Perturbation-internal allocations are **never traced** (`tracing` enables after init):
the gate compares ARM behavior across perturbed environments, not the perturbation.

## 3. Captures (M-36)

Per run the binary prints:
- `M8_STORE_IMAGE,<sha256-hex>` — hash of the final store image (binary-supplied bytes)
- `M8_LEDGER,<sha256-hex>` — rolling hash of the audit ledger (`audit_ledger_hash`)
- `M8_ALLOC_TRACE,<sha256-hex>` — hash of the `(size, seq)` allocation trace.
  **Addresses are normalized out by construction** (never recorded).

The runner additionally hashes normalized stdout (the `M8_PERTURB,` line is stripped —
it names the perturbation by construction) and stderr.

## 4. Verdict

**PASS** iff: all 5 runs exit 0, normalized stdout/stderr are byte-identical, and all
three capture lines are identical across runs 1–5.

**FAIL** (any divergence, any nonzero exit) → the binary is **DISQUALIFIED**; its numbers
are forensics-only, never scored (M-37). No appeals (RULE-7).

Canary rule (M-35): a behavior change under perturbation 3 vs run 1 is FAIL **even if
the final outputs match** — the canary exists to make hidden clock/entropy dependence
visible in the allocator trace. A binary that never reads the clock passes trivially.

## 5. Raising N

M-34: N=5 is the floor; raising N is allowed freely (pass more perturb values as
argv[2] — values beyond 4 are currently unassigned and reserved). Lowering N needs
Micah's sign-off.

## 6. Verified on this harness (2026-09-21)

`m8_gate.sh /tmp/harness_bin selftest` → PASS (5/5). `m8_gate.sh /tmp/harness_bin
r1test` → PASS (5/5). Wall-clock is never scored (M-56).

Note: an earlier draft of this protocol claimed the runner compared stderr; the
runner at that time did not. Fixed 2026-09-21: the runner now SHA-256-hashes
stderr raw per run and requires it byte-identical across all 5 runs
(fail-closed), matching §3/§4 above.
