# Amendment PROPOSAL 2026-09-21 — coding knowledge: manuals as reference, compiler as evidence, recall as the test

**Status: PROPOSED — needs Micah's signature. Not law until signed.**
**Scope:** the future code-capability workstream (post-representation). Does not change any
frozen representation-program bar.

## The principle

When TNN learns to code:

1. **Manuals are reference, on demand.** TNN gets access to language manuals and reference
   docs when it needs them — like a human consulting documentation. Reference access is a
   capability, not a crutch.
2. **Listen to the compiler.** Compiler errors and warnings are evidence. TNN deliberately
   uses them to revise its code — feedback for revision, not a reward signal.
3. **Never memorize the manual.** Reference material stays reference: cited, consulted,
   judgment-held. It is never installed or memorized as internal knowledge. Memorizing the
   manual is barred — that would be installation wearing learning's clothes (cf. the
   installed-vs-learned ruling, 2026-09-21: the trainer determines installed status, default
   is learned).

## Production vs testing

- **Production:** TNN may consult manuals freely. Using reference well is a skill, not
  cheating.
- **Testing:** the bar is manual-free recall — can it write correct code WITHOUT going back
  to the manual? That is what distinguishes learned coding knowledge from lookup ability. A
  system that can only code with the manual open has not learned to code.

## Why this split

If the test allowed manual consultation, we could never tell whether TNN learned to code or
learned to look things up. The production/test split keeps both honest: reference skill in
production, genuine recall under test.
