# U4 — CLASSES (manual excerpt; source: handbook/2/classes.html)

## Fields
- class Point { x: number; y: number; }
- Initializers run at construction: class Point { x = 0; y = 0; }  // inferred number
- --strictPropertyInitialization: every field needs an initializer OR assignment
  in the constructor, else TS2564: "Property 'name' has no initializer and is
  not definitely assigned in the constructor."
- Escape hatch: name!: string;  // definite assignment assertion — "trust me, it
  gets assigned" (handbook: use when an external library fills the field in).

## Constructors
- constructor(x = 0, y = 0) { this.x = x; this.y = y; }
- No type parameters on constructors; no return-type annotations.
- Derived classes: call super() BEFORE touching this.

## Methods
- scale(n: number): void { this.x *= n; this.y *= n; }
- Inside methods, fields are ALWAYS accessed via this. — bare `x` means the
  enclosing scope, not the field.

## readonly
- readonly name: string = "world"; — assignable only in the constructor.

## implements
- interface Pingable { ping(): void; }
- class Sonar implements Pingable { ping() { console.log("ping!"); } }
- implements CHECKS the class against the interface but does NOT change how the
  class body is inferred: method params still need their own annotations
  (TS7006 bites here: check(s) with implements Checkable still errors).
- A class may implement multiple interfaces: class C implements A, B {}

## extends
- class Dog extends Animal { woof(times: number) { ... } }
- Override must respect the base contract; use super.method() to call up.

## Getters/setters
- get length() { return this._length; } / set length(v: number) { ... }
- get-only accessor => property is readonly.
- Setter param type inferred from getter return type.

## Common errors
- TS2564 no-initializer (fix: initializer, constructor assignment, or !).
- TS2540 cannot assign to readonly.
- TS2420 class incorrectly implements interface.
- TS17009 super must be called before accessing this.
