# U5 — GENERICS (manual excerpt; sources: handbook/2/generics.html, handbook/2/functions.html)

## Why
- Reusable components over many types WITHOUT losing type info (any loses it).
- function identity<Type>(arg: Type): Type { return arg; }
- Type variable (type parameter) declared in < > after the function name.
- Call with explicit arg: identity<string>("hi"); or let TS infer: identity("hi").

## Rules for good generics
- Use the type parameter itself, not a constraint, when possible.
- Fewer type parameters is better.
- A type parameter should appear at least TWICE (relating two values); one use
  means you probably don't need generics.

## Using type variables in the body
- The compiler treats Type as ANY possible type: you may only use operations
  valid for all types.
- function loggingIdentity<Type>(arg: Type) { arg.length } // ERROR TS2339:
  Property 'length' does not exist on type 'Type'.
- Fix by constraining: function loggingIdentity<Type extends { length: number }>
  (arg: Type): Type { ... } — now .length is legal.

## Constraints
- <Type extends Lengthwise> — Type must have at least those members.
- getProperty<Type, Key extends keyof Type>(obj: Type, key: Key) { return obj[key]; }
- keyof T = union of T's property names.

## Generic interfaces and classes
- interface Box<Type> { value: Type; }
- class GenericNumber<NumType> { zeroValue: NumType; add: (x: NumType, y: NumType) => NumType; }
- let n = new GenericNumber<number>(); — type argument on the CLASS.
- Generic classes are generic over the INSTANCE side only; statics can't use it.

## Generic function types
- let myIdentity: <Type>(arg: Type) => Type = identity;
- interface GenericIdentityFn { <Type>(arg: Type): Type; }  // generic call signature

## Common errors
- TS2339 using members not on the unconstrained type variable.
- TS2322 returning a value of the constraint type where Type is promised.
