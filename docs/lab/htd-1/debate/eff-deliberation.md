# HTD-1 DEBATE — Deliberation Economy (eff-deliberation)

**Status:** DEBATE phase only. Nothing here is built. These hypotheses are proposed for preregistration and head-to-head testing.

**Standing constraints carried in:** pure Zag; zero randomness in any decision path (byte-identical reruns: same input + same logged state → byte-identical output); preregister with kill bars before building; test head-to-head, never minimize; evidence committed to `docs/lab/htd-1/` on the tnn-native-lab branch. Deterministic ordering everywhere: episode counters and slot indices, never wall-clock, never addresses, never hash-map iteration order. Audit entry layout (fixed, 16 words): op@0, slot@4, rc@8, b1..b5@12..28, a1..a5@32..48, stage@52, d1@56, d2@60.

**Shared proxy corpora (read in place, never copied):** `~/workspace/tnn-lab/corpora/pg100.txt` (5.6MB Shakespeare), `~/workspace/tnn-lab/corpora/sqlite3.c` (9.5MB C).

**Slice boundary (do not duplicate siblings):** this slice is the deliberation *process* being cheaper per thought — fewer expansions, shorter verifications, reused deliberations. Sparse routing (which subsystems wake) belongs to the E-SP* slice; ledger/IO write economy belongs to E-LG*. Overlap rule: if a saving comes from not waking a subsystem → E-SP; from writing fewer bytes → E-LG; from thinking fewer, shallower, or cheaper thoughts with the same awake machinery → here (E-DE*).

## Why this slice matters

Micah's question 1 for HTD-1: "Human brains took the free lunch" — ~20W, sparse activation. How far can deliberate efficiency go in TNN? TNN already has the expensive parts proven real: deliberate memory ops, eliminative hypothesis logic, deliberative refusal at 100% over 2,595 temptations. But every one of those is currently run at full cost, every time. This slice asks whether deliberation itself can be economized — bounded, truncated, deferred, or reused — without reintroducing the thoughtlessness the program was built to escape. Every hypothesis below must clear two gates at once: a CORRECTNESS gate (economy must not buy speed with wrongness — measured against the full-deliberation baseline, not against vibes) and a SAVINGS gate (measured in deterministic Zag-instrumented op counts, per the metrics referee's primary metric).

## Shared baseline: FULL-DELIB (what every hypothesis must beat)

The current native deliberation pipeline with no economy: for each task item, expand ALL candidate hypotheses to a fixed preregistered depth, gather ALL evidence in a fixed canonical order, run ALL verification checks, no caching, no budgets, no early exit. Outcome = the survivor set after full eliminative logic; ties broken by lowest hypothesis id (preregistered tiebreak rule). Every hypothesis below is scored as (outcome agreement with FULL-DELIB, deliberation ops vs FULL-DELIB) on identical items.

Deliberation-op taxonomy (fixed for HTD-1 prereg): one op = one hypothesis expansion, one evidence-gather call, or one verification check. All arms instrument the same three counters; shifting work into an uncounted category is cheating and fails the replay bar.

## Shared proxy tasks

**D-P1 "Playwright's desk" (pg100.txt):** 600 passages (200–400 chars, byte offsets fixed in the prereg file). Task: attribute each passage to one of 4 candidate plays (the hypothesis set). Evidence: deterministic feature extractors (fixed function-word list, line-length stats, speaker-tag presence — all rule lists frozen in the prereg). Eliminative logic: hypotheses eliminated by preregistered feature thresholds.

**D-P2 "Code cartographer" (sqlite3.c):** 600 function definitions (byte offsets fixed in prereg). Task: classify each into one of 8 subsystems {btree, pager, os, vdbe, parser, util, mem, other}. Evidence: identifier stems and called-function names from deterministic scans. Same eliminative structure as D-P1.

**D-P3 "Adversarial gauntlet" (synthetic, generated by a fixed Zag generator committed in the prereg):** hypothesis sets of size 4–16 with evidence streams in three fixed orderings — favorable (decisive evidence first), canonical (fixed neutral order), adversarial (decisive evidence last). Tests whether economy savings survive hostile ordering and whether correctness holds under it.

**Shared metrics:** (a) outcome agreement with FULL-DELIB (%, per task); (b) mean deliberation ops vs FULL-DELIB on identical items (saving %); (c) byte-identical replay from the ledger (pass/fail, zero tolerance).

## Hypothesis E-DE1 — "Task-class deliberation budgets" (depth gating)

**Mechanism sketch.**
Deliberation is recursive hypothesis expansion, and today it expands until the evidence runs out. E-DE1 caps it: every task instance carries a task class (e.g., `CLASSIFY_SNIPPET`, `ATTRIBUTE_PASSAGE`, `REVISE_MEMORY`); a fixed preregistered table maps class → (max expansion depth, max evidence-gather rounds). At episode open the deliberator loads the budget into counters; the expander loop refuses to expand past it *by construction* (`depth < budget[class]`, checked in the loop guard, not as an afterthought). If the budget exhausts with no single survivor, the system does not guess — it writes a `BUDGET_EXHAUSTED` entry and either refuses the decision or petitions for a larger budget (a deliberate, ledgered act with its own evidence, not a silent override). The saving happens in the expander: deep, expensive branches that routine tasks never need are never built.
*What could go wrong:* the budget table is a guess about the world — too low and routine items refuse or decide wrong; task-class misclassification assigns the wrong budget. The escalation path can also become a loophole if "petition for more" fires constantly (then the budget is fiction).
*Ledger recording:* the episode-open entry carries (class id, budget-table version, depth cap, round cap); every expansion entry carries its depth; a `BUDGET_EXHAUSTED` entry carries the live-hypothesis count at exhaustion. Replay replays the identical loop guard against the identical table → byte-identical.

**Falsifiable predictions.**
- P1: ≥95% of D-P1/D-P2 items resolve within their class budget (no `BUDGET_EXHAUSTED`).
- P2: Outcome agreement with FULL-DELIB ≥98% on both corpora.
- P3: Mean depth actually used correlates with task class, not with evidence arrival order (budgets do the work, not luck).

**KILL BARS (any one firing kills E-DE1).**
- KB1 (correctness): outcome differs from FULL-DELIB on >2% of items on either D-P1 or D-P2 (n≥600 each) → KILL.
- KB2 (savings): mean deliberation-op saving <15% vs FULL-DELIB across D-P1+D-P2 → KILL.
- KB3 (budget integrity): `BUDGET_EXHAUSTED` fires on >10% of items on either corpus → KILL (the table is fiction; escalation is the real mechanism).
- KB4 (replay): any rerun from the same logged state diverges by one byte → KILL (program law).

**Proxy task + metric:** D-P1 + D-P2. Metric: outcome-agreement % and mean op saving % vs FULL-DELIB on identical items; budget-exhaustion rate as a diagnostic.

**Must face head-to-head:** FULL-DELIB (the bar); E-DE2 (depth-cap saving vs evidence-driven saving — which generalizes?); D-P3 adversarial ordering (tests whether the cap is load-bearing or just lucky about evidence order); a "flat budget" arm (one depth cap for all classes — tests whether task-classing earns its keep).

## Hypothesis E-DE2 — "Early exit on single survivor" (sufficiency certificate)

**Mechanism sketch.**
Eliminative logic already narrows the hypothesis set; today the deliberator keeps expanding anyway. E-DE2 stops the moment the live set has exactly one survivor: it emits a `SUFFICIENCY_CERTIFICATE` entry listing the survivor, every eliminated hypothesis, the evidence id that eliminated each one, and the elimination rule applied. The certificate is the audit trail of the deliberation that did *not* happen — it says "here is why no further thought was needed." The saving happens in the expander/verifier: all remaining depth and all ungathered evidence are skipped. Replay feeds the logged evidence in the logged order through the same eliminative rules and must arrive at the same single survivor — the certificate makes the shortcut checkable.
*What could go wrong:* premature exit. Evidence that would have revived an eliminated hypothesis (or split the survivor) may sit ungathered later in the stream — exit is ordering-dependent. Two sub-arms: (a) naive exit on |live|==1; (b) revival-guarded exit, which additionally requires a preregistered monotonicity check (no remaining evidence *type* in the task's evidence plan can revive an eliminated hypothesis — declared per task class in the prereg). The head-to-head between (a) and (b) decides whether the guard earns its cost.
*Ledger recording:* certificate entry carries (survivor id, per-eliminated-hypothesis (evidence id, rule id) pairs, evidence-consumed count, guard verdict for arm (b)). Short-circuit is fully replayable from the certificate.

**Falsifiable predictions.**
- P1: Median exit depth is <50% of FULL-DELIB's fixed depth on D-P1/D-P2.
- P2: Arm (a) and arm (b) agree with FULL-DELIB ≥98% on canonical evidence ordering; on D-P3 adversarial ordering, arm (a) diverges measurably more than arm (b).
- P3: Every emitted certificate replays to its survivor (100% — construction claim).

**KILL BARS.**
- KB1 (correctness): outcome differs from FULL-DELIB on >2% of items on D-P1/D-P2 canonical ordering → KILL (both arms; arm (a) additionally killed if it diverges >5% on D-P3 adversarial ordering while arm (b) stays ≤2% — the naive variant is then proven unsafe).
- KB2 (savings): mean op saving <15% vs FULL-DELIB → KILL.
- KB3 (certificate integrity): any certificate that fails to replay to its recorded survivor → KILL (program-law level; the shortcut is unauditable).
- KB4 (replay): any byte divergence on rerun → KILL.

**Proxy task + metric:** D-P1 + D-P2 (canonical order) plus D-P3 all three orderings. Metric: outcome agreement %, mean op saving %, exit-depth distribution.

**Must face head-to-head:** FULL-DELIB; E-DE1 (which cap generalizes better — depth or evidence?); arm (a) vs arm (b) (the guard's price vs its protection); D-P3 adversarial ordering (the load-bearing test for any early-exit claim).

## Hypothesis E-DE3 — "Lazy verification with verification debt"

**Mechanism sketch.**
Full deliberation currently verifies everything: every elimination's evidence is provenance-checked, every commitment's premises re-verified. E-DE3 splits verification into *load-bearing* (needed to select the outcome — always executed now) and *archival* (provenance re-checks, cross-corroborations — deferred). The outcome commits with a `VERIFICATION_DEBT` entry: an IOU listing each deferred check, the evidence it covers, and its trigger condition. Triggers are demand-driven and preregistered: the debt settles when (i) another deliberation consumes this outcome as evidence, (ii) an explicit confidence query arrives, or (iii) a scheduled audit sweep runs. A debted outcome used as evidence forces settlement first — consumption without settlement is a ledger-level violation, checked in the consumer's guard. The saving happens in the verifier: archival checks that nobody ever demands are never run. Outstanding debt per episode is capped (preregistered cap); exceeding the cap forces immediate settlement (graceful fallback to full verification, not silent accumulation).
*What could go wrong:* misclassification — a check labeled archival that was actually load-bearing produces a wrong outcome that the debt never catches (until something consumes it). Debt can also accumulate across episodes into an audit backlog nobody scheduled.
*Ledger recording:* `VERIFICATION_DEBT` entries carry (check id, evidence id, trigger condition, episode id); `DEBT_SETTLED` entries carry the check outcome; every evidence-consumption entry references the settlement it depended on. Replay replays debts as pending and forces the same settlement order → byte-identical.

**Falsifiable predictions.**
- P1: ≥60% of verification ops on D-P1/D-P2 are classified archival and deferred.
- P2: <20% of issued debts settle before run end (most deferred work is pure saving, not delayed work).
- P3: Outcome agreement with FULL-DELIB ≥98% — the load-bearing/archival split is sound.

**KILL BARS.**
- KB1 (correctness): any settled debt whose check overturns the committed outcome counts as a divergence; divergences >2% of items on either corpus → KILL. (This is the bar that catches load-bearing misclassification.)
- KB2 (savings): mean op saving <15% vs FULL-DELIB → KILL.
- KB3 (debt integrity): any outcome consumed as evidence without its debt settled → KILL (hard zero-tolerance; the laziness violated its own contract). Any episode exceeding the debt cap without forced settlement → KILL.
- KB4 (replay): any byte divergence on rerun → KILL.

**Proxy task + metric:** D-P2 (verification = identifier-provenance re-checks, call-site cross-references — the richest verification workload) + D-P1. Metric: outcome agreement %, mean op saving %, debt-settlement rate, overturn-on-settlement count (must be zero-ish).

**Must face head-to-head:** FULL-DELIB; E-DE5 (both shrink verification work — deferral vs narrowing — which is safer per op saved?); trigger-sensitivity arms (aggressive vs conservative load-bearing classification — the classification itself is the experiment); a "debt-cap=0" arm (sanity: must reproduce FULL-DELIB exactly, byte-identical — validates the instrumentation).

## Hypothesis E-DE4 — "Deliberation memoization" (cache keyed by input-hash + relevant-state-hash)

**Mechanism sketch.**
Long runs deliberate the same thing repeatedly. E-DE4 caches deliberation outcomes: at episode open, compute H(canonical input record) and H(relevant state slice); on key hit, the recorded outcome and its certificate are replayed from the log *without re-running expansion* — but the episode still writes a `CACHE_HIT` entry pointing at the originating episode id, so the shortcut is auditable and the ledger stays complete. The byte-identical law is satisfied by construction: the original deliberation was deterministic, and the keyed material is exactly its inputs, so same key → byte-identical outcome. The load-bearing design decision is *relevant-state scoping*: hashing all of memory kills the hit rate; each task class preregisters the exact state partitions relevant to it, and only those are hashed. A miss (state changed → hash differs) is always safe; a false hit (over-broad relevance declaration reusing an outcome whose real inputs differed) is the catastrophic failure mode.
*What could go wrong:* relevance declarations are guesses — too narrow and the hit rate is zero (no saving, pure hashing overhead); too broad and false hits silently reuse wrong outcomes. Staleness is safe by construction (hash mismatch → miss), but declaration error is not.
*Ledger recording:* `CACHE_HIT` entries carry (key = input-hash + state-hash, originating episode id, relevance-declaration version). Replay looks up the same key in the same log → identical outcome.

**Falsifiable predictions.**
- P1: On D-P1/D-P2 with natural duplicates (Shakespeare repeats lines; sqlite3.c repeats idioms) plus injected near-duplicates, hit rate ≥30% with a preregistered narrow relevance declaration.
- P2: False-hit rate is exactly 0 by construction across all runs — any nonzero false hit falsifies the relevance declaration, not just the run.
- P3: Every `CACHE_HIT` replay is byte-identical to the originating episode's outcome.

**KILL BARS.**
- KB1 (correctness): ANY false hit — a cache-hit outcome differing from what FULL-DELIB would produce on that item — → KILL. Zero tolerance; this is a soundness bar, not a rate bar. (A single false hit proves the relevance declaration unsound.)
- KB2 (savings): mean op saving <15% vs FULL-DELIB, OR hit rate <10% on the duplicate-enriched workload → KILL (the cache doesn't earn its hashing overhead).
- KB3 (replay): any `CACHE_HIT` replay diverging from its originating episode → KILL.
- KB4 (hostile): on a hostile arm of inputs crafted to collide on input-hash while differing in relevant state, any hit (rather than miss) → KILL.

**Proxy task + metric:** D-P1/D-P2 on duplicate-enriched item sets (natural + injected near-duplicates, duplicates flagged in the prereg so hit-rate denominators are honest) + the hostile-collision arm. Metric: hit rate, false-hit count (must be 0), mean op saving %, replay identity.

**Must face head-to-head:** FULL-DELIB; relevance-scoping arms (narrow vs broad partition lists — the scoping decision is the experiment); E-DE1 (both bound work per item — which scales better as the run lengthens and duplicates accumulate?); the hostile-collision arm (mandatory safety case).

## Hypothesis E-DE5 — "Proposal-first deliberation" (cheap heuristic proposes; full deliberation verifies; the heuristic never decides alone)

**Mechanism sketch.**
A cheap deterministic heuristic — a fixed feature-weight table, preregistered and frozen for the run (no learning, no adaptation) — produces a *proposal*: a ranked guess at the outcome. Deliberation then verifies the proposal FIRST instead of expanding all hypotheses blindly. Two sub-arms, tested head-to-head: (a) *verify-proposal-only* — run the full eliminative checks against the top proposal; if it survives its own checks, accept, skipping the alternatives; (b) *proposal-ordered elimination* — check the proposal first, then eliminate the alternatives against the same evidence (full rigor, saving comes only from early pruning when the proposal is right). The heuristic's output is NEVER committed as a decision — it only reorders verification; the ledger records (proposal, heuristic version, verification sequence, accept/reject with reason). The saving happens in the expander: in the best case O(verify-one) instead of O(expand-all); in the worst case (proposal rejected) the cost is full deliberation + the heuristic's cost, so the heuristic's op budget is capped in the prereg (≤5% of a full deliberation).
*What could go wrong:* a systematically bad heuristic always falls back — pure overhead, no saving (the savings bar catches this). Arm (a)'s risk: accepting a proposal that survives its own checks while an unexamined alternative would also have survived — the acceptance check must be as rigorous as baseline elimination for the survivor, which is exactly what the correctness bar tests.
*Ledger recording:* episode entries carry (heuristic id + version, proposal ranking, per-proposal verification outcomes, accept/reject reason code, fallback flag). Replay replays the identical proposal and verification order → byte-identical.

**Falsifiable predictions.**
- P1: The frozen heuristic's top-1 proposal matches FULL-DELIB's outcome on ≥85% of D-P1/D-P2 items (it must be decent to be worth consulting).
- P2: Arm (a) saves strictly more ops than arm (b), but diverges from baseline strictly more — the head-to-head quantifies the price of the stronger shortcut.
- P3: On a deliberately degraded-heuristic arm, both sub-arms fall back gracefully: savings → ~0 (plus bounded overhead), correctness stays within bar.

**KILL BARS.**
- KB1 (correctness): outcome differs from FULL-DELIB on >2% of items → KILL (per sub-arm; arm (a) must additionally beat arm (b) on savings to justify its existence — if (a) saves no more than (b), (a) is killed as pointless risk).
- KB2 (savings): mean op saving <15% vs FULL-DELIB → KILL.
- KB3 (heuristic cheapness): proposal op cost >5% of a mean full deliberation → KILL (it was supposed to be cheap; an expensive heuristic is just deliberation with extra steps).
- KB4 (replay): any byte divergence on rerun → KILL.

**Proxy task + metric:** D-P1 + D-P2 (both sub-arms) + degraded-heuristic arm. Metric: outcome agreement %, mean op saving %, fallback rate, heuristic op cost as % of full deliberation.

**Must face head-to-head:** FULL-DELIB; arm (a) vs arm (b) (the price of the stronger shortcut, measured); E-DE2 (evidence-driven early exit vs guess-driven proposal — which trigger is more reliable?); degraded-heuristic arm (graceful-fallback test); a "random-proposal" control arm (proposals from a fixed arbitrary order — must show the heuristic earns its keep vs a dumb ordering).

## Required composition arm (not a hypothesis — a measurement)

Economy mechanisms may compose or collide. Required: **E-DE2+E-DE4 stack** (early exit inside each deliberation, memoization across deliberations) vs FULL-DELIB and vs each alone on D-P1/D-P2. Predictions: savings sub-additive (memoized hits skip deliberations that early exit would have shortened anyway); correctness bar identical (≤2% divergence). If the stack diverges more than either alone, the interaction is unsafe and both hypotheses carry a "do not compose" annotation in the prereg. A second composition probe, E-DE1+E-DE3 (budget cap + lazy verification), is optional if build bandwidth allows.

## Standing kill bars (apply to every E-DE* hypothesis)

- **SKB-REPLAY:** any rerun from the same logged state diverging by a single byte → the hypothesis is dead, no appeal (program law).
- **SKB-AUDIT:** any shortcut taken without a ledger entry that fully accounts for it (budget cap, certificate, debt IOU, cache-hit pointer, proposal record) → dead. A skipped deliberation must be replayable and attributable, always.
- **SKB-ORDER:** any use of wall-clock time, memory addresses, or hash-map iteration order in a decision path → dead on detection.
- **SKB-SIBLING:** any saving that turns out to come from sparse routing (not waking machinery) or from writing fewer ledger bytes rather than from cheaper deliberation → reclassified out of this slice, not counted toward any E-DE savings bar.

## Steelman: the strongest objection to deliberation economy

TNN's entire identity is deliberateness — every store a commit, every claim eliminable, every refusal deliberate. Economizing deliberation risks reintroducing exactly the thoughtlessness the program was built to escape: a system that is formally deliberate but practically thoughtless, where budgets, certificates, and debt IOUs become ritual paperwork stamped around decisions that were never really considered. The felt-intensity trial already demonstrated this failure shape — the machinery was clean, but the harness evicted memories before the feeling was ever consulted, so 15,000 valid readings changed nothing. A deliberation budget that is always exhausted, a sufficiency certificate that is always issued, a heuristic that is always "verified" would be the same structural fraud: the *form* of thought without the *act*. Worse, the no-randomness law forces every shortcut to be perfectly auditable, and audit machinery has its own cost — the economy could easily spend more on proving it thought than thinking would have cost. And the honest reading of the 20W brain is not "think less" but "think only about what matters" — no budget table or frozen heuristic knows what matters in advance. This objection is load-bearing, and it is why every hypothesis above carries a correctness bar measured against full deliberation rather than against ground truth: the claim is never "cheaper and still right," it is the stricter "cheaper and *the same thought*." Any hypothesis that buys speed with even 2% of wrongness dies — and if all five die, that is itself a result: deliberation, done honestly, may simply cost what it costs.
