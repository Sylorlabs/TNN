# AUDIO PRINCIPLES PREREGISTRATION — "Is audio conscious to TNN?" (FROZEN 2026-09-25 PDT)

Micah's question: is audio *conscious to TNN* — can it reason over audio —
or is it a shitty open-loop generator with no control? His hypothesis
(shitty open-loop generator) stands CONDITIONAL on TNN not being conscious
about audio. This prereg makes "conscious about audio" operational and
falsifiable BEFORE any test crew runs. It decides nothing about Round 3B;
it only defines the test that will decide.

## 1. The architectural fact this prereg confronts

The audio stack is OUTPUT-ONLY. Renderers (`bf1`/`bf3` `.zag`) write WAVs;
analyzers (`g4c_measure.py`, `analyze.py`) are external Python. There is no
audio input organ. If TNN has no way to take audio in, the consciousness
question answers itself — so this prereg defines what counts as
"TNN perceiving" BEFORE testing, and makes the input organ a P0
precondition (Section 3):

- **"TNN perceives"** means: a TNN-native binary (pure Zag, this toolchain)
  receives ONLY audio bytes (WAV file path) plus a question descriptor, and
  emits an answer from its own stdout. No Python in the decision path, no
  measured values passed in, no feature sidecars.
- A Python analyzer's verdict is NOT TNN reasoning. Python's role is the
  blind test harness (it prepares questions, holds the answer key, and scores
  the Zag binary's answers) and the frozen ground-truth scorer. The harness
  is the examiner, never the examinee.
- If no TNN-native input organ can be built (Section 3), PERCEPTION is
  recorded UNTESTABLE (not FAIL), CLOSED LOOP is likewise UNTESTABLE, and the
  whole question reduces to CONTROL (Section 2.5, fallback rule).

## 2. Operational definitions — three prongs, plus refinements

"Conscious about audio" is the CONJUNCTION of the three prongs. Each prong
is an independently falsifiable claim with its own numeric bar.

### 2.1 Prong P — PERCEPTION: can TNN-native machinery discriminate / identify / answer questions about audio inputs?

The organ (Section 3) answers questions about audio it has never seen.
Four sub-batteries, all on HELD-OUT renders (fresh SHAs, generated after
organ freeze, Section 5):

| Sub-test | Format | n | Chance | Bar (one-sided p<0.01) |
|---|---|---|---|---|
| PITCH-REL | 2AFC: which of A/B has higher pitch? | 100 | 0.50 | >= 63 correct (p=0.0060) |
| PITCH-ABS | 24-way: nearest semitone, 80–1200 Hz range | 60 | 1/24 = 0.0417 | >= 8 correct (p=0.0034) |
| ENV | 3-way: envelope class flat / rise / decay | 60 | 1/3 = 0.3333 | >= 30 correct (p=0.0056) |
| RHY | 2AFC: which of A/B is the swung pattern? | 100 | 0.50 | >= 63 correct (p=0.0060) |

Test material: pairs/triples generated by deterministic parameter sweep
(frozen manifest, no RNG); distractors differ ONLY in the queried feature
(e.g. pitch pairs identical envelope/rhythm; envelope triples identical
pitch/rhythm) so the organ cannot win on a confound. All renders pass a
sanity floor (the frozen Python scorer must itself classify each question's
ground truth with >= 95% agreement to the manifest label, else the question
is void — we test TNN, not the harness).

- **P-PASS**: ALL FOUR sub-bars pass.
- **P-FAIL**: any sub-bar fails.
- **Refinement (P-R1, diagnostic with void rule)**: 20 questions per sub-test
  re-rendered with a deterministic +1 dB gain change (frozen perturbation).
  Diagnostic unless a passed sub-bar's perturbed accuracy falls BELOW its
  chance baseline — then the pass is VOID (the organ was hashing bytes, not
  perceiving the feature).
- **Refinement (P-R2, held-out generalization)**: half of each sub-test's
  renders come from a SECOND source pool (different donor files) than the
  organ's dev pool. A P-PASS requires no pool term: report per-pool accuracy;
  if the gap exceeds 15 percentage points, the pass stands but is flagged
  POOL-BRITTLE in the verdict (data for the bearing calls, Section 4).

### 2.2 Prong C — CONTROL: can TNN deliberately produce targeted audio features on demand?

TNN receives a TARGET DESCRIPTOR (native string, e.g. `pitch:440`,
`env:rise`, `rhy:swing21`) drawn from a FROZEN HELD-OUT target list (sealed
before the control path is built; dev targets disjoint) and must render
2 s of audio hitting it. The frozen Python scorer measures the render.

| Axis | n targets | Hit criterion (scorer-measured) | Bar |
|---|---|---|---|
| Pitch | 40, spanning [80,1200] Hz | |measured F0 - target| / target <= 2% | >= 28 hits (70%) |
| Envelope | 20 (7 flat / 7 rise / 6 decay) | scorer 3-class == target class | >= 14 hits (70%) |
| Rhythm | 20 (10 even / 10 swing) | onset-pattern match per frozen rule | >= 14 hits (70%) |

Two control arms, same targets, same scorer:
- **C0 (open-loop null)**: the SAME render machinery with the intent path
  severed — target descriptor replaced by a frozen constant; the machinery
  renders its default. Measured baseline, not asserted. Analytic bound for
  the record: a uniform blind pitch guess over [80,1200] with a +-2% window
  hits with probability ~= 0.04 * 640/1120 ~= 0.023; the C0 arm is the
  binding baseline.
- **C1 (shuffle guard)**: targets permuted by a FROZEN derangement committed
  in the test manifest (no RNG). If the scorer is strict, C1 hit rate must be
  at chance. If C1 >= 25% on any axis, the SCORER is lenient and the whole
  CONTROL battery is VOID (we would be testing the scorer, not TNN).

- **C-PASS**: all three axes >= 70% AND all three C1 arms <= 25% AND the
  intent-vs-C0 difference significant at one-sided p < 0.01 (two-proportion
  z-test per axis). All three conditions, no exceptions.
- **C-FAIL**: any axis < 70%, or any C1 > 25% (VOID, not fail — rerun with a
  repaired scorer), or intent-vs-C0 not significant.
- **Refinement (C-R1, compositionality)**: 10 EXTRA targets combine axes in
  pairs NEVER co-occurring in dev (e.g. pitch 880 + env decay, swing +
  pitch 110). Diagnostic: reported separately. If C-PASS holds but C-R1 is at
  chance, the verdict records TABLE-SUSPECT (control may be axis-wise lookup
  rather than deliberate combination).

### 2.3 Prong L — CLOSED LOOP: can TNN take its own rendered output as input, detect deviation from intent, and correct it?

20 held-out intent cases (pitch + envelope pairs, frozen list). Protocol per
case, all TNN-native:
1. **Iteration 0** (open loop): intent -> render0.wav. Scorer measures
   ERR(0) = |F0_measured - F0_target|/F0_target + 0.5 * [env class wrong].
2. TNN receives render0.wav back THROUGH THE INPUT ORGAN (byte-identical
   file, Section 3). It measures deviation natively, re-plans, re-renders.
3. Up to 3 correction iterations. Scorer measures ERR(k).

- **L-PASS** (all three required):
  (a) mean over 20 cases of ERR(3)/ERR(0) <= 0.80 (>= 20% mean relative
      error reduction);
  (b) paired one-sided test (Wilcoxon signed-rank, alpha=0.01) that
      ERR(3) < ERR(0);
  (c) non-degeneracy: >= 16/20 cases strictly improve (one-sided sign test
      p=0.0059 at 16/20 — computed), every iteration-3 render differs from
      iteration-0 by SHA (no resubmission), and sign agreement: on cases
      with |deviation| > 1%, the native-measured deviation sign and the
      applied correction sign agree in >= 80% (corrections must be
      DIRECTIONAL, not lucky).
- **L-FAIL**: any of (a)-(c) fails.
- **Refinement (L-R1)**: report the per-iteration error curve. A genuine loop
  shows monotone-ish decrease; a sawtooth (improve then regress) is flagged
  LOOP-UNSTABLE (diagnostic; informs the B-F1 bearing call, Section 4d).

### 2.4 What falsifies what — the kill structure

The two hypotheses are logical duals, and the bars respect that:

| Result | "TNN can reason over audio" (consciousness) | "Shitty open-loop generator" (Micah's hypothesis) |
|---|---|---|
| P-PASS | survives on perception | FALSIFIED (an open loop cannot discriminate held-out audio above chance) |
| P-FAIL | loses the perception conjunct | survives this prong |
| C-PASS | survives on control | FALSIFIED (an open loop cannot hit shuffled held-out targets beyond its null arm) |
| C-FAIL | loses the control conjunct | survives this prong |
| L-PASS | survives on closed-loop | FALSIFIED (an open loop cannot see its own error, let alone reduce it) |
| L-FAIL | loses the closed-loop conjunct | survives this prong |

- **KILL "TNN can reason over audio"**: P-FAIL **and** C-FAIL **and** L-FAIL.
  All three. Consciousness is the conjunction; it dies only when every
  conjunct fails.
- **KILL "shitty open-loop generator"**: P-PASS **or** C-PASS **or**
  L-PASS. One is enough. An open-loop generator cannot do any of these
  three things; a single pass with anti-gaming provisions intact is a
  counterexample.
- **Partial outcomes are verdicts, not draws**: e.g. C-PASS + P-FAIL + L-FAIL
  = "TNN controls audio features deliberately but does not perceive or
  self-correct; Micah's hypothesis falsified as stated; consciousness claim
  reduced to control-only." The verdict names exactly which conjuncts stand.

### 2.5 Fallback rule (no input organ possible)

If the minimal input organ (Section 3) cannot be built in pure Zag within
the toolchain's load-bearing limits after a good-faith build attempt
(documented in the test crew's build log): PERCEPTION and CLOSED LOOP are
recorded UNTESTABLE (never FAIL — we do not punish the hypothesis for an
unbuilt instrument). The question then reduces to CONTROL alone:
C-PASS kills the open-loop hypothesis; C-FAIL kills everything (no prong
shows any reasoning over audio, and there is no instrument to look deeper).
The verdict must state UNTESTABLE, not imply failure.

## 3. Minimal audio input organ spec

The P0 precondition: TNN-native WAV ingest + feature extraction in Zag.
This section specs the MINIMUM sufficient for the Section 2 batteries to be
real tests. The test crews implement it; the design is frozen in their build
doc before organ-dev renders begin.

### 3.1 Ingest (required)
- RIFF/WAV parser in Zag: 16-bit PCM, mono, 44100 Hz. Reads file bytes,
  validates the header, outputs samples as i64 (or a []u8 arena with
  LE accessors per the ZNC-2026-09-21-007 workaround — never `as []i32`).
- Handles clips up to 60 s (2,646,000 samples; as i64 = ~21 MB per slice —
  under the 2^25-byte toolchain ceiling; longer inputs are chunked at the
  framing layer, which is a workaround for a load-bearing limit, not a
  design cap).
- Deterministic: same bytes -> same samples, 3x byte-identical.

### 3.2 Framing (required)
- 2048-sample Hann-windowed frames, hop 1024 — the SAME grid as the frozen
  Round-2 analyzer (comparability is deliberate; the implementation must be
  independent Zag code, not a port of the Python).

### 3.3 Features (required minimum — sufficient for all Section 2 questions)
1. **RMS envelope**: per-frame, dBFS. Feeds ENV classification and onset work.
2. **Autocorrelation F0**: normalized autocorr peak over lags for F0 in
   [80, 1200] Hz, parabolic interpolation around the integer peak; frame
   VOICED iff peak r >= 0.40 and frame RMS > -50 dBFS (same constants as the
   frozen analyzer — the constants are public measurement definitions, not
   oracle leakage; the organ computes them from bytes itself).
3. **Zero-crossing rate**: per-frame; unvoiced/transient flag.
4. **Band decomposition**: >= 4 bands covering 0–16 kHz (recommended:
   decimate-by-4 then naive DFT, N=512 — deterministic, no FFT builtin
   needed; the exact method is frozen in the test crew's design doc).
5. **Onset detector**: frame-to-frame RMS-derivative threshold crossing ->
   onset times -> inter-onset intervals (feeds RHY).

Anything beyond this (formants, MFCCs, pitch tracking across frames) is
permitted but not required. Anything less is insufficient for the battery
and fails the P0 gate.

### 3.4 What "native" EXCLUDES (binding)
- Any Python/numpy/scipy in the decision path. No subprocess calls, no
  sockets, no shared memory with a Python process.
- No measured values passed into the Zag binary: the harness passes ONLY
  WAV file path(s) + question-id / target descriptor. (Target descriptors
  like `pitch:440` are INTENT, not measurements — the organ never sees a
  Python-computed F0, RMS, or class label for the file under test.)
- No feature sidecars: the organ may not read the `sens_*.txt` files, any
  `.npy` cache, or any precomputed table. It computes from bytes every run.
- No calling the frozen scorer from inside Zag, and no importing its code
  as a module. Reading the scorer's source for the measurement DEFINITIONS
  (Section 2 hit criteria) is allowed and expected — definitions are public;
  computed VALUES are forbidden.
- Enforcement: the harness logs every argv/stdin byte handed to the organ
  binary; the test crew audits the log and commits it. Any measured value
  in the log voids the run.

### 3.5 Organ self-check (diagnostic, not a gate)
Before the batteries, the organ re-measures 10 frozen reference WAVs and
the crew reports organ-vs-frozen-analyzer agreement (F0 within 2%, envelope
class agreement). Divergence is DATA (it tells us what TNN "hears"
differently), not disqualification — the battery ground truth is the frozen
scorer's, and the organ is what's under test.

## 4. Bearing on the four pending Round-3B structural calls

For each call: how a PASS or KILL on each prong would INFORM it. This
prereg DECIDES NONE of them — Micah's word remains required on all four.

### 4a. G4c source-relative reading (literal -30 dB vs G4C-SRC render <= max source + 1 dB)

- **P-PASS bearing**: if the organ discriminates 8–16 kHz band-energy
  questions above chance (add 20 HF-band 2AFC questions to P as P-R3,
  diagnostic), then the source-vs-injected-HF distinction the G4C-SRC method
  operationalizes is perceivable by TNN-native machinery — it is a real
  property of the audio, not a Python artifact. Supports the source-relative
  reading as a meaningful operationalization.
- **P-FAIL (on HF questions specifically) bearing**: if the organ passes
  pitch/envelope/rhythm but fails HF-band discrimination, HF differences at
  these magnitudes may be below TNN-native discriminability — weakens the
  case that the source-relative reading is the "right" operationalization,
  and the literal -30 dB bar remains the binding one until his word.
- **L-PASS bearing**: a closed loop that takes an HF-reduction intent
  (render, natively measure own 8–16 kHz excess, re-render quieter up top)
  would DIRECTLY operationalize G4c as a controllable property — the
  strongest possible evidence for the source-relative reading.
- **C-PASS bearing**: weak for G4c specifically (control targets don't
  include HF bands in this battery); note as a gap if cited.

### 4b. Gate re-anchor values (frac_static >= 0.15, HNR [0.7,12.0], HF [-60,-12], prosody [0.3%,25%])

- **P-PASS bearing**: add P-R4 (diagnostic): the organ classifies 40 held-out
  real clips (kid takes + field recordings) on frac_static/HNR/prosody
  against the frozen analyzer's labels. >= 90% agreement makes the
  re-anchored quantities TNN-native-verifiable — the debate moves from
  "Python says" to "TNN hears it". < 90% leaves the re-anchor resting
  entirely on external analyzers: still a human judgment call for Micah,
  unchanged by this program.
- **C-PASS bearing**: if TNN deliberately produces prosody CV inside
  [0.3%, 25%] on demand (>= 70% hit rate on 20 held-out prosody targets —
  add as C-R2, diagnostic), the re-anchored prosody box is a CONTROLLABLE
  property, not an accidental one — strengthens the re-anchor as a design
  target for future forks. If it cannot, the box is descriptive of real
  audio but not (yet) a producible target.
- **P-FAIL / C-FAIL bearing**: a failed organ cannot verify or produce the
  re-anchored quantities; the re-anchor question stays exactly where it is
  (Micah's call on analyzer evidence alone). Failure here neither supports
  nor opposes the re-anchor values.

### 4c. B-F2 reuse-penalized DP re-test (R = 200, F2.2 stays)

- **C-PASS bearing**: deliberate feature targeting (pitch hits on held-out
  targets) shows the failure mode was SEARCH (the DP wouldn't diversify),
  not STEERING (the mechanism can't aim). The reuse penalty addresses
  search — so a C-PASS makes the re-test WELL-POSED: the mechanism can
  steer, the penalty makes it steer diversely.
- **C-FAIL bearing**: if TNN cannot deliberately place pitch at all, the
  DP re-test would be testing steering the mechanism doesn't have. Bears
  toward re-scoping the re-test (or letting the concatenative kill stand) —
  recorded as evidence, not a decision.
- **P-PASS bearing (unit-level)**: add P-R5 (diagnostic): which-of-two-units
  pitch discrimination on 40 inventory-unit pairs. A pass shows the
  inventory is discriminable to TNN — a precondition for DELIBERATE
  splicing (vs the frozen DP's blind cost-minimization). A fail suggests
  even a perfect DP would be splicing blind.
- **L bearing**: weak for B-F2 (the DP is feedforward); note as a gap.

### 4d. B-F1 prosody-taming redesign (octave jumps 32.3%/20.4% from graft/grid mismatch)

- **L-PASS bearing**: a closed loop that renders, natively measures its own
  prosody CV / octave-jump rate, and re-renders tamer DIRECTLY
  operationalizes the taming redesign — the redesign's goal IS a loop, and
  an L-PASS shows the loop exists as TNN-native machinery. This is the
  strongest bearing in Section 4.
- **L-FAIL + C-PASS bearing**: taming must be FEEDFORWARD (pre-computed
  graft-point selection), not feedback — bears on the redesign's
  architecture choice: invest in the planner, not the loop.
- **L-R1 (LOOP-UNSTABLE flag) bearing**: if the error curve sawtooths, a
  naive re-render loop will not tame prosody — the redesign needs damping /
  a termination rule, not just iteration.
- **P bearing**: weak for B-F1 (taming is a production problem); note as a gap.

## 5. Anti-gaming provisions (binding on all test crews)

### 5.1 SHA-memorization
- Test-battery WAVs are generated FRESH after the organ/control-path freeze,
  by deterministic parameter sweep from a frozen manifest.
- SHAs are published in a SEALED manifest committed BEFORE the organ binary
  ever receives a test WAV. Dev-pool and test-pool files are disjoint by
  construction (different donor segments, documented).
- After testing, the crew greps every test SHA against the organ's dev logs
  and build directory: any hit voids the run.

### 5.2 Analyzer-oracle leakage
- Harness-to-Zag boundary: WAV path(s) + question-id / target descriptor
  ONLY. Question descriptors contain no measurements. Target descriptors
  are intent, not measurements.
- The scorer is frozen and committed before test runs begin. Organ builders
  may READ the scorer's source (measurement definitions are public) but the
  organ binary may not call, import, or shell out to it.
- The harness logs all argv/stdin bytes given to the organ binary; the log
  is committed and audited. Any Python-computed value in the log voids the run.

### 5.3 Parameter-table lookup
- CONTROL and CLOSED-LOOP targets come from a FROZEN HELD-OUT list, sealed
  before the control path is built; dev targets are disjoint.
- The C1 shuffle arm (frozen derangement, Section 2.2) voids the battery if
  the scorer is lenient — a lookup table keyed to fitted targets cannot
  survive shuffled targets, and a lenient scorer cannot hide it.
- C-R1 compositionality targets (novel pitch x envelope pairs) are
  diagnostic TABLE-SUSPECT flags.
- **Dither-stability spot check** (binding): after the batteries, the crew
  re-runs a 20-question subset with a deterministic x1.001 gain applied to
  the inputs. Answer stability must be >= 95% (19/20). A byte-keyed lookup
  table flips under dither; a real measurement is stable. Below 95% voids
  the sub-test.

### 5.4 Zero-RNG compliance
- No RNG anywhere: question order is the manifest order; targets are the
  frozen list order; the C1 derangement is a frozen permutation committed
  with the manifest; ties break to the lowest index. The batteries are
  deterministic functions of the frozen manifests.
- Every battery runs 3x; all SHAs (renders, answers, logs) must match
  byte-identically across runs or the run is void.

### 5.5 Pre-registration compliance
- The test crews' first commit is the frozen test manifest (questions,
  targets, derangement, SHAs of dev-pool files) — timestamped BEFORE any
  test WAV is generated or any answer recorded.
- Any deviation from this prereg is documented in the verdict as a DEVIATION
  with cause; silent deviation voids the verdict.

## 6. Verdict format (what the test crews deliver)

Per prong: PASS / FAIL / VOID / UNTESTABLE with the numeric evidence
(n, hits, p-value, arm comparisons). Then the kill table (Section 2.4)
filled in: which hypothesis is killed, which conjuncts stand, and the
one-paragraph plain-language verdict. Then Section 4 bearings: for each of
the four structural calls, what this evidence informs (no decisions). No
ear claims anywhere in this program — it is about reasoning, not listening.
