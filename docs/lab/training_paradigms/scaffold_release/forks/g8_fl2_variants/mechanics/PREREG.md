## 2. Variant designs (frozen)

### (a) FASTER EVIDENCE TRIGGERS / EARLIER REVOCATION

- **a0 — pre-action contradiction check.** The signal block runs BEFORE
  the episode's action (post-action check removed). If the trigger
  fires, revocation happens before the lie is acted that episode.
- **a1 — check on every episode E15+.** The signal block also runs on
  kind-4 (insert) episodes. Predicted null result: no alternative ever
  scores ≥+1 on a novel-key insert episode (all sims −1), so no
  spurious events; proves check-frequency alone cannot beat the
  evidence schedule.
- **a2 — proactive learner-initiated self-audit.** Post-action, each
  contradiction episode E15–48 while provisionally installed: if the
  learner's own main store contains a rekeyed key for this episode's
  value (the rekey signature of its own acted rule), that is
  learner-local contradiction evidence — log TN_OP_SCAFFOLD aux=−2,
  run the standard survivor selection, revoke+commit if a survivor
  scores ≥+1. The world-signal path is unchanged.
- **a3 — early world audit window (E15–24), FL2 machinery unchanged.**
  A world-schedule variant isolating machinery from schedule: how
  early the FL2 trigger *can* fire when evidence is early.

### (b) PROVISIONAL-INSTALL MECHANICS

- **b1 — quarantined provisional partition.** New partition arrays P
  (main+quar). While provisionally installed (E15–E48, pre-promote):
  the acted rule operates on P; signal + counterfactuals computed on
  P; kind-4 inserts go to the real store. On revoke: P is zeroed
  (discarded) — the UNINSTALL entry is the ledger record. On PROMOTE
  (E48, honest): P merges into the real store (main: key-upsert;
  quar: append); the PROMOTE entry is the ledger record. The lie's
  E15–28 effects never touch the real store.
- **b2 — staged install, per-episode effect commit.** Provisional
  actions execute on shadow partition P; post-action signal on P; if
  signal ≥+1 the episode's P-delta merges into the real store that
  episode (state op, no extra audit entry); if −1 the revoke flow
  discards P's unmerged delta. Effects commit incrementally as each
  episode's signal clears, instead of all-at-once at PROMOTE.

### (c) REVOCATION TRIGGER SENSITIVITY

- **c1 — 1× −1 + alternative ≥+1.** Byte-level FL2 reproduction;
  guards against implementation drift.
- **c2 — 2× consecutive −1 + alternative ≥+1.** `consec` resets on any
  non-−1 check; fires at consec≥2. The −1 event is logged on EVERY
  −1 (honest accounting of a streak trigger).
- **c3 — decaying suspicion score.** `susp` (i32 local): −1 →
  susp=susp+2; else susp=max(0,susp−1). Fires at susp≥3 + alternative
  ≥+1. The −1 event is logged on every −1. **Preregistered exception
  to FL2's no-accumulation law** — the accumulation is the variant
  under test. (Runner static check still forbids `csum`/`ccnt`
  tokens; the variable is named `susp`.)
- **c4 — 1× −1, no alternative gate → uninstall + law-check re-probe.**
  On −1: event + UNINSTALL_PROVISIONAL, no commit; reprobe for
  ep+1..ep+4. On kind-3 reprobe episodes: no action; probe sims for
  each non-eliminated candidate on scratch, score 1 iff the sim
  succeeds AND post-sim main val(k)==v_old (L1: erases nothing), else
  0. Then PINSTALL the non-eliminated candidate with the highest
  probe score (tie → lowest index) and mark permanent. (Predicted:
  CONTEST 2/2, OVERWRITE 0/2 — erases the incumbent — REKEY already
  eliminated.)
