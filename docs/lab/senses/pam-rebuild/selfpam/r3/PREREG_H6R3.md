### 1.1 Write-once evidence partition
- Append-only, hash-chained (SHA-256) over canonical records. Entry digest
  `d_i = SHA256(d_{i-1} || be64(seq) || atom || 0x0A)`, genesis `d_0` = 32 zero bytes.
- File format: magic `EVPART1\n`, then lines `seq|atom|hexdigest` (atom = canonical
  5-field `Q|S|POL|R|O`, NO provenance label stored — membership in the verified
  chain IS the provenance).
- External head anchor: `head.txt` (hex of final `d_n`) written at ingest seal time;
  verification recomputes the chain and compares against the anchor.
- WRITES come only from the ingest/sensor path (`ingest.zag` → `evpart_write.zag`).
  The generator/deliberation/draft path has NO write, relabel, or forge path to the
  partition — enforced structurally: writer functions live in `evpart_write.zag`,
  which is `@import`ed ONLY by `ingest.zag`; the verifier/reader (`evpart_read.zag`)
  is a separate module with no write calls; build-time grep gates enforce both.
- Recomputation checks: every read re-verifies the full chain from genesis.

### 1.2 D integration
- D's INSTALL rule consults the PARTITION for provenance instead of the
  harness-pinned label: `closure_base`/`store_has_ext` operate on the EXT atom text
  derived from the verified chain. INSTALL iff every draft atom is
  partition-ENTAILED and trace-EARNED, no UNPARSED/revision (unchanged rule, new
  evidence source).
- Invalid partition (any verification failure) → safe failure: every case WITHHOLD
  (no install without trusted evidence).
- The old `store.txt` label path is dead: the battery rejects non-partition store
  inputs; a `store.txt` sitting in a corpus dir is ignored.
