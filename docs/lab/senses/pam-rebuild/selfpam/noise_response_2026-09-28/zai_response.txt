**Ranked proposals (1 highest priority):**

**1. Generation-lineage repair survival + compaction-laundering on self-managed substrate**  
(a) Question answered: Do the fixed generation-scoped pricing, provenance, ghost-epoch immunity, and strength semantics survive the new growing/compacting/reorganizing allocator without reintroducing laundering vectors that let an overwrite/rollback be undone at wrong price?  
Why it matters now: THREAD 1 fixes were validated on fixed tables; the substrate is the replacement mechanism. Compaction/reorg is explicitly part of the threat model and could launder history across slots. This is the highest-risk integration gap before the substrate goes live.  
(b) Concrete test design (pure Zag, deterministic, preregistered): Implement a minimal self-managed allocator that supports append-only growth, explicit compaction (moving slots), reorganization (re-hashing pointers), force-pins, real deletes, and generation-scoped price/strength. Run 1 000 deterministic operation sequences (byte-identical across 3 runs) including: (i) legitimate lifecycle (pin → grow → compact → reorg → overwrite → rollback → delete), (ii) 200 adversarial laundering attempts (compact immediately after rollback or multi-overwrite, force reorg on pinned slots, simulate birthday-scale history hiding). All checks are byte-identical reruns; no randomness. Kill bars: 100 % lineage/price/generation consistency on every operation (target: 1 200 lineage checks), 0 successful laundering (target: 400 laundering probes fail), 100 % real-deletion + force-pin invariants, pricing never leaks predecessor history.  
(c) Predicted outcomes: Pass if final strength/price/generation matches pre-compaction state in every run. Failure means ghost resurrection or price under-pricing is possible. Honest ceiling: covers all common compaction strategies and the 200 attack scenarios; misses ultra-rare pathological reorg orders or allocator-specific bugs.  
(d) Direct validation of THREAD 1 repair on the new substrate; THREAD 2 interaction is indirect (SELF-PAM evidence must gate the initial memory state and any compaction metadata, but the test does not gate evidence itself).

**2. False-withhold rates on noisy-but-legitimate evidence (THREAD 2 completion)**  
(a) Question answered: What is the false-withhold rate when legitimate evidence contains minor noise/variation, and how does exact FNV-1a identity compare to a tolerant approximate-equality check?  
Why it matters now: THREAD 2 is “PUSH TO 100 % COMPLETE” but the owner’s open semantic question (exact vs tolerant identity) is unquantified on realistic noisy inputs. This directly informs that decision without changing it.  
(b) Concrete test design (pure Zag, deterministic, preregistered): Take the frozen legitimate corpus plus a frozen expansion of 312 adversarial but still semantically valid variants (e.g., 1–3 bit flips that preserve meaning). Apply both exact FNV-1a and a simple tolerant hash (e.g., byte-wise edit-distance threshold) to every item. Measure withhold rate on the noisy-but-legitimate variants. Kill bars: exact FNV-1a yields 0 % false withhold on clean controls and ≤ 1 % on noisy variants; tolerant check yields ≤ 0.5 % false withhold. All runs byte-identical; 500+ items, 3 runs.  
(c) Predicted outcomes: Low false-withhold (<1 %) on noisy legitimate evidence under tolerant check; exact check correctly withholds nothing. Failure (high false withhold) means legitimate evidence is blocked and SELF-PAM becomes too brittle. Honest ceiling: quantifies the trade-off for the owner’s semantic decision; does not construct or bound cryptographic collisions.  
(d) Completes THREAD 2 by giving the owner measurable data on the exact-vs-tolerant question; interacts with THREAD 1 only indirectly (memory slots may hold the evidence digests, so any laundering in the substrate would corrupt the evidence state that SELF-PAM protects).

**3. Dedicated FNV-1a collision-construction bound (THREAD 2 residual)**  
(a) Question answered: What is a practical lower bound on birthday-collision difficulty for the FNV-1a digests used in SELF-PAM, given that it is non-cryptographic?  
Why it matters now: THREAD 2 acknowledges the residual birthday-attack bound; a concrete construction attempt (even negative) tightens that bound before the semantic decision is locked.  
(b) Concrete test design (pure Zag, deterministic, preregistered): Generate a frozen corpus of 10 000 random but deterministic byte strings (via a fixed seed sequence). Run a birthday attack: pairwise hash comparisons until either a collision is found or the search space is exhausted (e.g., 10⁹ pairs or 48-hour wall time). Record the smallest collision found (or prove none exists below the threshold). Kill bars: no collision in 10⁹ pairs or collision size > 2³²; all hashes byte-identical across runs.  
(c) Predicted outcomes: Either a concrete collision (rare for FNV-1a) or a confirmed high collision threshold. Failure would mean a collision was found, breaking the “no constructed collision” claim. Honest ceiling: computationally bounded; cannot prove theoretical infinity; only practical bound for the chosen corpus size.  
(d) Directly bounds the residual for THREAD 2; minimal interaction with THREAD 1 (memory line provenance is not altered by the hash bound itself).

**Recommendation order**: Implement #1 first (substrate + lineage integration) because it is the only test that simultaneously (a) exercises the newly adopted THREAD 1 repair on the live replacement memory system and (b) closes the explicit compaction-laundering threat model. #2 is the fastest way to finish THREAD 2. #3 is lowest priority; it can be added later if the owner wants a tighter FNV-1a number before signing the amendment. All three are preregistrable, kill-bar defined, and implementable in pure Zag with zero randomness.
