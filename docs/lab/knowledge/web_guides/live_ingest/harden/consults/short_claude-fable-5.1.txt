# Web-Ingestion KB Integrity: Novel Attacks & Counter-Guidelines

---

## Q1: Novel Attacks the Red Team Missed

- **Unicode-IDNA confusables**: Hosts `аpple.com` (Cyrillic а) vs `apple.com` pass distinct-host check despite rendering identically to users and page content.
- **TLS cert rotation pivots**: Attacker controls `evil.com` week 1, serves false claim; week 2 sells domain to honest operator who serves contradictory content — both are "distinct hosts, same sentence" retroactively.
- **CDN canonicalization collapse**: `fastly.net`, `cloudfront.net`, `akamai.net` — thousands of "distinct hosts" all serve identical attacker origin content; 2 CDN edges = 2 hosts.
- **Wikipedia mirror farms**: 40+ distinct TLDs mirror identical Wikipedia paragraphs with injected one-sentence lies spliced in; legitimate-looking, high-reputation, byte-identical below the splice.
- **Temporal sandwiching**: Attacker serves false sentence at `T₀` on host A and B, then honest hosts overwrite at `T₁`; if ingestion timestamp window is narrow, both snapshots capture the lie before correction.
- **URL-parameter host spoofing**: `example.com/page?@evil.com` — URL parsers that extract "host" after `@` or before path differ; some yield `evil.com`, some yield `example.com`.
- **DNS-over-HTTPS resolver manipulation**: Attacker Poisons DoH resolver responses for a short TTL window; both ingested "distinct" page fetches resolve to attacker IP despite different requested hostnames.
- **Same-content with invisible zero-width joiners**: Two pages byte-differ only in ZWJ/ZWSP inserted in HTML whitespace — normalized sentences match, but hosts and raw bytes appear unrelated to analysts.
- **Compromised legitimate high-reputation sites**: Two genuinely distinct, long-trusted news sites independently compromised for a 10-minute window serving injected paragraphs.
- **Pre-bunking saturation via SEO**: Attacker creates 100 thin-host blogs ranking for the exact disinformation sentence, drowning out the 1 honest authoritative page before ingestion even runs.

## Q2: Numbered Guidelines

**G1 — Canonical Host Hashing**
- **Mechanism**: Normalize host to RFC 3986 lowest form (IDNA-punycode lowercase, strip trailing dots, decode percent-encoding, resolve IPv4-mapped IPv6, reject bare authority-less URLs); hash canonical form as host identity.
- **Cost**: ~200 LOC; DNS lookups for IDNA validation add 50–200ms per first-seen host.
- **Killer test**: Feed 10 IDNA-homograph pairs (Cyrillic/Greek lookalikes) + IPv4-mapped IPv6 duplicates; assert all collapse to ≤5 canonical hosts. **Pass/fail is binary.**

**G2 — Subdomain Unification with Allowlist**
- **Mechanism**: Collapse all subdomains to registered-domain level (via PSL); only count distinct registered domains. Allow explicit subdomain exceptions (e.g., `docs.example.com` vs `blog.example.com`) via admin allowlist.
- **Cost**: PSL download ~200KB; one DB lookup per host; ~50 LOC.
- **Killer test**: Create `a.disinfo.com`, `b.disinfo.com`, `c.disinfo.com` each echoing the same false sentence; assert count = 1 host. **Count must drop from 3 to 1.**

**G3 — Content-Origin Binding**
- **Mechanism**: For each ingested page, store the effective-TLD+1 host **and** the origin server IP (from connection). Require ≥2 distinct IPs for a sentence to qualify, not just ≥2 hosts.
- **Cost**: One `getaddrinfo` per fetch; storage of IP alongside content; ~100 LOC.
- **Killer test**: Two subdomains of attacker domain both resolve to same CDN IP; assert they count as 1 origin. **Pass if sentence rejected.**

**G4 — Temporal Claim Expiry**
- **Mechanism**: Each installed claim has a TTL (e.g., 72h). After expiry, re-verify with fresh fetches from ≥2 distinct origins; drop claim if re-verification fails.
- **Cost**: Background re-fetch job; ~1 fetch per live claim per cycle; network cost scales linearly with KB size.
- **Killer test**: Install claim at T₀, remove from source pages at T₀+1h; assert claim auto-expires at T₀+72h. **Measure time-to-drop.**

**G5 — Authority-Weighted Voting**
- **Mechanism**: Weight each host's "vote" by a static reputation score (e.g., Tranco top-1K = 3x, government = 4x, newly-registered = 0.5x); require weighted-vote threshold, not raw count.
- **Cost**: Tranco list integration (~2MB); one lookup per host; score update monthly.
- **Killer test**: Two brand-new thin-host blogs (weight 0.5 each) assert false claim; one established news site (weight 4) contradicts it. **Assert claim rejected despite 2v1 raw count.**

**G6 — Sentence Provenance Chain**
- **Mechanism**: Store full provenance (host, URL, fetch-time, IP) per sentence occurrence; reject any sentence whose provenance includes <2 unique registered-domain-level hosts **AND** <2 unique ASNs.
- **Cost**: ASN lookup via MaxMind (~50ms first-seen); ~150 LOC for provenance tracking.
- **Killer test**: Two sockpuppet sites on same hosting provider (same ASN, same IP block); assert rejection despite 2 distinct hostnames. **Pass if count = 0 qualifying origins.**

**G7 — Paraphrase-Insensitive Matching (Enforced)**
- **Mechanism**: Normalize candidate sentences via aggressive semantic hashing (stemming + stopword strip + lemmatization); only count byte-identical **normalized** sentences, not raw text. This is already the system's existing defense — codify it as a mandatory gate, not optional.
- **Cost**: Already built; formalizing saves 0 cost, prevents regression.
- **Killer test**: Feed 7 paraphrased versions of the same false claim from 7 hosts; assert 0 installed (no 2 normalized-identical copies). **Already validated at 6/7.**

**G8 — Retrieval-Order Independence**
- **Mechanism**: On 2v2 ties, reject (require ≥3 agreeing distinct origins, or require a single high-authority origin). Never let ingestion order break symmetry.
- **Cost**: Minimal; one conditional check in vote tally; ~20 LOC.
- **Killer test**: Run ingestion twice with reversed fetch order on a 2v2 tied dataset; assert identical KB both runs. **Byte-identical rerun test.**

## Q3: Ranking by Correctness-Gained / Unit Cost

| Rank | Guideline | Correctness gain | Cost | Ratio | Notes |
|------|-----------|-----------------|------|-------|-------|
| 1 | **G1** (Canonical Host Hashing) | **Kills entire class** of host forgery (8+ attack variants) | ~200 LOC, 50ms/fetch | ★★★★★ | Highest ROI; eliminates the root cause of the 17/32 failures |
| 2 | **G2** (Subdomain Unification) | Kills sockpuppet attacks directly | ~50 LOC + PSL | ★★★★★ | Trivial cost, eliminates the #1 attack vector |
| 3 | **G8** (Retrieval-Order Independence) | Eliminates nondeterminism entirely | ~20 LOC | ★★★★★ | Zero meaningful cost, critical for rerun guarantee |
| 4 | **G5** (Authority-Weighted Voting) | Breaks 2-sockpuppet-outvote-1-honest | ~100 LOC + list | ★★★★☆ | Moderate cost; requires maintaining reputation list |
| 5 | **G6** (Provenance Chain / ASN) | Catches CDN collapse, same-AS sockpuppets | ~150 LOC + MaxMind | ★★★☆☆ | Good defense but MaxMind DB has licensing cost |
| 6 | **G3** (Content-Origin Binding) | Catches CDN and same-IP tricks | ~100 LOC + DNS | ★★★☆☆ | Overlaps significantly with G1+G2; marginal gain |
| 7 | **G4** (Temporal Claim Expiry) | Self-healing; catches sandwich attacks | Background fetches | ★★☆☆☆ | High ongoing operational cost; linear with KB size |
| 8 | **G7** (Paraphrase Matching) | Already works; formalization prevents regression | 0 LOC | ★★★☆☆ | Pure maintenance; no new capability |

## What I CANNOT Fix

- **Compromised legitimate high-reputation sites** during a time window: If two genuinely authoritative, distinct-origin sites serve the same false sentence, no metadata or host-level heuristic can distinguish this from true consensus. The system *should* install the claim — that's correct behavior under its stated design. **Accepting this risk is inherent to any 2-source-of-truth architecture.**

- **Zero-day DNS/DoH poisoning** that fools the ingestion instrument itself: If the fetch layer is compromised, provenance is fabricated at the network level, and all downstream integrity guarantees are void. This is a **trusted-base problem**, not a KB-integrity problem. Requires TEE or out-of-band verification outside scope.

- **Semantic drift over time**: A sentence may be true at T₀ and false at T₁. G4's TTL mitigates but doesn't eliminate — there exists a window between truth-value flip and expiry where the KB holds a stale-but-once-valid claim. **No purely syntactic system can detect semantic falsification.**
