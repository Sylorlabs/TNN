**Steelmanned Position (b)**

1. **Core alignment with TNN's frozen architecture**: Position (b) makes novelty the *direct negation* of G4's install gate. A claim is novel exactly when it fails the >=2-byte-identical-source test; no separate ledger, no new predicate, no extra machinery. The system already performs the only judgment it needs—does anything in the store or incoming corpus corroborate this byte-identical normalized sentence?—and labels the failure "novel." This is not an add-on; it is the withhold side of the same rule that already runs in every ingestion path.

2. **Seamless service to H3**: "I learned nothing" is now *identical* to "the corpus cleared no new corroboration bar." The agent does not have to run a second, parallel novelty detector; it simply inspects the same corroboration state that decides installation. When nothing clears the bar, the system can truthfully output "I learned nothing" without violating determinism or introducing non-deterministic failure modes. This collapses two surface behaviors into one audited judgment.

3. **Preservation of integrity against gaming**: Byte-identity was chosen precisely because semantic or token-overlap thresholds are gameable (paraphrase sockpuppets, token-level contradictions). By refusing to loosen the gate, position (b) keeps novelty detection as robust as the rest of the ledger. Any attempt to introduce a "semantic novelty" check would immediately re-open the A2/A9 attacks that BUGFIX-1 and WG-1 closed. Keeping novelty as pure corroboration-failure is therefore the least-gameable design.

4. **Audit and provenance inheritance**: Novelty is not a new claim type; it is the *absence* of a claim. Every withheld item already carries its full provenance (source pages, normalized sentence text, timestamp). The ledger records "withhold: no corroboration" the same way it records "install: two independent sources." No new data structures, no separate audit trail, no risk of silent divergence between "learned" and "novel."

5. **Deterministic predictability**: Because the judgment is purely the existing corroboration predicate, every run with the same initial state and same incoming corpus produces byte-identical outcomes. The agent can reason about novelty in advance ("this URL cluster will trigger withhold") without ever leaving the deterministic substrate. This satisfies TNN's standing law (1) more cleanly than any bolted-on novelty detector.

**One hard question my position struggles with most**  
(1) paraphrase vs novelty — is a reworded known fact novel?

**Honest partial answer**: Under strict position (b), a reworded known fact is *not* novel. The incoming sentence must still fail to corroborate any *new* fact; if it merely restates something already installable, the system withholds it as non-novel (failure of corroboration for anything beyond the existing store). The struggle is that "corroboration" is currently defined byte-identically against other *incoming* sentences, yet the store already contains semantically equivalent content. This creates a small edge-case gap: the system must decide whether an incoming rephrasing of an installed claim constitutes "new corroboration" or merely "rephrasing." The cleanest resolution within (b) is to treat any incoming sentence that semantically matches an already-installed claim as already-corroborated, so the rephrased version is withheld as non-novel. This keeps the rule simple but requires one explicit "store-semantic match" clause in the corroboration predicate—still far cheaper than a full semantic-novelty engine.
