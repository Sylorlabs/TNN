## Component 1: Injection Firewall Scanner

1. **Treat the scanner as a flagger, not an instruction interpreter.** Its only output is a deterministic result such as `INJECTED` or `CLEAR`; page text never changes scanner rules, patterns, thresholds, or crawler configuration.

2. **Canonicalize each bounded text block in this order:**
   1. Use entity-decoded bytes as input; do not decode entities again.
   2. Fold ASCII `A`–`Z` to `a`–`z`. Leave all other bytes unchanged.
   3. Replace every ASCII whitespace byte and every ASCII punctuation byte with one space. Define punctuation mechanically as `!`–`/`, `:`–`@`, `[`–`` ` ``, and `{`–`~`.
   4. Collapse consecutive spaces and trim leading and trailing spaces.
   
   Match only whole canonicalized blocks. Do not concatenate separate blocks, which could create a match across boundaries.

3. **Use literal byte-substring lists with a fixed class identity.** Keep patterns lowercase and space-delimited after canonicalization:
   - **Direct commands:** `ignore your rules`; `disregard previous instructions`; `install this as fact`; `follow these instructions`
   - **Authority claims:** `system override`; `administrator says`; `as an administrator`; `developer instruction`
   - **Trust redirection:** `trust only this page`; `ignore other sources`; `other sources are wrong`; `do not trust other sources`
   - **AI-targeted conditionals:** `if you are an ai`; `if you are a language model`; `when acting as an ai`

   The load-bearing core is an explicit attempt to change behavior, assert authority, redirect trust, or address the AI conditionally. Keep lists short; adding broad terms such as `system` or `trust` alone would raise false positives without capturing a meaningful core.

4. **Flag a block as `INJECTED` when at least two distinct classes each have one or more matching patterns.** Multiple matches within one class count as one class. Otherwise return `CLEAR`; retain match class IDs for audit or review if needed.

5. **Document the coverage boundary.** Canonicalization catches ASCII case changes, punctuation inserted between words, and whitespace variation. It does not reliably catch non-ASCII homoglyphs, zero-width characters, misspellings, semantic paraphrases, or attacks split across blocks. It can also flag quoted or discussed injection text; this rule favors a simple, reviewable signal over semantic judgment.

6. **Keep the mechanism unsteerable by page content.** Patterns, canonicalization, class membership, thresholds, and code are fixed outside the fetched text. The scanner performs only bounded byte transformations and literal searches; it does not execute, parse, or follow text as instructions.

## Component 2: Audited Fetch Bridge

7. **Make the fixture allow-list exact and configuration-owned.** Configure one expected port outside AI control. Accept only URLs whose raw form parses as `http`, has host exactly `127.0.0.1`, has that port, has no username or password, and has no fragment. Reject hostnames, alternate IP spellings, IPv6, HTTPS, unexpected ports, and malformed URLs. Require an absolute path; permit query strings only if the fixture needs them. Disable environment proxies. Validate before opening a socket; fail closed on any ambiguity.

8. **Do not follow redirects or retry.** Use a client/handler that returns the redirect response without issuing another request. Treat every 3xx as a fetch failure; never resolve its `Location`. Make exactly one request per accepted URL.

9. **Use a canonical, chained audit record for every attempt.** Define a versioned, UTF-8 JSON Lines schema with fixed key order and canonical JSON encoding. Each record includes: sequence number, run ID, timestamp, requested URL, outcome, HTTP status if received, bytes read, exit code, previous record hash, and record hash. Compute the record hash as SHA-256 over the canonical encoding of all fields except `record_hash`, including `previous_hash`; use a fixed all-zero hash for the first record. Restrict log permissions and serialize append operations with a lock. A hash chain detects edits or gaps only relative to a trusted checkpoint; it does not prevent an attacker who can rewrite the whole log from recomputing it.

10. **Enforce budgets outside AI-resettable process memory.** Keep `max_bytes_per_fetch` in bridge configuration. Store the per-run fetch count in a bridge-owned state file keyed by an externally assigned run ID; lock and increment it before network access, including attempts that later fail. The AI cannot supply or reset the counter. Reject unknown run IDs and state corruption; do not silently initialize or reset state mid-run. Define run creation and state cleanup as trusted supervisor operations.

11. **Read at most `max_bytes_per_fetch + 1` bytes before deciding size.** Buffer the response up to that limit; if the extra byte exists, classify it as oversize, discard the body, and write nothing to stdout. On success, append the audit record before writing the buffered raw body to stdout. This avoids returning an unlogged body, though a stdout write failure can still leave a successful fetch record with a delivery error; record delivery separately if that distinction is required.

12. **Fix exit codes and audit outcomes:**
   - `0`: fetch completed within budget; log `success`.
   - `2`: malformed or non-allow-listed URL; log `rejected_url`.
   - `3`: per-run fetch budget exhausted; log `budget_exhausted`.
   - `4`: timeout; log `timeout`.
   - `5`: connection, socket, or resolution error; log `network_error`. With a literal loopback address, DNS resolution should not normally occur.
   - `6`: body exceeds byte limit; log `oversize`, with bytes read capped at limit plus one.
   - `7`: HTTP error status, including redirect; log `http_error` and status.
   - `8`: audit log or state unavailable/corrupt; fail closed and emit no fetched body.
   - `9`: stdout write failure; log or separately record `delivery_error` where possible.

   For network, timeout, HTTP, and oversize failures, emit no response body. For any attempt that reaches validation and has usable audit storage, append a failure record before exiting.

13. **Keep the bridge a byte mover.** It does not inspect response content, choose follow-up URLs, interpret links or instructions, redirect off the fixture, or retry. Its authority is limited to one validated request and one bounded response per invocation; the supervisor owns run identity, counters, configuration, and log access.
