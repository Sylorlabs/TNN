## 1. Fixture Restrictions

Impose these restrictions on the generated HTML. They make the parser deterministic without requiring a general HTML parser.

### Encoding

- Input is UTF-8.
- Tags, attribute names, and the structural syntax emitted by the generator are ASCII.
- Text may contain UTF-8 bytes, but the parser must preserve valid non-entity UTF-8 text byte-for-byte except for whitespace normalization.
- Numeric entities must represent valid Unicode scalar values:
  - `&#0;` through `&#55295;`
  - `&#57344;` through `&#1114111;`
  - excluding surrogate values `55296` through `57343`
- Numeric entities are decimal only. Do not generate hexadecimal entities such as `&#x27;`.

### Tags

Only these tags are generated:

```text
html head body title h1 h2 h3 p li ul ol a script style
```

Tags are always lowercase ASCII.

The block tags are:

```text
title h1 h2 h3 p li
```

Restrictions:

- Block tags are not nested inside other block tags.
- Every block tag has an explicit closing tag.
- `title`, `h1`, `h2`, `h3`, `p`, and `li` contain only text and optional `<a>` elements.
- `<a>` elements may occur inside a block.
- `<a>` elements are not nested.
- `<a>` elements do not contain block tags.
- `script` and `style` do not contain `<script>` or `<style>` text.
- `script` and `style` content is ignored completely.
- `<html>`, `<head>`, `<body>`, `<ul>`, and `<ol>` are structural containers and do not produce blocks.

Recommended fixture shape:

```html
<html>
<head>
<title>...</title>
</head>
<body>
<h1>...</h1>
<p>Text <a href="/x">link</a>.</p>
<ul>
<li>...</li>
</ul>
</body>
</html>
```

### Attributes

Only `<a>` attributes matter.

Generate anchors in one of these forms:

```html
<a href=/path>
<a href='/path'>
<a href=/path?x=1&y=2>
<a href='/path?x=1&amp;y=2'>
```

Restrictions:

- `href` appears at most once.
- `href` is the first attribute.
- Attribute names are lowercase.
- There is at least one ASCII whitespace byte between `a` and `href`.
- There is optional ASCII whitespace around `=`.
- Unquoted values contain no:
  - whitespace
  - `>`
  - `'`
  - `"`
  - backtick
- Single-quoted values contain no single quote.
- The `href` value is nonempty.
- Double-quoted attribute values are not generated unless explicitly added to the parser.
- Attribute values may contain the supported entities.

For the simplest implementation, generate exactly:

```html
<a href=VALUE>
<a href='VALUE'>
```

with no additional attributes.

### Comments

Comments have this exact form:

```html
<!-- arbitrary bytes without -->
```

They always terminate with `-->`.

### Whitespace

Whitespace bytes are exactly:

```text
0x09 tab
0x0A newline
0x0C form feed
0x0D carriage return
0x20 space
```

The generator should use only these bytes as whitespace.

### Entities

Generate only:

```text
&amp;
&lt;
&gt;
&quot;
&#39;
&#NNN;
```

Named entities are lowercase and exact. Numeric entities are decimal and terminated by `;`.

Do not generate:

```text
&apos;
&nbsp;
&#x27;
&amp
```

The parser may recover from them deterministically, but they are outside the fixture grammar.

## 2. Output Semantics

The parser produces:

```text
blocks: ordered list of {
    kind: title | h1 | h2 | h3 | p | li
    text: normalized UTF-8 bytes
}

links: ordered list of {
    href: decoded UTF-8 bytes
    anchor_text: normalized UTF-8 bytes
}
```

### Block ordering

A block is appended when its closing tag is consumed.

For example:

```html
<h1>One</h1><p>Two</p><h2>Three</h2>
```

produces:

```text
[
  (h1, "One"),
  (p,  "Two"),
  (h2, "Three")
]
```

### Block text

Block text includes:

- direct text inside the block
- decoded entity values
- text inside an `<a>` child

Block text excludes:

- markup
- comments
- script/style content
- whitespace at the beginning and end
- repeated whitespace runs, which become one ASCII space

Example:

```html
<p> A   <a href='/x'> B </a>  C </p>
```

produces:

```text
(p, "A B C")
```

### Link ordering

A link is appended when its closing `</a>` is consumed. This preserves document order.

Example:

```html
<p><a href='/one'>First</a> and <a href=/two>Second</a></p>
```

produces:

```text
links = [
  ("/one", "First"),
  ("/two", "Second")
]
```

A link outside a block is still recorded if the fixture generator permits it. Prefer prohibiting that case.

### Empty blocks

Empty or whitespace-only blocks should be omitted:

```html
<p>   </p>
```

produces no block.

This avoids ambiguity around whether an empty structural element is meaningful.

## 3. State Machine

Use one byte cursor and a small fixed state machine. Every state checks `cursor < input_length` before reading.

```text
DATA
TAG_OPEN
TAG_NAME
TAG_SCAN
ATTR_NAME
ATTR_BEFORE_VALUE
ATTR_UNQUOTED_VALUE
ATTR_SINGLE_VALUE
COMMENT
RAW_SCRIPT
RAW_STYLE
```

Maintain this parser context:

```text
cursor: i64

state
current_tag_kind
current_block_kind
block_active: bool

anchor_active: bool
anchor_href_buffer
anchor_text_buffer

block_text_buffer

pending_space: bool
```

A useful distinction is:

- `block_text_buffer`: normalized text for the current block
- `anchor_text_buffer`: normalized text for the current anchor
- Every text byte is appended to the block buffer.
- Text inside an anchor is also appended to the anchor buffer.

Do not maintain a second independently normalized representation of the block. Use one `append_text_byte` routine for both destinations.

### `DATA`

Read one byte.

#### Byte is `<`

Transition to `TAG_OPEN`.

#### Byte is whitespace

Set:

```text
pending_space = true
```

Do not immediately append a space.

#### Byte begins an entity

If the byte is `&`, call the entity decoder.

- On success, feed the decoded code point/bytes into the text appender.
- On failure, treat `&` as an ordinary text byte and continue scanning.

#### Any other byte

Feed it to the text appender.

### Text appender

The appender receives decoded UTF-8 bytes or ordinary input bytes.

For each byte:

1. If it is whitespace:
   - set `pending_space = true`
   - return
2. If `pending_space` is true and the destination is nonempty:
   - append one ASCII space
3. Clear `pending_space`.
4. Append the byte.

For decoded Unicode code points, first encode the code point as UTF-8, then pass the resulting bytes through the same appender.

This gives:

```text
" a   b " -> "a b"
```

without needing to trim after the block closes.

At block or anchor close, simply clear `pending_space`. Do not append it.

### `TAG_OPEN`

The next byte determines the construct.

```text
!  -> COMMENT if the following bytes are "--"
 /  -> closing tag
letter -> TAG_NAME
other -> malformed-tag recovery
```

For comments, recognize only:

```text
<!--
```

If the sequence is not exactly `<!--`, enter malformed-tag recovery.

For a closing tag, consume `/`, then parse a lowercase ASCII tag name.

For an opening tag, parse a lowercase ASCII tag name.

### `TAG_NAME`

Consume lowercase ASCII letters until one of:

```text
ASCII whitespace
>
/
EOF
```

Store only the tag identity, not a string. Use an enum:

```text
TAG_UNKNOWN
TAG_HTML
TAG_HEAD
TAG_BODY
TAG_TITLE
TAG_H1
TAG_H2
TAG_H3
TAG_P
TAG_LI
TAG_UL
TAG_OL
TAG_A
TAG_SCRIPT
TAG_STYLE
```

After the name:

- `>`: process the opening or closing tag immediately
- whitespace: enter `TAG_SCAN`
- `/`: consume through `>`; self-closing tags are ignored except that fixtures should not generate them for block tags
- EOF: malformed-tag recovery

### `TAG_SCAN`

Scan attributes until `>`.

For `<a>`, recognize the exact attribute name `href`.

Other attributes are skipped.

Attribute handling:

```text
whitespace -> continue
>          -> finish opening tag
/          -> skip until >
letter     -> parse attribute name
other      -> malformed attribute recovery
```

For each attribute:

1. Parse the attribute name.
2. Skip whitespace.
3. If the next byte is `=`, consume it.
4. Skip whitespace.
5. Parse the value:
   - `'` -> `ATTR_SINGLE_VALUE`
   - anything other than whitespace or `>` -> `ATTR_UNQUOTED_VALUE`
   - otherwise -> empty/malformed value

Only capture the value if the attribute name is exactly `href`.

### `ATTR_UNQUOTED_VALUE`

Consume until:

```text
whitespace
>
EOF
```

Decode entities while copying the value into `anchor_href_buffer`.

Then return to `TAG_SCAN`.

### `ATTR_SINGLE_VALUE`

Consume until the next single quote.

Decode entities while copying the value into `anchor_href_buffer`.

If the closing quote is found, return to `TAG_SCAN`.

If EOF occurs first, use the deterministic malformed-input rule below.

### Opening-tag actions

After consuming an opening `>`:

#### Block tag

For `title`, `h1`, `h2`, `h3`, `p`, or `li`:

- If another block is active, apply malformed recovery.
- Otherwise:
  - set `block_active = true`
  - set `current_block_kind`
  - clear `block_text_buffer`
  - set `pending_space = false`

#### `a`

- If a block is not active, either:
  - ignore the anchor, or
  - prohibit it in fixtures.
- If a block is active:
  - set `anchor_active = true`
  - clear `anchor_href_buffer`
  - clear `anchor_text_buffer`
  - initialize href capture from the parsed attribute
- If `href` was absent, the anchor is not recorded, but its text still contributes to the enclosing block.

The recommended fixture restriction is that every `<a>` has exactly one valid `href`.

#### `script`

- Enter `RAW_SCRIPT`.
- Ignore all content until the exact lowercase byte sequence `</script>`.

#### `style`

- Enter `RAW_STYLE`.
- Ignore all content until the exact lowercase byte sequence `</style>`.

#### Any other opening tag

Ignore it and continue in `DATA`.

### Closing-tag actions

For `</a>`:

- If `anchor_active`:
  - append one link using the decoded href and normalized anchor text
  - set `anchor_active = false`
- Otherwise ignore it.

For a block closing tag:

- Only close if it matches `current_block_kind`.
- If the block text buffer is nonempty:
  - append `(kind, text)` to `blocks`
- clear block state
- clear `pending_space`

For `</script>` and `</style>`:

- These are consumed by their corresponding raw states.
- A normal `DATA` closing-tag handler should not process their contents.

Unknown closing tags are ignored.

### `COMMENT`

Scan until the exact three-byte terminator:

```text
-->
```

Consume the terminator and return to `DATA`.

If EOF occurs first, discard the remainder of the input and finish.

### `RAW_SCRIPT` and `RAW_STYLE`

Search byte-by-byte for the exact lowercase terminator:

```text
</script>
</style>
```

No entity decoding and no tag parsing occurs in these states.

The fixture restrictions make this safe because raw content cannot contain the matching closing sequence.

If EOF occurs before the terminator, discard the remainder and finish.

## 4. Entity Decoding

Implement a bounded scanner beginning at `&`.

The decoder must never read beyond the input slice.

### Named entities

Recognize only these exact byte sequences:

```text
&amp;  -> byte 0x26
&lt;   -> byte 0x3c
&gt;   -> byte 0x3e
&quot; -> byte 0x22
&#39;  -> byte 0x27
```

The decoder returns:

```text
success
bytes consumed
decoded code point or UTF-8 bytes
```

Do not use string comparison. Compare lengths and bytes manually.

### Numeric entities

Recognize:

```text
&#NNN;
```

Algorithm:

1. Verify the first two bytes are `&` and `#`.
2. Set `value = 0`.
3. Consume one or more decimal digits.
4. Before each multiplication/addition, check overflow against the chosen maximum:
   ```text
   value <= (1114111 - digit) / 10
   ```
5. Require a terminating `;`.
6. Reject:
   - no digits
   - missing `;`
   - value greater than `1114111`
   - surrogate values `55296..57343`
   - zero
7. Encode the scalar value as UTF-8.

UTF-8 encoding:

```text
value <= 0x7f:
    one byte

value <= 0x7ff:
    110xxxxx 10xxxxxx

value <= 0xffff:
    1110xxxx 10xxxxxx 10xxxxxx

otherwise:
    11110xxx 10xxxxxx 10xxxxxx 10xxxxxx
```

The encoder must write only to a buffer with known capacity. A four-byte local array is sufficient before passing bytes to the text or attribute appender.

### Entity failure

On failure, consume nothing and treat the original `&` as ordinary text.

This gives deterministic behavior for malformed input:

```html
<p>A &unknown; B</p>
```

becomes:

```text
(p, "A &unknown; B")
```

For malformed entities in `href`, preserve their source bytes as written.

## 5. Malformed-Input Rules

The parser must never use an unchecked lookahead, unchecked output write, or unterminated scan.

Use these rules consistently:

### Unexpected EOF

- EOF in `DATA`: finish normally.
- EOF in a comment: discard the unterminated comment and finish.
- EOF in script/style: discard the unterminated raw section and finish.
- EOF in an attribute value: treat the value as ending at EOF, then finish.
- EOF in a tag before `>`: discard the incomplete tag and finish.
- EOF inside a block:
  - flush the block if its normalized text is nonempty
  - flush an active anchor only if its closing `</a>` was seen; otherwise do not emit that link
  - finish

### Unexpected `<`

If `<` is not followed by a recognized tag start, treat it as literal text.

For example:

```html
<p>2 < 3</p>
```

becomes:

```text
(p, "2 < 3")
```

A practical implementation can enter `TAG_OPEN`, and on failure append `<` and return to `DATA`.

### Malformed tag

For a malformed tag:

1. Scan until `>` or EOF.
2. Do not change block or anchor state.
3. Resume at `DATA`.

This prevents malformed markup from corrupting the state machine.

### Mismatched closing tag

Ignore it.

Example:

```html
<p>Text</h1>
```

The `</h1>` does not close the paragraph. At EOF, the paragraph recovery rule applies.

### Nested block tag

Recommended behavior:

- Do not open the nested block.
- Treat its markup as ignored.
- Continue collecting text into the existing block.

The fixture generator should prohibit this case.

### Nested anchor

Recommended behavior:

- Ignore the nested opening `<a>`.
- Continue collecting its text into the current anchor.
- The first matching `</a>` closes the current anchor.

The fixture generator should prohibit this case.

### Duplicate `href`

Use the first `href` only. Ignore later occurrences.

The fixture generator should emit exactly one.

### Missing `href`

Still collect the anchor text into the enclosing block, but do not append a link.

The fixture generator should prohibit missing `href`.

### Output allocation failure

Because exceptions are unavailable, every append operation should return a status:

```text
0 = success
1 = capacity exhausted
```

On failure, terminate parsing with a deterministic parser error status and retain only the output successfully produced so far. Do not write past capacity.

## 6. Edge-Case Checklist

The following are useful fixture and parser tests.

| Input | Output |
|---|---|
| `<p>Hello</p>` | `blocks=[(p,"Hello")]` |
| `<p>  Hello   world  </p>` | `blocks=[(p,"Hello world")]` |
| `<p>Hello\n\tworld</p>` | `blocks=[(p,"Hello world")]` |
| `<p>  </p>` | `blocks=[]` |
| `<p>Hello &amp; goodbye</p>` | `blocks=[(p,"Hello & goodbye")]` |
| `<p>&lt;x&gt; &quot;q&quot; &#39;</p>` | `blocks=[(p,"<x> \"q\" '")]` |
| `<p>&#65; &#8364;</p>` | `blocks=[(p,"A €")]` |
| `<p>A &unknown; B</p>` | `blocks=[(p,"A &unknown; B")]` |
| `<p>A <b>B</b> C</p>` | `blocks=[(p,"A B C")]` |
| `<p>A <!-- hidden --> B</p>` | `blocks=[(p,"A B")]` |
| `<script><p>hidden</p></script><p>shown</p>` | `blocks=[(p,"shown")]` |
| `<style>.x{display:none}</style><h1>Title</h1>` | `blocks=[(h1,"Title")]` |
| `<h1>One</h1><h2>Two</h2>` | `blocks=[(h1,"One"),(h2,"Two")]` |
| `<p>Before <a href=/x>Link</a> after</p>` | `blocks=[(p,"Before Link after")]`, `links=[("/x","Link")]` |
| `<p><a href='/x'> A   B </a></p>` | `blocks=[(p,"A B")]`, `links=[("/x","A B")]` |
| `<p><a href='/x?a=1&amp;b=2'>Link</a></p>` | `links=[("/x?a=1&b=2","Link")]` |
| `<p><a href=/x>One</a> <a href='/y'>Two</a></p>` | `links=[("/x","One"),("/y","Two")]` |
| `<p><a href=/x>Text</a></p>` | `blocks=[(p,"Text")]`, `links=[("/x","Text")]` |
| `<p>2 < 3</p>` | `blocks=[(p,"2 < 3")]` |
| `<p>Text</h1>` | no block until EOF recovery; final block may be `(p,"Text")` if EOF flushing is enabled |
| `<p>Text` | `(p,"Text")` under EOF block-flush recovery |
| `<!-- no terminator` | `blocks=[]`, parser finishes safely |
| `<script>unclosed` | `blocks=[]`, parser finishes safely |
| `<a href=/x>outside</a>` | prohibit in fixtures; otherwise record link only if outside-anchor recording is intentionally supported |
| `<p><p>nested</p></p>` | prohibit in fixtures; parser should retain deterministic outer-block behavior |
| `<p><a href=/x><a href=/y>x</a></a></p>` | prohibit in fixtures; parser should not overwrite active anchor state |

The key implementation invariant is:

```text
Every byte is either:
- consumed by the current state,
- preserved as text,
- or discarded by a recognized comment/script/style region.
```

No state should perform unchecked lookahead, and every potentially unbounded scan must stop on either its terminator or `input_length`.
