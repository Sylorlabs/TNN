## 2. THE LEARNER: EXPLICIT PRODUCTION / PUSHDOWN REPRESENTATION

**Frozen design. No part of §2 reads the stage integer, the seed, a token id, a
role code, a type code, or a keyword subrole.**

Zag has no structs and no arrays, so every induced structure is a **record in the
flat `[]u8` learner arena** at a documented offset with a documented stride. The
complete layout is in §2.7.

### 2.1 R1 — INDUCED DELIMITER STRUCTURE (the pushdown discovery)

The learner discovers, from VALID examples only, an **opener -> closer-set
relation over opaque tokens**, by a hypothesis-free statistic followed by a
greedy depth-maximising selection. No delimiter is named.

**R1a. Pair support.** For every ordered pair of distinct tokens `(o,c)`,
compute `sup(o,c)` = the number of VALID examples in which, under the hypothesis
that `(o,c)` is the *only* bracket pair and all other tokens are atomic, the scan
maintains a stack such that every `o` is matched by a `c`, every `c` is matched
by an `o`, and the stack is empty at end of input. This is a pure function of
the token stream.

**R1b. Joint consistency.** For a pair set `P`, define the scan: on token `t`,
if `t` is a closer of some opener in `P`, pop the **nearest** opener whose
closer-set contains `t`; independently, if `t` is an opener in `P`, push `t`. (A
token may be both.) `P` is **consistent** iff all VALID examples scan to an
empty stack with every pop matched by a designation and every push matched by a
pop.

**R1c. Greedy selection, lexicographic objective `(consistentCount, maxDepth)`.**
`P := {}`; repeatedly try every `(o,c) not in P`, evaluate `(count, maxDepth)` of
`P ∪ {(o,c)}`, and adopt the best **only if it strictly improves** the current
pair lexicographically. Ties broken by lower opener id then lower closer id.
Maximum 8 pairs. Fully deterministic, no randomness.

**R1d. Reduction.** Under the final `P`, each VALID example is reduced to a
**skeleton**: the token sequence with the *interior* of every balanced region
replaced by a single typed placeholder `PH_k` (symbol `31+k`, where `k` indexes
the opener's pair). Balanced regions nest; the reduction is a single
deterministic left-to-right pass. The **nesting depth** of each example is
recorded and reported.

*Why this is pushdown and not statistics:* the accepted/generating object is a
**stack discipline over opaque terminals**, discovered from data. Recursion is
the recursion of the bracket relation, not a loop in a probability table.

### 2.2 R2 — INDUCED PRODUCTIONS (right-linear, per block context)

For each **block context** `k` (the top level, plus one per induced pair), the
VALID examples yield a set of skeletons over `tokens ∪ {PH_k}` where `PH_k` is
the placeholder for *that* context's body. Inference, per context:

1. Build the prefix trie of the context's skeletons.
2. Merge two trie nodes iff their **VALID follower sets are equal AND their
   accept flags are equal**, iterating bottom-up to a fixpoint. (This is
   suffix-tree compaction; it is what makes a *right-linear* grammar.)
3. Mark the initial node as accepting.
4. Add the `PH` self-edge: the context's start state has a transition on `PH_k`
   back to a body-start state, and the body-start state is the context's own
   start state, with the **return state pushed on an explicit stack**. This is
   the single recursive edge and it is what makes the model a PDA rather than a
   DFA. Nullable bodies (empty statement list) are permitted by an explicit
   epsilon transition from the body-start state.

**Productions are emitted as explicit records** (§2.7) of the form
`p_q -> sym p_q'` and `p_q -> sym` and `p_q -> eps` and `p_q -> PH_k p_body`,
with a VALID support count per production. Generation walks these records
forward; acceptance walks the same records.

### 2.3 R3 — TYPING (induced, negative-pruned)

Induced **type classes of atoms by context signature**: two atom tokens are the
same type iff for every operator token and every operand slot, one occurs in
that slot in some VALID example iff the other does. Then the induced signature
table `sig(op) -> (lt, rt, res)` is read off VALID occurrences of the operator
in operand position, and **every admissible pair that occurs in an INVALID
example is deleted** (negative-consistency pruning). Unobserved pairs stay
permissive; that asymmetry is stated, not hidden.

### 2.4 R4 — SCOPE (induced)

For each VAR token `v`, the learner induces a **bind pattern** `(b, v, a)`: the
token triple that surrounds `v` in VALID examples, selected as the
highest-support `(b,a)` pair, requiring that `b` never occurs as a plain operand
in VALID. Uses of `v` are then checked by an explicit stack discipline: push on
a bind-pattern occurrence at its depth, pop when depth falls below the pushed
depth, and a use is in scope iff the stack for `v` is non-empty with top depth
`<=` the use's depth. The rule is **verified against the INVALID corpus**; any
INVALID example that no induced rule explains is reported as `UNEXPLAINED`.

### 2.5 R5 — GLOBAL CONSTRAINT: THE `(M, c, val)` SOLVER

Implements AMENDMENT 1's identifiability argument. Search over
`M ∈ {2,4,8,16,32,64}`, `c ∈ [1, M-1]`, and an **injective** map `val` from the
6 induced ATOM tokens into `[0, M)`. Unit propagation from single-atom and
two-atom VALID examples, then bounded backtracking search with the reflection
`val -> c - val` broken **only** by VALID examples with 3 or more atoms.
A hypothesis `(M,c,val)` is **accepted** iff

- every VALID example has `sum of val(atom) == c (mod M)`, and
- every example that the learner's *own* R1-R4 accept path calls VALID but whose
  label is INVALID is a counterexample (must be zero), and
- no INVALID example that R1-R4 already reject is used as evidence.

**The search returns the full set of accepted hypotheses, not the first one.**
The size of that set is reported as `GLOBAL-AMBIGUITY`. This is the direct
consequence of the measurement in §3, and it is the honest form of the criterion.

### 2.6 R6 — THE GENERATOR AND THE UNCONDITIONAL FOLD

Generation is a forward walk of the R2 production records: expand the start
nonterminal, choose each production with probability proportional to its induced
VALID support, recurse through `PH_k` by pushing the return state. Operand
choice at operator positions is restricted by the **R3 typing table**. Variable
choice is checked by the **R4 scope rule**. The atom multiset is then completed
so that the **R5 congruence holds**, using the learner's own `val` map and its
own residue table — the same table the acceptor uses.

**There is exactly one accept path.** It is an unconditional fold:

```
accept(x) = R1_scan(x) AND R2_parse(x) AND R3_types(x) AND R4_scope(x) AND R5_global(x)
```

Every conjunct is always evaluated. There is no flag, no guard, and no branch
that decides *whether* to consult an induced structure. That is the whole of the
zero-diff claim, and §4 measures it rather than asserting it.

### 2.7 ARENA LAYOUT (documented strides; all cells i32 little-endian)

Learner arena `P`, flat `[]u8`. Strides are in bytes; `get32/set32` little-endian.

| structure | offset | stride | capacity | contents |
|---|---|---|---|---|
| header | 0 | 4 | 64 | counters, `nPair`, `nState`, `nProd`, induction stats |
| token alphabet | 256 | 4 | 32 | per-token: seen-in-valid, seen-in-invalid, role code, type id, val |
| pair table | 384 | 12 | 8 | `+0` opener, `+4` closer, `+8` support |
| closer-set table | 480 | 8 | 32 | `+0` opener, `+4` closer (multiple rows per opener) |
| state table | 768 | 24 | 512 | `+0` accept flag, `+4` transition-list offset, `+8` transition count, `+12` context id, `+16` depth class, `+20` reserved |
| transition table | 12800 | 8 | 4096 | `+0` symbol (`0..30` terminal, `31+k` placeholder, `-1` epsilon), `+4` target state |
| production table | 45696 | 12 | 4096 | `+0` lhs state, `+4` rhs symbol, `+8` target state, `+12` wait -> see below |
| type-sig table | 96000 | 4 | 32*32 | indexed `[op*32+cls]`, admissible flag |
| negative-prune set | 110336 | 8 | 2048 | `+0` op, `+4` operand-slot-coded pair, pruned |
| scope table | 126720 | 12 | 32 | `+0` bind-head token, `+4` var token, `+8` assign token |
| global table | 131072 | 4 | 512 | `M`, `c`, `val[32]`, residue decomposition `len/a/b/c` per residue |
| skeleton buffer | 140000 | 4 | 128 | reduced sequence of one example |
| artefact buffer | 141000 | 4 | 128 | generated token sequence |

**Production record, stride 12:** `+0` = lhs state, `+4` = rhs symbol
(`-1` = epsilon), `+8` = target state. Derived productions `p_q -> PH_k p_body`
are represented by `rhs symbol = 31+k` and `target = body-start state of
context k`. Total arena 160000 bytes, allocated once.

## 3. PRE-IMPLEMENTATION MEASUREMENTS ON THE FROZEN FIXTURE (DISCLOSED)

I ran two **world-side probes** (`p6_inspect.zag`, `p6_ident.zag`,
`p6_ident2.zag` — all contain `p6_lang`/`p6_ckcore` and are **not** part of any
learner translation unit) on the frozen corpora **before writing any learner
code**. Three results, all disclosed now:

**M1. The prior report's §3.2 claim is FALSE for set A.**
`p6/formal-induce/REPORT.md` §3.2 states "of the six single-atom programs at
stage 0, exactly one is valid". For set A (seed 1009, `M=64`, `C=17`, atom values
`30,57,38,3,43,0`) **none** of the six single-atom programs is valid: no atom
value is congruent to 17 mod 64. The VALID atom-count histogram at stage 0 is
`2:2 3:4 4:8 5:10 6:51 7:37 8:18` — there is **no 1-atom VALID example at all**.
The claim is true for set B (`M=16`, `C=1`, atom value 1 exists:
`1R[`), which is presumably where it came from. It was reported as a general
property of the fixture. This matters because AMENDMENT 1 A2 *rests* on 1-atom
valid examples existing; for set A they do not, so set A's global constraint is
anchored only by 2-atom valid examples.

**M2. THE TRUE MODULUS IS NOT UNIQUELY RECOVERABLE FOR SET A.**
For set A, `m = 32` with `c = 17` and the true `val` map reduced mod 32 gives
`VALIDviol = 0` and `GLOBALinvalid_sat = 0` at **every** stage — it separates the
corpus exactly as well as the truth `m = 64`. `m = 16` fails (3 global-invalid
examples satisfy it), `m = 8` fails (13), `m = 4` (14), `m = 2` (32). For set B
the true `m = 16` is the unique separator (`m=8` leaves 3 satisfied). So:
**set A's modulus is recoverable only up to the divisor ambiguity
`{32, 64}`.** This is an identifiability theorem about the corpus, not a learner
failure, and it was knowable from AMENDMENT 1's own argument once one notices the
constraint is a congruence.

**M3. Consequences carried into the predictions, not into the bars.**
A learner that recovers the `m=32` member of the ambiguity class will generate
programs whose true residue is `17` or `49` mod 64 with roughly equal weight, so
roughly half its self-accepted artefacts are rejected by the sealed checker. I
therefore predict (§6, P7) that **set A unseen-valid is capped near 50% of the
learner's self-accepted count for reasons of identifiability, while set B is
capped near 100%** — a difference that is a property of the fixture, not of the
learner, and which a reader must be able to see through.
