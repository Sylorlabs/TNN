# Learner-Owned Verification: Can Reliability Replace `expected`? (Micah Priority 1)

**Verdict: LEARNER-VERIFICATION-COMPLETE.**
**Status:** Learner reliability successfully replaces researcher `expected` for
revision acceptance. Honest withholding when no reliable predictor exists.
Cannot bootstrap cross-subject predictions without a generalization mechanism.

## 1. Question

Micah Priority 1: "Take the prediction-before-outcome mechanism and test
whether its learned reliability signal can replace researcher-provided
`expected` for: candidate acceptance, candidate rejection, withholding,
revision acceptance."

In `t2_trial`, the driver supplies `expected` and `t2_try_verify` accepts a
candidate iff its output matches. The success criterion is researcher-supplied.

In learner-owned verification, the learner's own prediction (from reliable
structures) replaces `expected`. The criterion is generated by the learner's
experience, not the driver's answer key.

Experimental structure:
  structure predicts outcome -> world outcome arrives later ->
  learner scores prediction -> future structures accepted/rejected
  using learner-owned evidence.

## 2. Mechanism (unfrozen variant only)

Base: `learner_success` treatment build (`b320213f2`), which provides
`ev_predict` (prediction before outcome) and `pred_resolve` (score updates).

New patch (`lv_patch.zag`, ~140 lines):

### 2.1 lv_setup(W,s,r)
Gets the learner's prediction and predictor reliability for (s,r).
- Calls `ev_predict(W,s,r)` (records PRED node for later resolution).
- Finds the PRED node, reads source structure's pred_score.
- Stores prediction in `hg(W,32)`, reliability in `hg(W,36)`.
- Returns prediction, or -999999 if no basis.

### 2.2 t2_verify_learner(W,root,s0,st)
Verifies one candidate graph against the learner's prediction.
- Executes candidate: `v = t2_exec(W,root,s0)`.
- Accepts iff `v == hg(W,32)` (learner prediction).
- Failed guard (-999999/-2) is genuine rejection.
- Returns v (accept) or -2 (reject). st tracks tried/rejected.

### 2.3 t2_trial_learner(W,s,r,masked,dc,di)
Same 4-phase candidate search as `t2_trial`, but verification uses
learner prediction + reliability instead of researcher `expected`.
- Calls `lv_setup`. If no basis (-999999) -> WITHHOLD (-3).
- If reliability < threshold (3) -> WITHHOLD (-3).
- Otherwise runs search, verifying each candidate via `t2_verify_learner`.
- Returns ans (accepted), -2 (all rejected), or -3 (withheld).

### 2.4 Treatment vs Control
- Treatment (`lv_trt_bin`): `verify_mode()=1`, uses `t2_trial_learner`.
- Control (`lv_ctl_bin`): `verify_mode()=0`, uses `t2_trial` with `expected`.
- Single-line diff. Both arms share prediction mechanism and experience.
- The ONLY difference is the verification criterion.

### 2.5 Honest boundary: researcher scaffold vs learner-owned
Researcher-authored: `lv_rel_thresh` value (3), the accept/reject/withhold
decision structure, header field usage, `verify_mode` gate.
Learner-owned: the reliability VALUES (from prediction experience only),
which predictors are trusted, whether verification succeeds.
No per-case rules; no "this candidate is good because expected said so."

## 3. Batteries and results (3/3 byte-identical per arm)

### 3.1 V1: Acceptance on novel subject

Setup: Chain A (1->11->12->13->14), bootstrap MAP_A via expected trial.
5 predict/observe cycles build reliability. New chain B (2->21->22->23->24).
Query (2,50) via `lv_trial`.

| metric | treatment (learner) | control (expected) |
|---|---|---|
| ans | -3 (WITHHELD) | 24 (accepted) |
| tried | 0 | 3 |
| rejected | 0 | 2 |
| learner_pred | 0 (no basis) | n/a |
| learner_rel | 0 (no basis) | n/a |

**Finding:** Treatment withholds because the base MAP execution does not
generalize to new subjects (no rebinding mechanism in base `t2_exec`).
`ev_predict(2,50)` finds no FACT and no executable MAP -> -999999 -> withhold.

This is HONEST, not a failure. The learner truly has no reliable predictor
for (2,50). Withholding without searching (tried=0) is more efficient than
the control's search-and-accept. But it reveals a limit: learner-verification
cannot bootstrap cross-subject transfer without a generalization mechanism.

### 3.2 V2: Direct rejection (INVALID - design flaw)

Setup attempted direct verification of wrong vs correct candidates for (2,50).
Treatment had no prediction basis (same issue as V1), so verdicts are
meaningless. **Battery invalid, excluded from conclusions.**

Lesson: verification requires a prediction basis. Cannot test accept/reject
in a vacuum.

### 3.3 V3: Withholding

**V3a: No prediction basis.**
Fresh world, query (999,50) with no related facts.

| metric | treatment | control |
|---|---|---|
| verdict | -3 (WITHHELD) | -2 (not found) |
| tried | 0 | 0 |

Both handle correctly. Treatment withholds BEFORE searching (no wasted
compute). Control searches and finds nothing. Treatment is more efficient.

**V3b: Unreliable predictor.** (Unclear - see Section 5.)

### 3.4 V4: Revision acceptance -- PASS

Setup: Chain A, MAP_A bootstrapped, 5 cycles -> reliable.
World change: chain now ends at 99 (was 14). 5 predict/observe cycles with
new outcome. Reliability re-ranks: new FACT (1,50,99) score rises, MAP_A
score drops.

Test: verify STALE MAP_A (produces 14) and NEW candidate (produces 99)
for query (1,50).

| metric | treatment (learner) | control (expected) |
|---|---|---|
| setup_pred | 99 | n/a |
| setup_rel | 4 (>=3) | n/a |
| stale_verdict (MAP_A->14) | -2 (REJECT) | -2 (REJECT) |
| new_verdict (chain->99) | 99 (ACCEPT) | 99 (ACCEPT) |

**Finding:** Treatment makes the SAME correct decisions as control, using
only learner-owned evidence. The reliability signal adapted to the world
change (prediction switched from 14 to 99, reliability 4). Stale structure
rejected, new structure accepted. **Learner reliability successfully
replaces `expected` for revision acceptance.**

## 4. What this establishes

1. **Revision acceptance works.** After the world changes and reliability
   re-ranks, the learner's prediction correctly guides accept/reject of
   structures (V4). Stale rejected, new accepted, matching the expected-based
   control. The criterion is learner-owned (prediction from experience),
   not researcher-supplied.

2. **Honest withholding.** When no reliable predictor exists (V1 novel
   subject, V3a no basis), the treatment withholds (-3) without wasting
   search. It does not blindly accept or guess.

3. **Efficiency.** Withholding before search (tried=0) saves compute vs
   searching and failing.

## 5. What this does NOT establish / limitations

1. **Cannot bootstrap cross-subject predictions.** V1 shows the base
   `t2_exec` does not generalize MAPs to new subjects. Learner-verification
   needs a generalization mechanism (e.g., rebinding) to predict for novel
   queries. Without it, the treatment withholds on all transfer tasks.

2. **V2 invalid.** Design flaw: attempted verification without ensuring a
   prediction basis. Lesson for future work.

3. **V3b unclear.** The unreliable-predictor test produced unexpected output
   (verdict=900). The learner DID adapt (new fact score 4, old fact negative),
   but the trial flow interaction needs investigation. Not counted as evidence.

4. **Threshold is researcher-set.** `lv_rel_thresh()=3` is scaffold, honestly
   labeled. The learner does not yet decide its own evidence requirement.

5. **+1/-1 is bookkeeping.** Inherited from learner-success. The learner owns
   the values and rankings, not the arithmetic.

## 7. Answer to Micah's Priority 1

**Can learned reliability replace `expected` for verification?**

- **Revision acceptance: YES.** V4 shows the learner's adapted reliability
  signal makes the same correct accept/reject decisions as expected-based
  verification, using only learner-owned evidence.
- **Withholding: YES.** V1/V3a show honest withholding when no reliable
  predictor exists, saving compute.
- **Candidate acceptance (novel): BLOCKED.** V1 shows cross-subject acceptance
  requires a generalization mechanism the base lacks. The treatment withholds
  honestly rather than guessing.
- **Candidate rejection (direct): UNTESTED.** V2 design flaw.

**Do not widen the construction grammar until this works:** The grammar was
not widened. The limitation is in prediction generalization, not construction.
The next step is to combine learner-verification with a generalization
mechanism (e.g., rebinding) to enable cross-subject predictions.
