## Compiler fault found and worked around

- The first control build returned `pred=-2` on every disagreement while the
  treatment arm behaved correctly. Isolated to the `if(rank_fixed()==1){...}
  else {...}` form where the else branch is skipped: with `rank_fixed()=1`
  the disagree path miscompiled (minimal repros of the if/else shape alone
  passed, so the trigger is specific to the full function context).
- Workaround: both arms now run the identical reliability-ranking code; the
  control applies the hardcoded rank as a post-hoc override
  (`if(rank_fixed()==1){pick=7;}`) with no else branch. Documented in
  `pl_patch.zag` and REPORT.md. Treatment output byte-identical before and
  after the restructure, confirming behavior preservation.
