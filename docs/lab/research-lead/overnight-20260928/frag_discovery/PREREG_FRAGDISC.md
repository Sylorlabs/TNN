## 3. Mechanism design (frozen)

There is no population of candidate programs, no scalar score, no ranking,
no beam, no retention by score anywhere. All search is deterministic
fixed-order enumeration. No randomness exists in the design.

### 3a. Straight-line base constructor

Grammar (frozen): leaves IN0, IN1, PUSH c for c in {-1,0,1,2,3}; unary NEG;
binary ADD, SUB, MUL, DIV, MOD. EQ/LT/GT are excluded: the predicted T3
solution is comparison-free and the smaller space keeps the budget honest.
Enumeration: bottom-up by tree size, sizes 1..8 ascending. Level 1: leaves.
Level s>1: NEG over level s-1 classes (fixed order), then binary ops in the
fixed order ADD, SUB, MUL, DIV, MOD over splits (a, s-1-a) for a in 1..s-2,
operand classes in first-seen order; commutative ops (ADD, MUL) restricted
to index pairs i<=j. Per-level class cap K=5000 with deterministic
first-seen truncation (disclosed completeness/budget tradeoff).
Observational equivalence: behavior = output vector on the task train
episodes, computed compositionally with frozen VM edge semantics (DIV:
divisor 0 yields 0; MOD: mod_nonneg; i32 wraparound identical to Zag i32
arithmetic). The first-seen class per behavior is kept; all later
equivalents are discarded. One new distinct behavior counts as one
candidate evaluation; the run aborts FAIL past 1M (not expected).
Accept: the first behavior exactly equal to the target on ALL train
episodes. The winning class is reconstructed to a postfix stack program
and verified exact by executing it on the real VM before it is reported.
Used for: T0, T2, T3 (full VM) and as the region-body synthesizer (3c)
with the P-VM op subset.

### 3b. Routing (frozen, generic)

Kink analysis on train episodes: sort by x; kink at interior x_j iff
(t_j - t_{j-1}) != (t_{j+1} - t_j). K_T is the kink set.
- R1: single-input, K_T non-empty, library holds an input-agnostic
  single-input fragment whose kink set is a subset of K_T -> composer (3e).
- R2: single-input, K_T non-empty, no such fragment -> assembler (3c) iff
  |K_T| == 1; otherwise FAIL (assembler scope is single-kink by design).
- R3: otherwise (K_T empty, or two-input) -> base constructor (3a).

### 3c. Case-capable assembler (the amendment core)

Scope: single-input P-VM tasks with exactly one kink. This is the
case-capable base constructor the `*` clause requires.
1. Partition: R_lo = episodes with x <= kink x_j; R_hi = the rest.
2. Region repair: enumerate bodies sizes 0..4 over leaves {TOP} plus
   {PUSH c: c in -1..3}, unary {NEG}, binary {ADD, SUB, MUL} (all
   P-VM-valid), fixed order; TOP denotes the value already on the stack
   (compiles to the empty program); behavior computed with TOP = x; first
   exact body per region wins. Size 0 = identity.
3. Chain emission (frozen layout): let A be the smaller region (tie: the
   region containing the smallest x), B the other. V_A = A's train values
   in ascending order. For i in 0..|V_A|-2 emit DUP, PUSH(-v_i), ADD,
   JZ L_A. For the last value emit DUP, PUSH(-v_last), ADD, JNZ L_END.
   At L_A emit body_A; if body_B is non-empty emit JMP L_END. At L_END
   emit body_B. All jump targets are absolute addresses computed from the
   layout. This is the finite JZ decision-chain route of redesign
   exhibit 4: genuine branching structure, P-VM-valid by construction.
4. Verification: pvm_valid == 1 on the fragment (F-SMUG audit), exact on
   all train episodes on GENEXEC2-P, total ops (main [IN0, CALL f] plus
   fragment body) <= 40 (F-MEM). Violation of any check is FAIL, not a
   quiet repair.
T1 instance (predicted): R_lo = x in -8..-1 with body [NEG]; R_hi =
x in 0..8 with body []; A = R_lo (8 values); emitted fragment is 33 ops;
main [IN0, CALL0] is 2 ops; total 35 <= 40.

### 3d. Inducer: fragment detection from experience (frozen)

A fragment is detected (not supplied) iff ALL of the following hold; each
step is logged:
1. Extraction: the task solution came from the assembler (M = [IN0, REST],
   fragment candidate = REST) OR the base solution contains a MOD op
   (periodic folds; v1 rule carried over).
2. Input-agnosticism: the candidate body contains no IN0/IN1.
3. Signature: output vector on probe set S = {-4..4} (S x S grid for
   two-input fragments), executed on the task's VM with probe inputs
   pushed on the stack.
4. Kink set: kinks of the signature function on S (same kink rule as 3b).
5. Dedup: the signature differs from every stored fragment signature;
   otherwise DEDUP-SKIP and no promotion (B-F3 guard).
6. Generality gate: run the body on s in -12..12 (grid for two-input);
   verdict GENERAL iff exact against the task target everywhere, else
   TRAIN-SCOPED. Promotion happens under either verdict: on the P-VM any
   finite JZ chain is inherently train-scoped (a finite chain covers
   finitely many values), so refusing train-scoped fragments would refuse
   the construct under measurement; the verdict is recorded honestly and
   reported. Confirmation status starts UNCONFIRMED and flips to
   CONFIRMED on first composer reuse.
Promotion: assign the next fragment id; store id, body, signature, kink
set, input-agnostic flag, generality verdict, confirmation status, and
the inducing task. Log the INDUCE event with the extraction trace. The
library persists across tasks in run order T0..T5 and is committed as
LIBRARY.md (the persistence record).

### 3e. Composer: RETRIEVE + CALL reuse (frozen)

Retrieval: for each library fragment in id order, log RETRIEVE-DECISION
with the reason. A fragment is retrieved iff it is input-agnostic AND
single-input AND its kink set is a subset of the task kink set K_T.
For each retrieved fragment (id order) log RETRIEVE with the kink-subset
justification (the a priori behavioral match).
1-CALL: P2 ranges over SEG13 = [PUSH-1, PUSH0, PUSH1, PUSH2, PUSH3, IN0,
IN1, ADD, SUB, MUL, NEG, DUP, DROP] in this fixed order, lengths 0..3
(2380 candidates). Candidate [IN0, CALL f, P2], executed on the P-VM
train episodes. First exact wins. If none, log 1CALL-EXHAUSTED with the
count.
2-CALL: P2 lengths 0..3, P3 lengths 0..2, ordered by (len(P2)+len(P3))
ascending then lexicographic. Candidate [IN0, CALL f, P2, CALL f, P3].
First exact wins.
On success: pvm_valid == 1 on the main program and every called fragment
(F-SMUG audit); total ops (main plus all called fragment bodies) <= 40
(F-MEM); exact on all train episodes. Log COMPOSE-SUCCESS with the
program, plus one RETRIEVE-CALL-SITE event per CALL site recording the
fragment id, the kink-subset match, and the sub-behavior confirmed by the
exact-train run. Composer solutions are not re-induced (inducer rule 3d.1
covers assembler and MOD-base solutions only).
Predicted: T4 [IN0, CALL0, PUSH2, SUB, CALL0] (5 + 33 = 38 ops);
T5 [IN0, CALL0, IN0, PUSH2, SUB, CALL0, ADD] (7 + 33 = 40 ops).

## 6. Falsifier watch (frozen from the battery prereg)

- F-TRICK: any jump-free GENEXEC2-P program achieving v2-SOLVE on
  T1/T4/T5 with ops <= 40 voids the affected task pending
  re-investigation. The base grammar contains no jumps, so a base SOLVE
  on a P-VM task fires F-TRICK (the task is VOID, not passed).
- F-SMUG: a P-VM task final program (main plus all called fragment
  bodies) containing DIV, MOD, LT, EQ, or GT is VOID. Audited in code by
  pvm_valid on every emitted program; a violation is reported, never
  silently absorbed.
- F-MEM: total ops over the 40 cap is not SOLVE.
- B-F1: T4/T5 solved without retrieval events falsifies the composition
  claim. Guard: retrieval events are mandatory in the trace.
- B-F2: fragments that are whole-task solutions with no extraction step
  falsify the induction claim. Guard: the extraction pipeline (factor,
  input-agnostic check, signature, dedup, generality gate) is logged per
  induction.
- B-F3: near-duplicate fragments accumulating falsify semantic indexing.
  Guard: signature dedup enforced and logged.
