## 2. Objective

Run a clean lifetime-learning evaluation of the TNN contestant on fresh
unseen worlds, with the contestant frozen (including the known one-line
bug fix) BEFORE world generation, zero Python anywhere, and full
determinism evidence.

Primary question: does the corrected frozen TNN again score
near-perfectly on fresh unseen worlds?

Secondary: harder sealed variants probe whether the architecture
generalizes beyond the original difficulty or fit the original
difficulty profile.

## 3. Non-goals and claim discipline

- This wave does NOT claim L3 for any mechanism. It measures behavioral
  lifetime-learning capability.
- Do NOT claim "TNN beats LLMs". The serious LLM baseline remains
  PENDING (no credentials authorized, no LLM run in this wave).
  Track separately: TNN CLEAN SCORE vs LLM BASELINE: PENDING.
- Do NOT claim "TNN beats humans".
- Do NOT reuse the old evaluation worlds for the canonical score.
- If the clean wave succeeds, the honest claim is: the frozen TNN
  architecture achieves near-perfect lifetime learning on fresh unseen
  synthetic worlds with tiny persistent state. It does NOT establish
  superiority over LLMs.

## 5. Contestant freeze protocol

5.1 The contestant source and binary hashes are recorded in a freeze
    commit BEFORE any C1-CLEAN world generation begins.

5.2 C1-CLEAN worlds are generated AFTER the contestant freeze commit.
    New seeds are derived after the freeze. The worker does not view
    seed values during derivation (mechanical /dev/urandom derivation,
    blind shell handling; verified by hash only).

5.3 The contestant is never modified after the freeze. If any
    contestant code changes after world generation, the wave is VOID;
    refreeze with a new unseen seed and regenerate.

## 8. Hard variants (sealed, exploratory)

In addition to the 3 canonical worlds, 2 HARD worlds (H0, H1) are
generated with a separately frozen `c1_clean/world_gen_hard.zag`.
Hard worlds use the SAME 63-query structure and turn protocol, but
with harder content. The contestant is NOT modified to accommodate
hard worlds.

Hard modifications (all in the generator, before its freeze):

- H-B DEEPER CHAINS: stage B uses 3-hop chains for ci<6 and 4-hop
  for ci>=6 (was 2-hop/3-hop). The chain query builder is extended
  to 4 relations. Tests deeper compositional chains.
- H-J HEAVIER INTERFERENCE: stage J emits 4000 noise observations
  (was 2000). Tests delayed reuse after substantially more
  interference.
- H-C MORE CORRECTIONS: stage C runs 5 immediate correction
  episodes (was 3), plus the delayed correction and 2 collateral
  probes. Query IDs C1-C5 immediate, C6-C7 collateral, C8-C9
  delayed retention. Total C queries: 9 (was 8). Tests multiple
  corrections over time.
- H-L LAW REVERT: stage L adds a second law-change notice reverting
  pb to its ORIGINAL rule, with 2 re-adaptation queries (L3-L4
  under reverted law) and 1 retention query (L5). Total L queries:
  5 (was 5: L1-L3 adaptation, L4-L5 retention; now L1-L2 new-law,
  L3-L4 reverted-law, L5 retention). Tests law changes that later
  revert.
- H-D UNRESOLVED STAYS UNRESOLVED: stage D setup 2 never receives
  discriminating evidence; D3-D4 query the unresolved setup and
  the correct answer remains UNRESOLVED. Tests contradictions
  where neither statement is immediately resolvable.

Hard world scoring: same exact-match protocol. Hard scores are
reported separately as EXPLORATORY-HARD, not part of the canonical
63-query clean score. The canonical TNN CLEAN SCORE is the mean
over the 3 canonical worlds only.

## 9. Run protocol

9.1 Each world (canonical W0-W2, hard H0-H1): contestant runs 3 full
    times from fresh state. Cognitive replies must be byte-identical
    across all 3 reps per world (determinism).

9.2 Sequencer: `c1_clean/run_race.sh` (shell only, no Python).
    Per-turn process spawning as in the void wave.

9.3 Tool budgets: F stage 3 calls, G stage 4 calls (INTERVENE
    allowed). Exceeding budget rejects the call.

9.4 Save/load: runner archives state dir at save turn, resumes
    against archived copy in new path (true process boundary).
    Post-load checksum must match saved checksum.

## 10. Scoring

- Exact-match on query answers. UNKNOWN and UNRESOLVED are valid
  answers where the key specifies them.
- Canonical score per world: correct / 63.
- TNN CLEAN SCORE: mean correct over W0-W2 (and per-world scores).
- Hard scores: correct / 63 (H worlds keep 63 queries: B8 C9 D4
  E6 F3 G2 H6 A10 J9 K4 L5 = 66; see note) reported separately.

NOTE on hard query counts: H-C adds 1 query (9 vs 8), H-L keeps 5.
Hard total = 64. The hard score is X/64, reported separately and
never mixed with the canonical 63.

- Transfer measurements (examples-to-criterion T1 vs T2) reported
  per world as in the void wave.
- Cost ledger per world: wall_ms, peak_rss_kb, state_bytes,
  observations, tool calls, learned-structure ledger.
