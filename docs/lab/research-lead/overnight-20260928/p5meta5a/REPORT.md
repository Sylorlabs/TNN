# REPORT -- P5-meta5a: VOID. Harness cannot reach a solution that provably exists.

Branch `lane/ownership`. Successor to p5meta4, generated by the queue rule.
3/3 sha-identical. 18 fingerprint rows. No `*_ok` flags.

## WHAT THIS PHASE WAS FOR

`p5meta4` identified the blocker: the associative substrate **cannot
represent a mapping** independent of stored facts, so learning-to-learn
was unaskable. `p5meta5a` fixes the *substrate* rather than the question:
candidates are now 3-op **programs**, so a program generalises by
computing, not by being stored. There is no fact table at all.

## VERDICT: VOID

Every arm scores 300 (= never acquires) in all three families. **That is
a harness fact, not a learner fact**, and I am recording it as void rather
than as a negative result about learners.

## PROOF THE HARNESS IS AT FAULT

Solutions provably exist, and they generalise perfectly to the unseen
probe band:

| family | solutions on train | also correct on unseen probes |
|---|---|---|
| 0 | 5 | **5** |
| 1 | 5 | **5** |
| 2 | 6 | **6** |

So the criterion (`leader correct on the unseen probe`) is satisfiable,
and a program that satisfies it exists for every family.

**Root cause:** the population is a *cloning-only* evolutionary loop. The
fittest program is copied into the even slots, odd slots keep their old
value, and **no mutation operator exists anywhere in the source**. The
initial population is 24 draws from a 4-op ISA at depth 3 (64 possible
programs), and the leader-clone step can only ever move the population
*toward* whatever the current leader already is. If no solution is in the
initial draw, no number of trials can produce one.

Two arms share this defect, which is why all six arms are identical: the
prior phase and the acquisition phase use the same clone-only loop.

## DEFECTS FOUND (three, all mine, all before any result was believed)

1. **Population had only 4 distinct members.** Initial seeding was
   `(i*7+3)%4, (i*13+5)%4, (i*29+11)%4` — linear in `i mod 4`, so 24 slots
   collapsed to 4 programs. Fixed with a mixing hash; fingerprints then
   differed by family, confirming the fix.
2. **Inheritance homogenised the population.** Cloning the leader into
   *every* slot made the population one program. Fixed to partial
   (even slots only).
3. **Fitness/criterion category error.** The probe fitness compared every
   program against the answer at *one* probe query across all 10 training
   queries. A program cannot equal one value on 10 different inputs, so
   fitness was pinned and acquisition could never terminate. Fixed by
   scoring agreement with the family's function and using the unseen
   probe only as the criterion.

**I also made an analysis error worth recording.** Two independent Python
checks of the same `exec` disagreed, because I implemented `%61`
*after every op* in one and only at the end in the other. The Zag code
reduces only at the end. I resolved it by re-deriving the Zag semantics
exactly rather than trusting either earlier claim — which is what showed
the solutions exist and the harness is at fault.

## SUCCESSOR (per queue rule)

1. **Falsified**: nothing. This phase is void, not negative.
2. **Does NOT falsify**: the structural substrate as a route to
   representable mappings; genetic algorithms; meta-learning.
3. **Assumption that caused failure**: a clone-only evolutionary loop can
   search. It cannot. The harness needs a *generic* variation operator.
4. **Smallest structurally different successor**: add one generic
   point-mutation operator (perturb one op slot of one individual) with
   no domain knowledge, and re-run unchanged otherwise. That is a
   **harness repair**, not a new experiment, so it must be labelled as
   such — repairing the instrument is not evidence about learners.
5. **Architecture simplifiable?** Not yet; the substrate is still
   unexercised.
