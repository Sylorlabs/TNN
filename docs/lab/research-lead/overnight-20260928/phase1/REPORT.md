# PHASE 1 -- THE BOUND, CLOSED MECHANICALLY

Branch `ownership`. Hypothesis under audit:

> Learner state changes preference/ranking among researcher-eligible
> candidates but does not change the structural candidate space itself.

**Verdict: CONFIRMED, bounded.** Audited 1,025 `.zag` sources. 137 write
structure. **Zero** of those writes read learner state.

> **AMENDED after the Zag port** (`PORT_NOTES.md`). The bound is
> reproduced by `audit_struct.zag`: **0 levers across 574 structural
> writers**. The writer count differs because the Zag scanner accepts
> multi-line function headers that the Python single-line regex skipped,
> so the negative now holds over a larger surface. The defensible
> statement is "0 of 574" (or "0 of 137" under the narrower grammar) --
> both are zero, and the denominator depends on the scanner's function
> grammar. The bound itself is unaffected.

## METHOD, INCLUDING THE TWO AUDITORS THAT WERE WRONG

The instruction was to trace actual dataflow and not infer from names. Two
of my three auditors did exactly that wrong, and both failures are recorded
because the errors are the interesting part.

**v1 `audit_structure.py` -- line-coincidence matching.** Reported **94**
structural hits. False positive: `hc_full.zag`'s two structural writers are
`mat_inputs(G,W)` and `apply_kind1(G,W,OUTS,ni)`. Neither takes learner
state. v1 matched lines containing *any* state name *and* *any* sink name
with no scope check.

**v2 `audit_scope.py` -- added parameter scoping, still wrong.** Reported
**137 of 137** sources as genuine levers. The self-accumulation regex also
matched scalar self-assignment `x = x + ...`, which captures ordinary
locals and `i32` parameters. It reported "learner state via buffer `e`" for
`fn es(W:[]u8,e:i32,f:i32,v:i32)` in `bp2_full.zag` -- where `e` is an edge
index, not state. 137/137 was one artifact.

**v3 `audit_v3.py` -- type-aware.** Requires the writing function to have a
learner-state **array** parameter (`X:[]u8`, not `X:i32`) that is
**self-accumulating** and that the sink reads. Result: **0**.

The v1 and v2 numbers would each have been a publishable-looking claim, and
both were wrong. Recorded because a bound this strong needs its error bars.

## HAND VERIFICATION (not trusting v3)

`borrow/b23.zag:145-188`, `learn()`:

```
fn learn(W:[]u8,train:[]u8,nt:i32)[]u8 {
  let L:i32=1;
  while(L<=MAXQ() && bn==0){        // depth bound: compile-time constant
    let a:i32=0; while(a<nv && bn==0){   // nv = nvoc(): compile-time constant
      let b ... let c ... let d ...
        set32(seq,0,a); set32(seq,4,b); ...   // researcher-authored spec
        reset_graph(W);
        let root:i32=build_seq(W,seq,len);
        if(root>=0 && fits(W,train,nt,root)==1){ set32(best,...); bn=len; }
```

The candidate space is a **hardcoded 5-deep nested loop** over
`(L, a, b, c, d)` with bounds `MAXQ()` and `nvoc()` -- both compile-time
constants. `L` is a **local loop counter** (`let L:i32=1` at line 151,
`L=L+1` at 184), not learner state. Every candidate is enumerated
regardless of experience. `build_seq(W,seq,n)` writes `W` and takes only
`(W, seq, n)`.

Learner state enters at exactly one place: `fits(...)==1` decides whether to
**record** a candidate as `best`. It never decides whether to **enumerate**
one.

This is the pattern in all 137 sources: enumerate a fixed space, evaluate,
record which won.

## THE BOUNDED FINDING

> **Across the audited family, learner state selects among
> researcher-created candidate spaces but does not alter those spaces.**

The structural candidate space is fixed at compile time in every audited
source: hardcoded loop bounds, hardcoded vocabularies (`nvoc()`), hardcoded
spec arrays. Experience changes which pre-existing candidate is *preferred*,
scored, cached, or tie-broken. It does not add, remove, reshape, deepen,
reconnect, or rewrite any candidate.

## WHAT THIS DOES NOT ESTABLISH

* **Bounded to this corpus and this audit method.** Static analysis with
  type-aware scope resolution. It cannot see a structural change effected
  through a pointer alias or a shared global, and it audits only what is
  committed on this branch.
* **Static, not dynamic.** A mechanism could depend on state that is only
  materialised at runtime in a way the regexes miss.
* **Does not prove the bound is fundamental.** It proves it holds for the
  1,025 sources here. A mechanism that alters structure may simply not have
  been written yet -- which is exactly what Phase 4 is for.
* **The corpus's own substrate cannot express it.** Per `FORK_TESTS.md`,
  `sup[]` in `b24.zag` ranks but never gates (11 reads, all `sc>bestScore`;
  0 support-gated failures). So Phase 4 needs new infrastructure, not a new
  world.

## CONSEQUENCE FOR THE FRONTIER

Phases 6-9, 16, and 17 all failed for a reason this audit now names
mechanically: **every one of them varied selection within a fixed
researcher-authored space.** Scaling `N` (Phase 16) widened that space
without changing who authored it. Making frequency non-discriminative
(Phase 17) removed the signal while leaving the space fixed. Neither
operation could reach the ownership question, because ownership is a
property of *who generates the space*, not of how well it is searched.

This is why the instruction not to return to "beat counting" experiments
was right, and it is now a mechanical result rather than an intuition.
