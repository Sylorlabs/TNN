## A2.3 LLM baseline: BLOCKED_BY_TOOLCHAIN (replaces "pending credentials")

Prereg 9(f) required an OpenAI-compatible LLM adapter plumbing-tested against
a stub, with live runs pending credentials. That is withdrawn. Under the
pure-Zag rule the adapter cannot be built: the Zag toolchain has no TLS/HTTPS
client, and implementing TLS 1.2/1.3 over raw syscalls inside this program is
infeasible. No Python HTTP client is permitted. There is therefore no
mechanism in this environment by which a pure-Zag arena can call an LLM API.

Consequences:
- No LLM results are claimed in the pilot. The arena's LLM column is marked
  BLOCKED_BY_TOOLCHAIN, with this amendment as the reason.
- The contestant turn protocol (prereg section 5) is contestant-agnostic and
  is frozen as the LLM interface: any external runner with TLS capability can
  implement the LLM side later against the committed battery and briefing
  without changing the arena.
- A frozen LLM prompt pack (`llm_prompt_pack.txt`, rendered from the same
  briefing content plus the protocol instructions) is committed so the future
  LLM cell uses byte-identical instructions to what the pilot specifies.
- The blind-LLM control (prereg V4) is likewise blocked for the same reason.
