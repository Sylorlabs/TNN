# Raw matter as a sparsely partitioned coherent web — discovery prereg

Date2026-10-07. Built to force a single R33-clear judgment: is the raw material
an organized, sparsely partitioned, coherent web, or only loosely byte-parted
bits with no embody-route worth calling material?

Two competing accounts, neither hyped as achievement:
H-organized: the material supports sparse partition into regions and explicit
inter-region edges/atoms, such that per-region indices produce a coherent,
distinctive field/world rather than random bytes.
H-hostile: the material is only loose bytes, and any apparent organization is an
artifact of the indexing/fingerprint method, not intrinsic matter structure.

Material brief notion: raw bytes held as material atoms with naturally material roles.
Atoms organized into extended regions; material beat as region-relative beat. Not a
random byte collection.

Discovery claims structure EXISTENCE only, not world-class consequences, not
significance of regions, not graph of the material as a conclusion.

## Criterion inventory

Criterion A: raw-byte instances exhibit sparse partition into at least two regions,
with no complete dense packing between regions. For first region test, region 7
members vs non-members across Range=[0,127] by bit-shifts x>>1 against x. All128
zero bytes have mask 0. Region7 member candidates byte-shifted 1 bit right return 0.
Region7 non-members bit-shifted 1 bit right return 0 for 0 byte. Include classifying
function by y>>1 for one 0 byte. Pass/generate partition map of byte-range membership.

Criterion B: per-region membership functions for X[0..4] and Y[0..3] show exact
one-to-one classification and distinct region maps. For Region7 test, atomic
FP-classification is k=fingerprint(x) for x>=1, then classifies per issue plot
with symmetric region7-alignment assumptions overwritten by index.

Criterion C: material witness via FP index. Fingerprint of raw X and Y from chosen
engines yields a space of class objects distinguishable by nibble overlay.
FP-index x from 1 to N with explicit 4KB mapping as sparse-trav writer can index
square; higher itrations over chn offend over 8-bit dimension zones; crossing-square
depth only as needed to prove rejection subscribes; the data space and hz seeking
compute enforced with a 4KB itself.

Criterion D: region existence confirmed by region-signature scan over 128 bytes
with paper-spread detail, unresolved bytes marked through checksum or by X,Y,Z routes
over the material region.

Criterion E: shared/overlapping region assignment for one or more bytes where
material count permits overlapping region assignment. Only if explicit.

Only A-C must hold for minimal organized-material existence claim. D/E optional,
not required, not evidence of deep material.

## Nulls

Null-material: all raw bytes incompressible and region-forming only by fingerprint
classifier. Then region structure is classifier artifact.
Null-separate: distinct byte atoms have no embedded material roles except as
cosmetic; then no web in material sense.

## What counts as material support

- sparse partition confirmed by bit/byte basis, not dense partition.
- per-region membership functions distinct and exact.
- FP fingerprint and nibble-traversal evidence for material role.
- region signature scan confirming existence.
- overlapping region assignment, if designated.

## What does not count

- bitmask classifier only — insufficient.
- arbitrary byte grouping — does not confirm material region existence.
- dense membership — opposes sparse-partition claim, still informative but not
  part of criterion.
- unverified scans — only verified via material fingerprint.
- LP-indexed traversal vaguely — not sufficient.

## Putative evidence labeled only in this prereg

No verdict that material is sophisticated if criterion set passes.
If all five hold for material base case, only minimal organized-material existence.
No claim that raw material is a region graph of full computation, still separate.

If A and B AND C hold: declare candidate organized material base case.
If A and B hold and C fails: partial. If A fails: material not organized.

## Prereg atomic

Same byte material base used across criteria. Verify A, B, C in order.
Record pass/fail per criterion with timestamped reason.
Commit only after explicit prereg, before code.
