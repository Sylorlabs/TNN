# Learner-Owned Success Criteria: Prediction Before Outcome (Micah Q8)

**Verdict: LEARNER-SUCCESS-COMPLETE.**
**Status:** Mechanism works. Prediction error judges structures. Three of four
batteries discriminate; one has an honest confound (documented).

## 1. Question

Micah Q8: "Can TNN generate predictions BEFORE seeing outcomes and later use
prediction error / consequences to decide whether a structure was useful?
Much stronger than: environment supplies expected answer -> search until
something matches."

In trial (`t2_trial`), the driver supplies `expected` and the learner searches
until a graph produces it. The success criterion is researcher-supplied: the
environment hands over the answer, the learner matches it.

In prediction, the direction reverses: the learner commits to an answer from
its existing structures WITHOUT knowing the outcome, then the world reveals
the outcome and judges. The criterion (was my prediction right?) is generated
by the learner's own commitment meeting the world, not by the driver handing
over `expected` before the search.

## 2. Mechanism (unfrozen variant only)

Base: `provenance_exp/pv_base.zag` verbatim, SHA-256
`a29972ca8183b2857c0c7b262d004fce6e4547c02a971a7aef035b44aa76a8bd`
(frozen TNN-2 hash, verified). Frozen source never modified.

Treatment patch (`ls_patch.zag`, 169 lines). Control patch (`ls_patch_ctl.zag`)
is byte-identical except `score_on()` returns 0 instead of 1 (verified by diff).

### 2.1 PRED node (tag 31)

A recorded prediction awaiting outcome resolution.
- f4: resolved (0 pending, 1 resolved)
- f8: error (0 correct, 1 wrong; valid after resolve)
- f12: struct_id (source FACT or MAP node)
- f16: struct_kind (1 FACT via activate, 20 MAP via execute)
- f20: s, f24: r, f28: predicted p, f32: tick

### 2.2 ev_predict (before outcome)

Generates a prediction from existing structures only. No trial, no search,
no expected answer supplied.
- Treatment: among matching FACTs, pick highest pred_score (FACT f8); tie by
  bid. Then MAP fallback: relation-matched MAPs executed via t2_exec on s;
  first executable wins.
- Control (`score_on`=0): highest bid only (existing recency behavior).
- Records the prediction and its source structure in a PRED node.
- Returns -999999 if no basis (no prediction possible).

### 2.3 pred_resolve (after outcome)

Called from `ev_observe` after the world reveals o. Resolves all pending
PRED nodes for (s,r).
- Treatment: source structure pred_score +1 if correct, -1 if wrong.
  FACT f8 holds pred_score (verified unused on tag-1 in base).
  MAP f12 holds pred_score (was -1 in base), f16 holds pred_trials.
- Control: PRED nodes recorded and resolved (same node cost), but scores
  never updated and never read.

### 2.4 Score consumers (treatment only)

- **Selection:** `ev_predict` prefers high-score FACTs.
- **Retention:** `evict_node` skips nodes with pred_score > 0; falls back to
  unfiltered scan if all candidates protected (avoids deadlock).

### 2.5 Honest boundary: researcher scaffold vs learner-owned

Researcher-authored: PRED layout, the +1/-1 counting rule, the hook points
(predict/resolve/evict), score-guided selection, the >0 protection threshold.
Learner-owned: the score VALUES (accumulated only from the experience stream),
which structures get preferred, whether the criteria diverge from
researcher-defined success. No per-case success rules; no "this structure is
good because the researcher said trial-verified it."

The +1/-1 rule is bookkeeping. What makes the criterion learner-owned is that
the thing being counted (prediction correct/wrong) is generated by the
learner's own commitment meeting the world, not by matching a driver-supplied
`expected`.

## 3. Batteries and results (3/3 byte-identical per arm)

### 3.1 Battery 1: reliability tracking (useful vs merely stored)

Teach reliable facts (6000+i, always 100+i) and unreliable facts (6010+i,
100+i normally but 200+i in 30% of cycles). 20 cycles of predict then observe.

| metric | treatment | control |
|---|---|---|
| acc_rel (reliable correct/100) | 100 | 100 |
| acc_unr (unreliable correct/100) | 75 | 75 |
| rel_score (per reliable fact) | 20,20,20,20,20 | 0 x5 |
| unr_true_score (100+i fact) | 6 x5 | 0 x5 |
| unr_false_score (200+i fact) | 1 x5 | 0 x5 |
| pred_nodes / resolved | 200 / 200 | 200 / 200 |

Treatment scores rank structures by predictive reliability: 20 for always-right,
6 for usually-right, 1 for sometimes-right. The learner distinguishes "useful
for prediction" from "merely stored." Control tracks nothing.

Note: prediction accuracy is identical (100/75) because score-guided selection
does not beat bid-guided selection here; the value is in the SCORES, which the
control cannot produce. The 75 on unreliable exceeds the 70 base rate because
scores learn to prefer the usually-correct fact.

### 3.2 Battery 2: abandonment after world change

Teach (6100,50,111). 5 predict/observe cycles (scoreA_pre=5). Teach
(6100,50,222). 15 predict/observe cycles of the new outcome.

| metric | treatment | control |
|---|---|---|
| scoreA_pre | 5 | 0 |
| switch_at (first k with p==222) | 1 | 1 |
| scoreA_post | 4 | 0 |
| scoreB_post | 14 | 0 |

Prediction switches to the new correct answer at k=1 in both arms (activate
returns the most recent fact). The difference: treatment records WHY. The new
fact accumulates 14 net correct; the old fact sits at 4 (one wrong prediction
after the change, then never selected again because its score lost the ranking).
The learner's history now says which structure the world currently rewards.
Control has no such history.

### 3.3 Battery 3: divergence (researcher success vs learner success)

3a: plain taught FACT (6200,50,321), never trial-verified. 10 correct
predictions. fact3a_score = 10 (treatment) vs 0 (control). Learner success
without researcher success: the fact was never verified against a
driver-supplied expected, but it predicts well, and the treatment knows it.

3b: chain 7001->7002->7003->7004 taught on r=51; `ev_query(7001,50,7004,0)`
runs trial, promotes a MAP (trial_ans=7004, map_found=38). This is RESEARCHER
success: the driver supplied expected=7004 and trial searched until match.
Kill the shadow FACT so the MAP is the prediction source. MAP predicts 7004.
Observe 5555 (world differs).

| metric | treatment | control |
|---|---|---|
| map_score_pre | -1 | -1 |
| map_pred | 7004 | 7004 |
| map_score_post | -1 | 0 |
| map_trials | 1 | 0 |

(Treatment: score initialized -1 -> 0 on first use, then -1 after the wrong
prediction, trials=1. Control: initialized to 0 on use, never updated.)

The MAP has researcher success (trial-verified, promoted) but learner failure
(wrong prediction on new data). Treatment records the negative learner
judgment; control cannot. The two criteria DIVERGE on the same structure, and
only the treatment sees it.

### 3.4 Battery 4: retention under pressure (honest confound)

Score up facts 0..4 (5 correct predictions each, hi_score=5); leave 5..9 at 0.
1100 filler teaches force evictions (exceeds 1024 nodes).

| metric | treatment | control |
|---|---|---|
| hi_alive (of 5) | 5 | 5 |
| lo_alive (of 5) | 0 | 0 |
| live_nodes | 1022 | 1022 |

CONFOUND (documented, not hidden): both arms preserve the 5 scored facts and
evict the 5 unscored ones. In treatment this is score protection (pred_score > 0
skipped by evict_node). In control it is recency: the scored facts were also
the most recently predicted/observed, so bid/ref_prot protects them. Battery 4
does NOT discriminate score-protection from recency-protection in this
configuration. A stronger test would score up OLD facts (not recently touched)
and check survival; not run here.

## 4. What this establishes

1. **Prediction before outcome works.** `ev_predict` commits from existing
   structures with no expected answer supplied; `pred_resolve` judges against
   the revealed world. The information flow is learner-commit -> world-judges,
   reversing trial's world-supplies-answer -> learner-searches.
2. **Scores track reliability.** 20 / 6 / 1 ordering matches actual predictive
   reliability (BAT1). The learner distinguishes useful from merely-stored.
3. **Criteria diverge.** A trial-promoted MAP can carry researcher success and
   learner failure simultaneously; only the treatment records both (BAT3).
   A never-verified FACT can carry learner success with no researcher success
   (BAT3a).
4. **World changes are tracked.** Scores re-rank after the world shifts; the
   history says which structure the world currently rewards (BAT2).

## 5. What this does NOT establish

- The +1/-1 counting rule is researcher bookkeeping, honestly labeled. The
  learner owns the values and the rankings, not the arithmetic.
- BAT4 does not isolate score-protection from recency (confound above).
- Prediction error does not yet trigger REVISION (only selection and
  retention-protection). Wiring error into `t2_revise_graph` is future work.
- `ev_predict` uses existing structures; it does not invent new ones.
- No test of prediction for genuinely novel (s,r) with no matching FACT or
  MAP (returns -999999; untested path).

- RESEARCHER-OWNED STRUCTURAL DECISIONS: PRED node layout (tag 31, 9 fields),

- LEARNER-OWNED STRUCTURAL DECISIONS: all score values (from experience only),
  which structures get preferred in selection, the divergence judgments in BAT3
  (MAP judged bad despite trial promotion; FACT judged good despite no trial).
