## 1. Background and the two mechanism failures

HYPD-REVIEW-COMPLETE (prereg `2c4c58e80`, review `c6069aca4`) structurally
explained D-v2's T3 parity miss:

- **R4 dilution**: D-v2's uniform round-robin parent selection over
  ~4k-12k occupied niches, with per-niche cyclic mutation counters
  (cycle M up to 191), cannot reliably execute the 6-7 deep serial
  append chain the 8-op parity solution needs. Realistic cost of chain B
  (~1.37M evals) exceeds the 1M budget.
- **R5 carried niche poisoning**: T2's archive, carried into T3 and
  inserted silently, contains 11 constant-2 programs `[PUSH:-9 x k,
  PUSH:2]` that map to the exact niches the solution chain needs
  (len-4 maps to niche **17570** = Q4's niche). Same output vector
  implies same score (0), so the strictly-greater retention rule can
  never displace them. Q4 is unreachable for the entire run,
  regardless of budget.
- R1 confirmed the 8-op solution `[IN0,IN1,ADD,PUSH 2,MOD,PUSH 1,SWAP,SUB]`
  is REAL (25/25 train, 39/39 held-out): the miss is a search failure,
  not a theory failure.

## 2. v3 design (built on v2 code; fix, don't rewrite)

v3 = `hyp_d_v2.zag` (`2500fd02b`) plus the two deltas below, selected by
two frozen constants. One source file; three build configurations.

### Fix 1: concentrating selection policy (SEL_MODE=1; attacks R4)

Replace uniform round-robin parent selection with a deterministic
four-source schedule. A selection counter `k` (incremented per parent
selection in the main loop) chooses the source:

- `k%8` in {0,1,2,3}: **nursery** (50%). The 256 most recently inserted
  niches, round-robin. New niches start their per-niche mutation
  counter at 0, and all chain appends need template indices < 31, so a
  new niche's first ~31 selections cover every append continuation.
  The nursery gives each new niche a burst of ~39 selections, letting
  serial append chains execute link by link.
- `k%8==4`: **score bands** (12.5%). The 17 score_norm bands
  (band = (score*16)/n, 0..16), deficit-weighted by (band+1)
  (total 153), round-robin within the chosen band. Exploits the
  quality gradient.
- `k%8==5`: **uniform** (12.5%). Round-robin over all occupied niches,
  as in v2. Coverage floor; no starvation.
- `k%8` in {6,7}: **seed pool** (25%). Carried programs banded by
  new-task score (see Fix 2), deficit-weighted by (band+1),
  round-robin within band. Transfer channel.

If the scheduled source is empty, fall back to the first non-empty of
(seed, uniform, nursery, score). All weights derive only from
mechanism-internal quantities (elite score, insertion recency). No
task knowledge. Fully deterministic (counters only, no RNG).

Frozen design constants (chosen a priori for the mechanism rationale,
not tuned to T3; no v3 run has been observed): nursery R=256; shares
4/8, 1/8, 1/8, 2/8; band weight = band+1; deficit scheduler. These are
round numbers frozen before implementation.

### Fix 2: non-poisoning carry-over (CARRY_MODE=1; attacks R5)

Carried programs are **never inserted into the new task's archive**.
Instead:

- Each carried program is evaluated once on the new task's train set
  (counts toward the eval budget, as in v2). On P-VM tasks, carried
  programs containing an ablated opcode are dropped, as in v2.
- Survivors enter the **seed pool**, banded by new-task score_norm
  (17 bands), each with its own cyclic mutation counter. They serve
  as parents via the seed share of the schedule. Their mutations are
  evaluated and inserted into the archive under the normal retention
  rule. The carried programs themselves never occupy archive niches.
- Archive niches can only be claimed by programs generated inside the
  new task's own search (the empty-program seed on the first task, or
  mutations thereafter). This implements the review's recommendation:
  carried programs compete on the new task's score as parents rather
  than holding niches by occupancy.

**Falsification check (observer, not participant):** niche 17570 is
Q4/PA's niche on T3. At the end of T3, v3 logs CARRY_BLOCK_CHECK with
the elite program at niche 17570 and whether it is byte-identical to
any carried program. If the elite is byte-identical to a carried
program AND was not generated by T3's own search (no I-line for it),
the R5 poisoning recurred and v3 FAILS. Under CARRY_MODE=1 this is
structurally impossible (no code path inserts carried programs); the
check audits the structure. The check is a log line only: it does not
influence selection, mutation, or retention.

### Source audit note (anti-tuning)

The v3 source contains no parity-specific mechanism. The only
T3-specific constant is the 17570 diagnostic observer. Selection
weights use only elite score and insertion recency; seed banding uses
only new-task score. The design constants above were frozen before
any v3 run.

## 3. Build configurations (one source, `sed` of two constants)

- **v3-both**: SEL_MODE=1, CARRY_MODE=1. The claim configuration.
- **v3-selection-only** (diagnostic): SEL_MODE=1, CARRY_MODE=0 (v2
  silent carry insertion). Isolates Fix 1.
- **v3-carry-only** (diagnostic): SEL_MODE=0 (v2 round-robin),
  CARRY_MODE=1. Isolates Fix 2.

The committed source is the v3-both configuration. Ablation binaries
are built from `/tmp` copies with the two constant lines edited by
`sed` (commands recorded in BUILD_V3.sh); the mode is echoed in each
run log header. No per-configuration tuning of any other kind.
