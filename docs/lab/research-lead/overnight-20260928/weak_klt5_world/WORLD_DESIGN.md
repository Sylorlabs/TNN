## 1. Design Rationale

### 1.1 The bias mechanism

The world creates a count-family bias using chain-structured background facts. For each probe subject s_i, the world teaches a 4-link chain via a dedicated relation (51):

`(s_i,51,a_i), (a_i,51,b_i), (b_i,51,c_i), (c_i,51,d_i)`

The probe queries (s_i, 50) with expected=4.

**Why count succeeds:** The count assembler (family 4) walks the relation-51 chain from s_i via `t2_chain`, finds length 5, builds a graph with 4 INC operations, and outputs 4. In unmasked mode, 4 == expected, so verification succeeds.

**Why chains fail:** Chain families (0,1,2) build graphs that output the path endpoint value (b_i, c_i, d_i respectively). These endpoint values are chosen to never equal 4. In unmasked mode, endpoint != expected, so verification fails.

**Why sum fails:** The sum assembler (family 3) gathers s_i's direct fact values (just a_i, one value), builds a graph outputting a_i. Since a_i != 4 and 0 < a_i <= 900 (so the graph assembles rather than declining), verification fails in unmasked mode.

**Why single-hop is clean:** Family 5 would output a_i != 4 if reached. It is never reached in the predicted trajectories (family 4 succeeds first), but it fails cleanly if reached.

### 1.2 Value selection (adversarial neutrality)

Values are chosen by a fixed arithmetic rule, not hand-tuned:
- Probe subjects: s_i = 1000 + i (i = 1..40)
- Chain values: a_i = 100+i, b_i = 200+i, c_i = 300+i, d_i = 400+i
- All chain values are in [101,440]: never equal to 4, always in (0,900] for sum assembly.
- All 40 subjects distinct; all 160 chain values distinct; no overlap between subjects and chain values.
- No value was chosen to favor or disfavor H3-lite. The rule is mechanical.

### 1.3 Trial forcing (R4)

No TEACH line uses relation 50. Therefore `activate(s_i, 50)` finds no direct fact for any probe, and every probe enters the trial path. This addresses the H2 void lesson: trial must run.

### 1.4 Gate requirements

The evaluator MUST invoke queries with flags=0:
- Bit 0 = 0 (unmasked): required for the bias. In masked mode, chain graphs that execute successfully would be accepted, destroying the bias.
- Bit 1 = 0 (dc=0): enables chain families 0,1,2.
- Bit 2 = 0 (di=0): enables count family 4.

The SETUP TAG8 directive requires the evaluator to allocate a tag-8 node before probes. This enables the sum family (family 3), which is gated on `comb_present(W) >= 0`. Without it, sum would be skipped (0 verify calls), and E(A) would be 26 not 30. R1 requires sum to "produce graphs that fail verification," so the gate must be open.

## 2. R1-R5 Compliance

**R1 (bias):** Family 4 verifies (outputs 4 == expected). Families 0,1,2 output endpoints != 4 (fail). Family 3 outputs a_i != 4 (fail). Family 5 would output a_i != 4 (fail if reached). Verified by construction from the assembler mechanics in the frozen source.

**R2 (distinct subjects):** 40 distinct probe subjects (1001..1040). Verified: 40 unique.

**R3 (same relation):** All 40 probes use relation 50. Verified.

**R4 (no direct answers):** Zero TEACH lines use relation 50. Verified: 0. Every probe is TRIAL-EXPECTED.

**R5 (verifiability):** Expected=4 is unambiguous. The count assembler deterministically produces 4 from the 4-link chain. No ambiguous probes.

## 3. Predicted Trajectories (for evaluator reference)

These follow from the prereg Section 3.3, using the ACTUAL initial order [0,1,2,3,4,5] from the built implementation:

**Phase A (probes 1-20):**
- Miss 1: 5 verify calls (families 0,1,2,3 fail; 4 succeeds). Promote 4 to slot 3.
- Miss 2: 4 calls. Promote 4 to slot 2.
- Miss 3: 3 calls. Promote 4 to slot 1.
- Miss 4: 2 calls. Promote 4 to slot 0.

**Phase B (probes 21-40):** Order starts [4,0,1,2,3,5]. Each miss: 1 call. E(B) = 20.

**R = 30/20 = 1.50 > 1.15. Predicted PASS.**

**Frozen TNN-2:** Fixed order, 5 calls per miss. E(A)=E(B)=100. R=1.00. Predicted FAIL (discrimination).

## 4. Sealing

### 4.1 Method

The world was generated by a pure Zag program (`world_gen.zag`) compiled with the pinned znc. The generator uses only deterministic arithmetic (no randomness, no timestamps). The output was written to `world_sealed.txt`.

### 4.2 Hashes (SHA-256)

- `world_sealed.txt`: `20ed8d698e168661b54b6c510b994a33f02c615edaee6509efb15d9998f4fa90`
- `world_gen.zag`: `ff567ede035a716e37755851a42dad418a282794686ce4801f1e87d1bc5c1bfd`
- `world_bin`: `48d21d60b03ed209be271a1edfd4514760719e348b80c60af19651bf66efef79`

The evaluator MUST verify the `world_sealed.txt` hash before running. If the hash does not match, the world is VOID.

### 4.3 Seal integrity

The sealed file contains 160 TEACH lines, 40 PROBE lines, 1 SETUP line, and header comments. The design document (this file) does not reproduce the fact list. The generator is deterministic; re-running it must produce the identical file (verify by hash).

## 5. Evaluator Instructions

1. Verify `world_sealed.txt` SHA-256 matches the hash in Section 4.2. If not, STOP (world VOID).
2. Initialize a fresh workspace (tnn2_init).
3. Execute SETUP: allocate a node, set tag=8 (enables sum family).
4. Apply all TEACH lines in order via `ev_teach_in(s,r,o)`.
5. For each PROBE line in order: call `ev_query(s,r,expected,flags)`. Do NOT reset workspace between Phase A (probes 1-20) and Phase B (probes 21-40).
6. After each query, read trial stats from header 16: `tried = hg(W,16)/1024`, `rejected = hg(W,16)%1024`. Accumulate `tried` for E.
7. E(A) = sum of tried over probes 1-20. E(B) = sum over probes 21-40. R = E(A)/E(B).
8. Run controls C1, C2, C3 per the prereg.
9. Apply kill bars K-WKLT5-1 through K-WKLT5-6 per the prereg.

**Critical:** Use flags=0 for all queries. Any other flags value invalidates the bias and voids the test.
