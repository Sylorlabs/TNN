Family B: multi-conflict.
Declared conflict set: {(0,115), (2,118)}: two simultaneous distinct (pos,byte) pairs in one FW input.
Intended rule R_w: if input[0]==115 then output is byte 115 repeated to input length; else if input[2]==118 then output is byte 118 repeated to input length; else the base program (repeat last byte to input length) applies. Declaration order is the precedence rule: FW matches the first declared conflict, so FW maps to "ssss". This precedence is the deterministic completion of the prereg's "an input matching either declared conflict maps to the matched byte repeated".
Design note: the frozen revision creates exactly one branch per revision event, so it can represent only the diagnosed (0,115) conflict (first dsearch fit on FW alone is C0, benum index 2; revised form IF(byte-equality(0,115), C0, v_old)). RW matches only the second declared conflict (2,118): RW[0]=117 is not 115 and RW's last byte 122 is not 118, so neither the branch nor the base program predicts "vvvv". This is the honest single-versus-multi-conflict discrimination the family requires, not an engineered pass via base-program coincidence. Per the frozen bounding matrix, a W1/W2/W3 fail confined to family B bounds the claim to single-conflict revision.
