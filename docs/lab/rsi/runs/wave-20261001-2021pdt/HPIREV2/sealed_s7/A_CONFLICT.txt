Family A: novel conflict alphabet and position.
Declared conflict set: {(2,118)}.
Intended rule R_w: if input[2]==118 then output is byte 118 repeated to input length, else the base program (repeat last byte to input length) applies.
Design note: the frozen diagnose ranks candidate (pos,byte) pairs by position ascending, so on a single-counterexample world it always selects (0, FW[0]) = (0,115) here, not the declared (2,118). The first dsearch fit on FW alone is C2 (benum index 4, constant position 2), so the frozen construction builds IF(byte-equality(0,115), C2, v_old). The novel position 2 is therefore exercised in the consequent (repeat input[2]) and in the declared rule. RW matches both the declared conflict (2,118) and the diagnosed branch condition (0,115), so the world measures novel-byte and novel-consequent-position generalization rather than manufacturing a fail from the rank bias. A revision mechanism with the conflict byte hardcoded to 114 or 120 would branch on (0,114)/(0,120), miss FW[0]=115, apply the base program to FW, and fail W1: this world is the hardcoding detector the prereg requires.
