## 1. Capability definition

C16 synthetic language acquisition (implemented battery, CA-2 refreeze):
the learner is exposed to labeled Zem word examples during the expo phase and
must induce the word-class morphology, then (a) produce the transformed word
form for a given segment triple and (b) classify segment triples as
well-formed or not.

Concretely, from world_gen.zag (read-only; unmodified):
- Expo events `{"t":"z","w":NAME,"cls":"A","s":[s0,s1,s2]}` (5 A-words sharing
  one template) and `{"t":"z","w":NAME,"cls":"B","s":[s0,s1,s2]}` (2 B-words
  sharing the transformed template), plus `{"t":"n","w":NAME,"gloss":...,
  "s":[...]}` new-word teachings (A-form).
- Test items: 3x `zemprod|s0,s1,s2` (input is the A template; answer is the
  B-form segments as "b0,b1,b2") and 3x `zemclass|s0,s1,s2` (answer "yes" iff
  the triple matches the learned word template, else "no").

The required mechanism is morphological rule induction: learn per-class
segment templates and the position-wise A to B rewrite rule from labeled
examples only, then apply productively. No transform-type enumeration is
permitted (the four transform ids documented in the world proofs are never
read by the contestant and play no role in the mechanism).

## 4. Planned changes (v6, from v4)

Built on devint1_contestant_v4.zag (0.676). Additive only; no existing
handler or store is altered.

1. Zem word store in W (free region 13120..13916): 24 entries x 32B
   (name 16B, class 1B, 3 segment i32s), plus class-A template (3 i32),
   class-B template (3 i32), and known/conflict flags.
2. learn_zem: on `t:"z"` events store (name, class, segments); first
   A-class (or new-word) example sets the A template, first B-class example
   sets the B template; later same-class examples must match (mismatch only
   increments a white-box conflict counter, keeps the first). Word names are
   also fed through the existing DEVINT1 lexicon feed (lex_feed), consistent
   with learn_fact/learn_rel/learn_conflict. On `t:"n"` events store as
   A-class evidence (new vocabulary conforming to the taught word form).
3. Test handler `zemprod|s0,s1,s2`: position-wise rewrite induction. For each
   position p, if input segment equals A[p] emit B[p]; any unmapped position
   yields "UNKNOWN". Output format "b0,b1,b2" (matches segs3, no spaces).
4. Test handler `zemclass|s0,s1,s2`: "yes" iff the triple equals the learned
   A template, else "no"; "UNKNOWN" if no A template was learned.
5. Reply metrics gain `zem_n` (words learned); scorer-visible fields
   (turn, item, cap, reply, ms, rss_kb, state_bytes) keep their exact format.

Generality properties (by construction, verified in K7): no segment values,
word names, class labels, or answers appear in source; templates and the
rewrite rule are learned solely from exposure events; the mechanism works
for any world the generator can emit.

## 6. Honest boundaries

- This is morphological rule induction over a tiny segmental morphology
  (3 positions, values 0..3) from 7 to 10 labeled examples. It does not
  acquire syntax, compositional semantics, open vocabulary, or
  productive generalization beyond the taught template family.
- zemprod is tested only on the taught A template; the position-wise rule
  is the honest general form of what the battery tests.
- The zemclass validity notion used ("matches the learned word template")
  mirrors the generator's validity definition; the ambiguity (whether
  B-form triples should count as valid) is documented and does not affect
  scoring on the sealed battery.
- No L3 or "language understanding" claim is made. A positive result is a
  CANDIDATE score: it does not move the canonical 0.573; only a clean
  refreeze reproducing composition without contamination can do that.
- Still expected 0 after this lane: C8 inquiry (separate candidate v5),
