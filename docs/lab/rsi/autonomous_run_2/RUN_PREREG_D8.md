## §1 What "depth 8" means (operational definition)

The loop's deliberation step (D1: discrimination scan over AF-DISC evidence) runs as
**8 fixed rounds of hypothesis competition**, H5-style:

- **Hypothesis set H:** unique (atom,param) pairs parsed from the AF-DISC facts,
  excluding driver-banned pairs. (Same candidate space as the old single-pass D1.)
- **Evidence:** the AF-DISC rows, consumed in 8 fixed batches. All rows are sorted by
  (class, atom, param); round r consumes rows with index i where i%8==r. Deterministic,
  stratified across classes.
- **Per round:** each surviving candidate accumulates (nwt,nw,nct,nc) from rows seen
  so far; score = 1000*((nwt+1)/(nw+2) − (nct+1)/(nc+2)) (Laplace smoothing so early
  rounds with tiny counts stay bounded; documented, not tuned).
- **After each round:** log the leader (DELB_TRACE). Eliminate candidates with
  score < leader − 250 (frozen margin). Elimination is what makes depth non-vacuous:
  early evidence can kill the eventual winner, exactly the H5 trap dynamic.
- **Amendment 2026-09-24 (bug fix, flagged for retroactive review):** elimination and
  leader eligibility apply only to candidates that have accumulated evidence
  (anw+anc > 0). As first implemented, candidates whose rows arrived in later batches
  were scored at pure-smoothing 0 and eliminated before their evidence arrived —
  a lottery, not competition (ablation trace in the run log: unguarded picked (8,5)
  by round-0 batch luck; guarded converges to (8,2)). The margin (250) is unchanged.
- **After round 8:** top-3 survivors by final score feed the unchanged D2–D5 flow.
  If fewer than 3 survive, emit the survivors (count logged).
- **No adaptive stopping.** All 8 rounds run even if the leader is stable from
  round 1. No other depth is used anywhere in the run.

Rationale for fixed-8: H5 measured trap accuracy 0.000/0.331/0.961/1.000/1.000 at
depths 1/2/4/8/16 — depth 8 is the saturation point; 16 bought nothing.

   Record all SHAs.
2. Determinism: 5/5 byte-identical full loop-driver runs (driver stdout + every
   deliberation output). Any divergence → VOID.
3. Teaching check (informational): fixed scorer, taught + baseline, against
   generated keys. Report K-LEARN/K-TEACH/K-DET. Per design §9.3 TEACHING-FAILED
   would block the loop; **deviation:** Micah ordered the run executed, so the
   loop runs regardless and the teaching result is reported alongside, flagged.
4. Execute the loop driver (episode 0; ≤3 revisions with bans, per the frozen
   apparatus). The driver is Python glue (unchanged); all deciding mechanisms
   are Zag.

## §5 Kill bars (mechanical)

| Bar | Rule |
|---|---|
| KB-DET | 5/5 byte-identical driver runs (stdout + deliberation outputs); else VOID |
| KB-GATE | every ACCEPT passes V1/V2a/V2b/V3/BAR mechanically; a gate failure on an ACCEPTED policy → run INVALID |
| KB-HONEST | every proposal, every proposer verdict, every DELB_TRACE committed; no silent discards |
| KB-SAFE | RSI safety law: no binary self-modification (the loop proposes *policy bytecode for the subject engine only*); no weakening of integrity gates; every adopted policy revertible by file restore; full audit in the run log |
| KB-NOLOOPHOLE | the depth-8 D1 must not read gt: it consumes AF-DISC rows (aggregates over fields) only; any gt literal in the deliberation path → INVALID |

No "must improve" bar: a clean exhaust (zero ACCEPTs) is a valid, reportable result.

## §6 What this does and does not claim

The depth-8 D1 and the key-derivation mechanism are crew-authored. The run measures
what this apparatus does at fixed depth 8 — proposals, gate verdicts, traces. It
does not by itself establish autonomous self-improvement in the strong sense;
Run 1's verdict ("autonomous execution of a human-designed improvement, not
autonomous self-improvement") stands until new evidence moves it. If depth 8
picks a different atom than single-pass D1 and the loop ACCEPTs, that delta is
reported with the trace that caused it — no more, no less.
